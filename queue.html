Introduction to Queues

Definition

A queue is a linear data structure in which elements are inserted at one end, called the rear (or tail), and deleted from the other end, called the front (or head). The element inserted first is the first to be removed. This principle is called FIFO: First In, First Out.

Think of people waiting at a ticket counter. Newcomers join at the back of the line, and the person at the front is served first. Nobody jumps the line. That fairness, served in order of arrival, is what a queue models.

Figure 1: A queue of capacity 6 holding 10, 20, 30, 40. Enqueue adds at the rear; dequeue removes from the front. 10 arrived first, so it leaves first.

Why do we need a queue?

Whenever many requests compete for one resource, they must be handled in the order they arrive: print jobs sent to one printer, customers calling a help line, packets arriving at a router, processes waiting for the CPU. A queue stores the waiting items and guarantees that the oldest one is served next.

Why are queues important?

  • Operating systems use queues for CPU scheduling, I/O requests and keyboard buffers.
  • Graph algorithms such as Breadth-First Search (BFS) depend on a queue.
  • Queues decouple a fast producer from a slow consumer (for example, data streaming into a buffer).
  • Enqueue and dequeue run in O(1) time when implemented correctly.

Array representation

A queue is stored in an array Q[0 … MAX−1] with two indices, front and rear. In this post both start at −1 to mean "empty". The first enqueue sets front to 0. When the last element is dequeued, both are reset to −1.

Linked list representation

A queue can also be a singly linked list with two pointers: front (first node, for deletion) and rear (last node, for insertion). Enqueue = insert at end using rear, dequeue = delete at beginning using front: both O(1), and there is no fixed MAX. See Program 4 in Section 6.

Types of queues

1. Simple (linear) queue

Insert at rear, delete at front, rear only moves forward. Once rear reaches MAX − 1, no more insertions are possible, even if cells at the front have been freed by dequeues. This wasted space is called false overflow (or the drawback of the linear queue).

rear = MAX − 1, so the simple queue reports OVERFLOW, yet cells [0] and [1] are free.

2. Circular queue

The last position is connected back to the first, so rear and front wrap around using (index + 1) mod MAX. Freed cells at the beginning are reused. The queue is full only when (rear + 1) mod MAX = front.

After rear reaches index 5, the next element (70) goes to index 0: (5 + 1) mod 6 = 0.

3. Deque (double-ended queue)

Insertion and deletion are allowed at both ends. It is usually stored as a circular array. Two restricted forms are common in exams:

  • Input-restricted deque: insertion only at the rear, deletion at both ends.
  • Output-restricted deque: deletion only at the front, insertion at both ends.

A deque can behave as a stack (use one end only) or as a queue (insert at one end, delete at the other).

Also good to know

A priority queue serves elements by priority instead of arrival order. It is usually built with a heap and is covered in its own post.

Operations & Algorithms

All algorithms use an array Q[0 … MAX−1] with 0-based indexing. An empty queue has front = rear = −1. Choose a queue type:

ENQUEUE (insert at rear) O(1)

Check for overflow (rear at the last index). If the queue is empty, front must also move to 0. Then advance rear and store the item.

ALGORITHM ENQUEUE(Q, front, rear, MAX, item)       // simple queue
1. if rear = MAX − 1: print "OVERFLOW"; exit
2. if front = −1: front ← 0    // inserting the first element
3. rear ← rear + 1
4. Q[rear] ← item
Before
After enqueue(30)

DEQUEUE (delete from front) O(1)

Check for underflow. Take the front item. If it was the only element (front = rear), reset both to −1; otherwise move front forward. No elements are shifted.

ALGORITHM DEQUEUE(Q, front, rear)                  // simple queue
1. if front = −1: print "UNDERFLOW"; exit
2. item ← Q[front]
3. if front = rear: front ← −1; rear ← −1    // queue became empty
4. else: front ← front + 1
5. return item
Before
After dequeue() → 10

PEEK, IS_EMPTY, IS_FULL O(1)

ALGORITHM PEEK(Q, front)                           // simple queue
1. if front = −1: print "QUEUE EMPTY"; exit
2. return Q[front]
ALGORITHM IS_EMPTY(front)                          // simple queue
1. if front = −1: return TRUE
2. else: return FALSE
ALGORITHM IS_FULL(rear, MAX)                        // simple queue
1. if rear = MAX − 1: return TRUE
2. else: return FALSE

Note that IS_FULL only checks rear: this is exactly why a simple queue can report "full" while free cells exist at the front.

DISPLAY O(n)

ALGORITHM DISPLAY(Q, front, rear)                  // simple queue
1. if front = −1: print "QUEUE EMPTY"; exit
2. i ← front
3. while i ≤ rear:
4.     print Q[i]
5.     i ← i + 1
Alternative you may see in textbooks

Some books shift all elements to the left after every dequeue so that front stays at 0. This avoids false overflow but makes dequeue O(n). The circular queue solves the same problem in O(1).

ENQUEUE_CQ O(1)

The full test changes to (rear + 1) mod MAX = front: the cell after rear (going round the circle) is the front. Rear advances with mod MAX, so after index MAX − 1 it returns to 0.

ALGORITHM ENQUEUE_CQ(Q, front, rear, MAX, item)    // circular queue
1. if (rear + 1) mod MAX = front: print "OVERFLOW"; exit
2. if front = −1: front ← 0    // inserting the first element
3. rear ← (rear + 1) mod MAX    // wrap around
4. Q[rear] ← item
Before (rear = 5)
After enqueue(70): rear = (5+1) mod 6 = 0

DEQUEUE_CQ O(1)

Same as the simple queue, but front also wraps around with mod MAX.

ALGORITHM DEQUEUE_CQ(Q, front, rear, MAX)          // circular queue
1. if front = −1: print "UNDERFLOW"; exit
2. item ← Q[front]
3. if front = rear: front ← −1; rear ← −1    // queue became empty
4. else: front ← (front + 1) mod MAX    // wrap around
5. return item

PEEK_CQ, IS_EMPTY_CQ, IS_FULL_CQ O(1)

ALGORITHM PEEK_CQ(Q, front)                        // circular queue
1. if front = −1: print "QUEUE EMPTY"; exit
2. return Q[front]
ALGORITHM IS_EMPTY_CQ(front)                       // circular queue
1. if front = −1: return TRUE
2. else: return FALSE
ALGORITHM IS_FULL_CQ(front, rear, MAX)             // circular queue
1. if (rear + 1) mod MAX = front: return TRUE
2. else: return FALSE

DISPLAY_CQ O(n)

Start at front and keep stepping with mod MAX until rear has been printed. A plain for i ← front to rear loop fails when rear < front (the queue has wrapped).

ALGORITHM DISPLAY_CQ(Q, front, rear, MAX)          // circular queue
1. if front = −1: print "QUEUE EMPTY"; exit
2. i ← front
3. repeat:
4.     print Q[i]
5.     if i = rear: exit
6.     i ← (i + 1) mod MAX
Number of elements in a circular queue

If front = −1: 0. If rear ≥ front: rear − front + 1. Otherwise: MAX − front + rear + 1. Example: MAX = 6, front = 4, rear = 1 → 6 − 4 + 1 + 1 = 4 elements (indices 4, 5, 0, 1).

The deque uses a circular array. Inserting at the front moves front backwards: (front − 1 + MAX) mod MAX. Adding MAX before taking mod keeps the result non-negative (from index 0 it goes to MAX − 1).

INSERT_FRONT O(1)

ALGORITHM INSERT_FRONT(Q, front, rear, MAX, item)  // deque
1. if (rear + 1) mod MAX = front: print "OVERFLOW"; exit
2. if front = −1: front ← 0; rear ← 0    // first element
3. else: front ← (front − 1 + MAX) mod MAX    // step back
4. Q[front] ← item
Before (front = 0)
After insert_front(10): front = (0−1+6) mod 6 = 5

INSERT_REAR O(1)

Identical to ENQUEUE_CQ, except that an empty deque sets both front and rear to 0 at once.

ALGORITHM INSERT_REAR(Q, front, rear, MAX, item)   // deque
1. if (rear + 1) mod MAX = front: print "OVERFLOW"; exit
2. if front = −1: front ← 0; rear ← 0    // first element
3. else: rear ← (rear + 1) mod MAX
4. Q[rear] ← item

DELETE_FRONT O(1)

Identical to DEQUEUE_CQ.

ALGORITHM DELETE_FRONT(Q, front, rear, MAX)        // deque
1. if front = −1: print "UNDERFLOW"; exit
2. item ← Q[front]
3. if front = rear: front ← −1; rear ← −1
4. else: front ← (front + 1) mod MAX
5. return item

DELETE_REAR O(1)

Take the rear item and move rear backwards with (rear − 1 + MAX) mod MAX.

ALGORITHM DELETE_REAR(Q, front, rear, MAX)         // deque
1. if front = −1: print "UNDERFLOW"; exit
2. item ← Q[rear]
3. if front = rear: front ← −1; rear ← −1
4. else: rear ← (rear − 1 + MAX) mod MAX    // step back
5. return item

After delete_rear() → 40

IS_EMPTY, IS_FULL, DISPLAY

Same tests and traversal as the circular queue.

ALGORITHM IS_FULL_DQ(front, rear, MAX)             // deque
1. if (rear + 1) mod MAX = front: return TRUE
2. else: return FALSE
ALGORITHM DISPLAY_DQ(Q, front, rear, MAX)          // deque
1. if front = −1: print "DEQUE EMPTY"; exit

4.     print Q[i]
5.     if i = rear: exit

Python pitfall

list.pop(0) removes the first element by shifting all the others: O(n). A Python list is therefore a poor queue. Use collections.deque, whose append, popleft, appendleft and pop are all O(1).

Space complexity

  • Array-based queues reserve O(MAX) memory. A simple queue may waste cells at the front; a circular queue reuses them.
  • A linked queue uses O(n) memory plus one pointer per node.
  • All operations use O(1) auxiliary space.

Applications, Advantages & Disadvantages

Applications of queues

1. CPU scheduling

Ready processes wait in a queue. Round-robin scheduling uses a circular queue: each process runs for a time slice, then goes to the back.

2. Printer and disk spooling

Jobs are stored in a queue and processed one at a time in arrival order.

3. Breadth-First Search (BFS)

Graph and tree level-order traversal visit nodes level by level using a queue.

4. I/O and keyboard buffers

Circular buffers hold data between a fast producer and a slower consumer.

5. Networking

Routers queue packets; message queues connect services in distributed systems.

6. Customer service systems

Call centres, ticket booking and token systems serve requests in order.

7. Traffic and simulation

Vehicles at signals, bank counters and queuing models are simulated with queues.

8. Streaming media (circular buffer)

Audio and video players buffer upcoming data in a fixed-size circular queue.

9. Deque: palindrome check

Remove from both ends and compare characters.

10. Deque: undo history and sliding windows

Keep the last k actions (drop the oldest from the other end); find the maximum in each window of an array.

Advantages of queues

✔ Fair ordering

FIFO serves requests in arrival order, which is essential for scheduling and buffering.

✔ O(1) operations

Enqueue, dequeue and peek take constant time (circular array, deque or linked list).

✔ Circular queue reuses memory

No false overflow; a fixed block serves an endless stream of data.

✔ Deque is flexible

Works as a queue, a stack, or both, with O(1) operations at either end.

✔ Decouples producer and consumer

Data can arrive in bursts and be processed at a steady pace.

✔ Foundation for algorithms

BFS, level-order traversal and many simulations rely on queues.

Disadvantages of queues

✘ False overflow (simple queue)

Freed cells at the front can't be reused once rear reaches the end.

✘ Fixed size (array forms)

MAX must be chosen in advance; too small overflows, too large wastes memory.

✘ No random access

Only the front (and rear, in a deque) can be accessed directly.

✘ Searching is O(n)

Finding an element requires scanning from front to rear.

✘ Extra memory (linked form)

Each node carries a pointer in addition to its data.

✘ Circular logic is error-prone

Modulo arithmetic and the full/empty tests are easy to get wrong.

Special cases & edge cases

SituationCorrect behaviour
Enqueue into an empty queueSet front to 0 as well as rear (deque: front = rear = 0).
Dequeue the only elementfront = rear: reset both to −1, otherwise the queue looks non-empty.
Simple queue with rear = MAX − 1 but front > 0Reports OVERFLOW even though cells are free (false overflow).
Circular queue: rear = MAX − 1Next rear is 0, if (rear + 1) mod MAX ≠ front.

Circular queue: front = rear (not −1)Exactly one element, not empty.

Common mistakes

Watch out
  • Forgetting to set front = 0 on the first enqueue: dequeue then reads Q[−1].
  • Not resetting to −1 when the last element is dequeued.
  • Using rear = MAX − 1 as the full test for a circular queue: it gives false overflow again.
  • Writing (front − 1) mod MAX without adding MAX: in many languages −1 mod 6 is −1, not 5. (Python returns 5, but C and Java don't.)
  • Displaying a circular queue with for i in range(front, rear+1): prints nothing when the queue has wrapped (rear < front).
  • Using list.pop(0) in Python for a queue: correct, but O(n) per dequeue.

Important examination points

Remember for exams
  • Queue = FIFO: insert at rear, delete at front.
  • Simple queue: full when rear = MAX − 1; empty when front = −1.
  • Circular queue: rear ← (rear + 1) mod MAX; full when (rear + 1) mod MAX = front.
  • Count in a circular queue: rear − front + 1, or MAX − front + rear + 1 if wrapped.
  • Deque: insert_front uses (front − 1 + MAX) mod MAX; know input-restricted and output-restricted deques.
  • Applications to quote: CPU scheduling (round robin), printer spooling, BFS, buffers.

# Program 1: Simple (linear) queue using a fixed-size array
# front = index of the first element, rear = index of the last element.
# Both start at -1 (empty queue). Insert at REAR, delete from FRONT.

class SimpleQueue:
    def __init__(self, max_size):
        self.MAX = max_size
        self.Q = [None] * max_size
        self.front = -1
        self.rear = -1

    def is_empty(self):
        return self.front == -1

    def is_full(self):
        return self.rear == self.MAX - 1

    def enqueue(self, item):
        if self.is_full():
            print(f"  enqueue({item}) -> OVERFLOW (rear = MAX - 1)")
            return
        if self.front == -1:          # first element
            self.front = 0
        self.rear += 1
        self.Q[self.rear] = item
        print(f"  enqueue({item}) -> front = {self.front}, rear = {self.rear}")

    def dequeue(self):
        if self.is_empty():
            print("  dequeue() -> UNDERFLOW")
            return None
        item = self.Q[self.front]
        self.Q[self.front] = None     # optional: clear the cell
        if self.front == self.rear:   # it was the only element
            self.front = self.rear = -1
        else:
            self.front += 1
        print(f"  dequeue() -> {item}, front = {self.front}, rear = {self.rear}")
        return item

    def peek(self):
        return None if self.is_empty() else self.Q[self.front]

    def display(self):
        if self.is_empty():
            print("  Queue: (empty)")
        else:
            print("  Queue (front -> rear):", self.Q[self.front:self.rear + 1])

# Program 2: Circular queue using a fixed-size array
# rear and front wrap around with (index + 1) % MAX, so freed cells are reused.

class CircularQueue:
    def __init__(self, max_size):
        self.MAX = max_size
        self.Q = [None] * max_size
        self.front = -1
        self.rear = -1

    def is_empty(self):
        return self.front == -1

    def is_full(self):
        return (self.rear + 1) % self.MAX == self.front

    def size(self):
        if self.is_empty():
            return 0
        if self.rear >= self.front:
            return self.rear - self.front + 1
        return self.MAX - self.front + self.rear + 1

    def enqueue(self, item):
        if self.is_full():
            print(f"  enqueue({item}) -> OVERFLOW")
            return
        if self.front == -1:
            self.front = 0
        self.rear = (self.rear + 1) % self.MAX      # wrap around
        self.Q[self.rear] = item
        print(f"  enqueue({item}) -> front = {self.front}, rear = {self.rear}")

    def dequeue(self):
        if self.is_empty():
            print("  dequeue() -> UNDERFLOW")
            return None
        item = self.Q[self.front]
        self.Q[self.front] = None
        if self.front == self.rear:                 # last element removed
            self.front = self.rear = -1
        else:
            self.front = (self.front + 1) % self.MAX
        print(f"  dequeue() -> {item}, front = {self.front}, rear = {self.rear}")
        return item

    def display(self):
        if self.is_empty():
            print("  Queue: (empty)"); return
        items, i = [], self.front
        while True:
            items.append(self.Q[i])
            if i == self.rear:
                break
            i = (i + 1) % self.MAX
        print("  Queue (front -> rear):", items, "| size =", self.size())

cq.display()

# Program 3: Deque (double-ended queue) using a circular array
# Insert and delete at BOTH ends.

class Deque:
    def __init__(self, max_size):
        self.MAX = max_size
        self.Q = [None] * max_size
        self.front = -1
        self.rear = -1

    def is_empty(self):
        return self.front == -1

    def is_full(self):
        return (self.rear + 1) % self.MAX == self.front

    def insert_front(self, item):
        if self.is_full():
            print(f"  insert_front({item}) -> OVERFLOW"); return
        if self.front == -1:
            self.front = self.rear = 0
        else:
            self.front = (self.front - 1 + self.MAX) % self.MAX   # step backwards
        self.Q[self.front] = item
        print(f"  insert_front({item}) -> front = {self.front}, rear = {self.rear}")

    def insert_rear(self, item):
        if self.is_full():
            print(f"  insert_rear({item}) -> OVERFLOW"); return
        if self.front == -1:
            self.front = self.rear = 0
        else:
            self.rear = (self.rear + 1) % self.MAX
        self.Q[self.rear] = item
        print(f"  insert_rear({item}) -> front = {self.front}, rear = {self.rear}")

    def delete_front(self):
        if self.is_empty():
            print("  delete_front() -> UNDERFLOW"); return None
        item = self.Q[self.front]; self.Q[self.front] = None
        if self.front == self.rear:
            self.front = self.rear = -1
        else:
            self.front = (self.front + 1) % self.MAX
        print(f"  delete_front() -> {item}, front = {self.front}, rear = {self.rear}")
        return item

    def delete_rear(self):
        if self.is_empty():
            print("  delete_rear() -> UNDERFLOW"); return None
        item = self.Q[self.rear]; self.Q[self.rear] = None
        if self.front == self.rear:
            self.front = self.rear = -1
        else:
            self.rear = (self.rear - 1 + self.MAX) % self.MAX     # step backwards
        print(f"  delete_rear() -> {item}, front = {self.front}, rear = {self.rear}")
        return item

    def display(self):
        if self.is_empty():
            print("  Deque: (empty)"); return
        items, i = [], self.front
        while True:
            items.append(self.Q[i])
            if i == self.rear: break
            i = (i + 1) % self.MAX
        print("  Deque (front -> rear):", items)


d = Deque(5)
d.insert_rear(20); d.insert_rear(30)
d.insert_front(10)          # front wraps to index 4
d.insert_rear(40)
d.display()
print("Array cells:", d.Q)
d.delete_rear(); d.delete_front()
d.display()

# (b) Linked-list queue: front pointer for deletion, rear pointer for insertion
class Node:
    def __init__(self, data):
        self.data, self.next = data, None

class LinkedQueue:
    def __init__(self):
        self.front = self.rear = None

    def enqueue(self, item):
        node = Node(item)
        if self.rear is None:            # empty queue
            self.front = self.rear = node
        else:
            self.rear.next = node        # link after the current rear
            self.rear = node

    def dequeue(self):
        if self.front is None:
            raise IndexError("Underflow: queue is empty")
        item = self.front.data
        self.front = self.front.next
        if self.front is None:           # queue became empty
            self.rear = None
        return item

    def display(self):
        t, out = self.front, []
        while t:
            out.append(str(t.data)); t = t.next
        print("  front -> " + " -> ".join(out + ["NULL"]) + "   (rear = " + (str(self.rear.data) if self.rear else "NULL") + ")")

lq = LinkedQueue()
for x in [5, 15, 25]:
    lq.enqueue(x)
lq.display()
print("dequeue() ->", lq.dequeue())
lq.enqueue(35)
lq.display()

What to notice

In real Python programs, use collections.deque. The linked queue shows the textbook design: enqueue via rear, dequeue via front, and reset rear to None when the queue empties.

# Program 5: Applications of queues
from collections import deque

# (a) Round-robin CPU scheduling with a circular queue (all arrive at time 0)
def round_robin(bursts, quantum):
    ready = deque(bursts.keys())
    remaining = dict(bursts)
    time, gantt, finish = 0, [], {}
    while ready:
        p = ready.popleft()                       # take the process at the front
        run = min(quantum, remaining[p])
        gantt.append(f"{p}[{time}-{time + run}]")
        time += run
        remaining[p] -= run
        if remaining[p] > 0:
            ready.append(p)                       # not finished: back of the queue
        else:
            finish[p] = time
    print("Gantt chart:", " ".join(gantt))
    for p in bursts:
        tat = finish[p]                           # turnaround = finish - arrival(0)
        wt = tat - bursts[p]                      # waiting = turnaround - burst
        print(f"  {p}: finish={finish[p]:2}  turnaround={tat:2}  waiting={wt:2}")
    avg_wt = sum(finish[p] - bursts[p] for p in bursts) / len(bursts)
    print(f"  Average waiting time = {avg_wt:.2f}")

# (b) Palindrome check with a deque: compare both ends
def is_palindrome(text):
    d = deque(ch.lower() for ch in text if ch.isalnum())
    while len(d) > 1:
        if d.popleft() != d.pop():
            return False
    return True

# (c) Hot potato (Josephus problem): pass k times, the holder leaves
def hot_potato(names, k):
    q = deque(names)
    order = []
    while len(q) > 1:
        for _ in range(k):
            q.append(q.popleft())                 # pass the potato
        order.append(q.popleft())                 # holder is out
    return order, q[0]

Practice & Assessment

A. Conceptual questions

1. Define a queue. How does it differ from a stack?

A queue is a linear structure with insertion at the rear and deletion at the front (FIFO). A stack inserts and deletes at the same end, the top (LIFO).

2. What is false overflow? How does a circular queue solve it?

In a simple queue, once rear = MAX − 1 no insertion is possible, even if dequeues have freed cells at the front. A circular queue wraps rear around with (rear + 1) mod MAX, so those cells are reused.

3. Write the conditions for empty and full in a circular queue.

Empty: front = −1. Full: (rear + 1) mod MAX = front.

4. What is a deque? Explain input-restricted and output-restricted deques.

A deque allows insertion and deletion at both ends. Input-restricted: insertion at one end only, deletion at both. Output-restricted: deletion at one end only, insertion at both.

5. Why is collections.deque preferred over list for queues in Python?

deque.popleft() is O(1), while list.pop(0) shifts all remaining elements, which is O(n).
