Minimum Spanning Trees: Prim's & Kruskal's Algorithms

What is a Minimum Spanning Tree?

Suppose a company must lay fibre-optic cable to connect six office buildings. Cable can only run along certain routes, and each route has a cost. The company wants every building connected (directly or indirectly) while spending as little as possible. There is no need for two different routes between the same buildings — that would waste money. The cheapest such network is a Minimum Spanning Tree.

Definitions
  • A tree is a connected graph with no cycles.
  • A spanning tree of a connected, undirected graph G = (V, E) is a subgraph that includes every vertex of G and is a tree. It always has exactly |V| − 1 edges.
  • In a weighted graph, the weight of a spanning tree is the sum of the weights of its edges.
  • A Minimum Spanning Tree (MST) is a spanning tree whose total weight is the smallest possible. (Also called a minimum-cost spanning tree.)

A simple example

The graph below has 4 vertices and 5 edges. It has 8 different spanning trees (each with exactly 3 edges). Three of them are shown. The first one has the smallest total weight, 6, so it is the MST.

  • Spanning tree = all 4 vertices, 3 edges, no cycle.
  • Weights of all 8 spanning trees: 6, 7, 8, 8, 9, 9, 11, 12.
  • Adding any 4th edge to a spanning tree creates a cycle; removing any edge disconnects it.

Why do we need MSTs?

Trying every spanning tree is hopeless: a complete graph on n vertices has nn−2 spanning trees (Cayley's formula) — already 100 million for n = 10. Prim's and Kruskal's algorithms find an MST quickly, in about E log V steps.

Real-world applications

🔌 Network design

Laying cable, pipelines, power lines or roads to connect all locations at minimum total cost.

🧩 Clustering

Build an MST and delete the k − 1 heaviest edges: the remaining pieces are k natural clusters (single-linkage clustering).

🧭 Approximation algorithms

An MST gives a route at most twice the optimal for the metric Travelling Salesman Problem.

🖼️ Image segmentation

Pixels are vertices, colour differences are weights; MST-based methods split an image into regions.

📡 Broadcasting

Sending a message to every node of a network once, over the cheapest set of links.

🏘️ Circuit design

Connecting pins on a circuit board with the least amount of wire.

Core Concepts

2.1 Key terminology

TermMeaning
Undirected weighted graphEdges have no direction (u–v is the same as v–u) and each edge has a weight. MSTs are defined for this kind of graph.
Connected graphThere is a path between every pair of vertices. Only a connected graph has a spanning tree.
CycleA path that starts and ends at the same vertex. A tree never contains one.
CutA division of the vertices into two groups S and V − S.
Crossing edgeAn edge with one end in S and the other in V − S.
Light edgeThe crossing edge with the minimum weight for a given cut.
Greedy algorithmMakes the choice that looks best right now (the cheapest safe edge) and never undoes it. For MSTs, greedy choices are provably optimal.
Spanning forestFor a disconnected graph: one spanning tree for each connected component.

2.2 Properties of spanning trees

  • A spanning tree of a graph with V vertices has exactly V − 1 edges.
  • Adding any extra edge to a spanning tree creates exactly one cycle.
  • Removing any edge from a spanning tree disconnects it into two parts.
  • A connected graph may have many spanning trees and even several MSTs, but all MSTs have the same total weight.
  • If all edge weights are distinct, the MST is unique.

2.3 The two rules behind every MST algorithm

Cut property

For any cut (S, V − S), the lightest crossing edge belongs to some MST. (If weights are distinct, to every MST.)

Why: if an MST T did not use the light edge e, add e to T. This creates a cycle that must cross the cut again through some heavier edge f. Swap f for e: still a spanning tree, and no heavier. So e is safe.

Prim's algorithm uses this rule: S = the tree built so far.

Cycle property

The heaviest edge on any cycle (if it is strictly the heaviest) is not in any MST.

Why: removing it keeps the graph connected (the rest of the cycle is still there), and makes the total cheaper.

Kruskal's algorithm uses this rule: an edge that would close a cycle is the heaviest on that cycle, so it is rejected.

Prim's and Kruskal's Algorithms

Both algorithms are greedy: they build the MST one edge at a time, always adding the cheapest edge that is safe (keeps the result cycle-free and can be part of an MST). They differ in which edges they consider.

🌱 Prim's — grow one tree

Start from any vertex. Repeatedly add the cheapest edge that connects the tree to a new vertex. The tree grows like a plant from its seed.

🧱 Kruskal's — merge many trees

Sort all edges. Go from lightest to heaviest and add an edge if it does not form a cycle. Small trees (a forest) merge until one tree remains.

3.1 Prim's algorithm

Proposed by Vojtěch Jarník (1930) and rediscovered by Robert Prim (1957) and Edsger Dijkstra (1959), so it is also called the Jarník–Prim algorithm.

Step-by-step working

  1. Choose a start vertex s. Set key[s] = 0 and key[v] = ∞ for all other vertices. (key[v] = weight of the cheapest edge that connects v to the tree so far; parent[v] = the tree vertex at the other end of that edge.)
  2. Pick the vertex u not yet in the tree with the smallest key, and add it to the tree (together with the edge parent[u]–u).
  3. For every neighbour v of u that is still outside the tree: if w(u, v) < key[v], set key[v] = w(u, v) and parent[v] = u.
  4. Repeat steps 2–3 until all V vertices are in the tree.

Pseudocode

1PRIM(G, s)
2 for each vertex v: key[v] ← ∞, parent[v] ← NIL, inMST[v] ← false
3 key[s] ← 0
4 repeat V times:
5 u ← vertex with inMST[u] = false and minimum key[u] // EXTRACT-MIN
6 inMST[u] ← true // edge parent[u]–u joins the MST
7 for each neighbour v of u:
8 if inMST[v] = false and w(u, v) < key[v]:
9 key[v] ← w(u, v); parent[v] ← u // DECREASE-KEY

3.2 Kruskal's algorithm

Published by Joseph Kruskal in 1956.

Step-by-step working

  1. Put every vertex in its own set (a forest of V single-vertex trees).
  2. Sort all edges in non-decreasing order of weight.
  3. Take the next edge (u, v). If u and v are in different sets, add the edge to the MST and merge (union) the two sets. If they are in the same set, the edge would form a cycle — reject it.
  4. Stop when the MST has V − 1 edges (or the edges run out).

Pseudocode

1KRUSKAL(G)
2 A ← ∅ // edges of the MST
3 for each vertex v: MAKE-SET(v)
4 sort the edges of G by weight (ascending)
5 for each edge (u, v) in sorted order:
6 if FIND-SET(u) ≠ FIND-SET(v): // different trees → no cycle
7 A ← A ∪ {(u, v)}
8 UNION(u, v)
9 return A

Detecting cycles: the Disjoint Set Union (Union–Find)

Kruskal's needs a fast way to answer “are u and v already connected?”. The Disjoint Set Union (DSU) data structure stores each tree of the forest as a set, using a parent array. Each set has a representative (root).

  • MAKE-SET(v): parent[v] = v — v is alone in its set.
  • FIND(v): follow parent pointers up to the root. Path compression makes every visited node point directly at the root, so later finds are faster.
  • UNION(u, v): make one root the parent of the other. Union by rank attaches the shorter tree under the taller one, keeping trees flat.

With both optimisations, each operation takes O(α(V)) amortised time, where α is the inverse Ackermann function — less than 5 for any realistic input, i.e. practically constant.

Complexity Analysis

4.1 Prim's algorithm

The cost depends on how we find the minimum-key vertex (EXTRACT-MIN, done V times) and how we lower keys (DECREASE-KEY, up to E times):

ImplementationEXTRACT-MINDECREASE-KEYTotal timeGood for
Adjacency matrix + arrayO(V) each, V timesO(1)O(V²)Dense graphs (E ≈ V²)
Adjacency list + binary heapO(log V)O(log V)O((V + E) log V) = O(E log V)Sparse graphs
Adjacency list + Fibonacci heap (reference)O(log V) amortisedO(1) amortisedO(E + V log V)Theory / very large graphs

Program 1 in Section 7 uses Python's heapq with “lazy deletion” (old entries are skipped when popped). The heap can then hold up to E entries, giving O(E log E) = O(E log V), since E ≤ V² means log E ≤ 2 log V.

4.2 Kruskal's algorithm

T = O(E log E) sorting + O(E · α(V)) find/union = O(E log E) = O(E log V)
  • Sorting the edges dominates the running time.
  • With union by rank + path compression, the DSU part is almost linear: O(E α(V)).
  • Without any DSU optimisation, FIND can take O(V), giving O(E · V) — much slower.
  • If the edges are already sorted (or weights are small integers that can be counting-sorted), Kruskal's runs in nearly O(E).

4.3 Best, average and worst cases

AlgorithmBest caseAverage caseWorst caseSpace
Prim's (array)Θ(V²)Θ(V²)Θ(V²)O(V²) matrix + O(V) arrays
Prim's (binary heap)O(E log V)O(E log V)O(E log V)O(V + E)
Kruskal's (DSU)O(E log E)*O(E log E)O(E log E)O(V + E)

* Kruskal's can stop early once V − 1 edges are chosen, but the sort is already done, so the bound stays O(E log E).

4.4 Relation to Dijkstra's algorithm

Prim's algorithm looks almost identical to Dijkstra's (from our earlier post): both grow a set from a start vertex using a priority queue. The only difference is the value stored in the queue:

Prim's (MST)Dijkstra's (shortest paths)
Priority of vkey[v] = w(u, v) — weight of one edgedist[v] = dist[u] + w(u, v) — length of the whole path
ResultTree of minimum total weightTree of shortest paths from the source
Negative weightsAllowedNot allowed

Difference between Prim's and Kruskal's Algorithms

Both algorithms are greedy, both produce a minimum spanning tree of the same total weight, and both work with negative weights. Here is how they differ — a very common examination question.

5.1 Point-by-point comparison

BasisPrim's algorithmKruskal's algorithm
ApproachVertex-based: grows one tree from a start vertexEdge-based: picks edges globally, merging a forest of trees
Starting pointNeeds a start vertexNo start vertex; starts from the lightest edge
Edge selectedCheapest edge joining the tree to a new vertexCheapest remaining edge in the whole graph that does not form a cycle
Partial resultAlways a single connected treeMay be a disconnected forest until the end
Rule usedCut propertyCycle property (and cut property)
Cycle checkingNot needed: a new vertex is always outside the treeNeeded for every edge: Disjoint Set Union (Union–Find)
Main data structurePriority queue (min-heap) or key arraySorted edge list + Disjoint Set Union
Graph representationAdjacency matrix or adjacency listEdge list
Time complexityO(V²) with array; O(E log V) with binary heapO(E log E) = O(E log V)
Best forDense graphs (many edges)Sparse graphs (few edges)
Disconnected graphSpans only the start vertex's component (must be restarted)Naturally produces a minimum spanning forest
Edges pre-sorted?No benefitBig benefit: skips the O(E log E) sort
Similar toDijkstra's algorithmUnion–Find based connectivity / clustering

5.2 Similarities

  • Both follow the greedy design technique and always produce an optimal (minimum) spanning tree.
  • Both select exactly V − 1 edges for a connected graph.
  • Both work with negative and zero edge weights.
  • Both need an undirected graph.
  • When weights are distinct, both return the same MST; with ties they may choose different MSTs of the same weight.

5.3 Same graph, different order

On our worked example both algorithms pick the same five edges, but in a different order:

Prim's (start A)

1. A–C 32. C–B 43. B–D 24. D–E 75. E–F 1

Follows the tree outward; a heavy edge (7) can come before a light one (1).

Kruskal's

1. E–F 12. B–D 23. A–C 34. B–C 45. D–E 7

Special Cases & Common Mistakes

6.1 Special cases and edge cases

SituationWhat happens / what to do
Disconnected graphNo spanning tree exists. Kruskal's returns a minimum spanning forest with V − c edges (c = number of components). Prim's spans only the start vertex's component unless restarted from each unvisited vertex. Try the “Disconnected graph” preset.
Equal weights (ties)There can be several different MSTs, all with the same total weight. A square with four edges of weight 1 has 4 MSTs. Which one you get depends on the tie-breaking order.
Negative or zero weightsPerfectly fine for both algorithms — only the order of weights matters, never their sum along a path.
Directed graphsPrim's and Kruskal's do not apply. The directed version (minimum spanning arborescence) needs a different algorithm (Chu–Liu/Edmonds), which is beyond this syllabus.
Self-loopsNever part of a tree (a self-loop is a cycle). Ignore them.
Parallel edgesOnly the lightest edge between a pair of vertices can be useful. Kruskal's handles this automatically; for a matrix keep min.
Maximum spanning treeSort in descending order (Kruskal's) or use a max-heap (Prim's), or negate all weights and find the MST.
Graph that is already a treeThe MST is the graph itself (E = V − 1).

6.2 Advantages and disadvantages

✅ Advantages

  • Both are simple greedy algorithms with a proof of optimality.
  • Fast: O(E log V) — far better than checking all spanning trees.
  • Handle negative weights (unlike Dijkstra's).
  • Kruskal's is easy to code with an edge list and works on forests.
  • Prim's array version is ideal for dense graphs and needs no sorting.

❌ Disadvantages

  • Only for undirected graphs.
  • An MST minimises total weight, not the distance between two particular vertices.
  • Kruskal's needs all edges sorted first — wasteful for very dense graphs.
  • Prim's needs a priority queue for good speed on sparse graphs.
  • With ties, the MST is not unique, which can surprise users.

6.3 Common implementation mistakes

Mistake 1 — Using “visited vertices” for cycle detection in Kruskal's

Some students reject an edge if both ends are already visited. That is wrong. Edges A–B (1), C–D (2), B–C (3): after the first two edges, all four vertices are “visited”, so B–C is rejected — but it is needed to connect {A, B} with {C, D}! Two vertices can both be visited yet lie in different trees. Always use Union–Find (compare roots).

Mistake 2 — Storing undirected edges only once in an adjacency list

For Prim's, the edge u–v must appear in both adj[u] and adj[v]. Otherwise the algorithm can only travel in one direction and may miss vertices.

Mistake 3 — Updating keys of vertices already in the tree

In Prim's, check not in_mst[v] before lowering key[v]. Otherwise parent[] gets overwritten for tree vertices and the reported edges are wrong.

Mistake 4 — Not skipping stale heap entries

With heapq (no decrease-key), a vertex can be pushed several times. When popping, skip it if it is already in the tree (if v in in_mst: continue).

Mistake 5 — Confusing an MST with shortest paths

The path between two vertices inside the MST is not necessarily their shortest path in the graph. See the example below.

6.4 MST ≠ Shortest-path tree

Triangle with A–B = 2, B–C = 2, A–C = 3.

  • MST = {A–B, B–C}, weight 4. In it, the path from A to C costs 4.
  • Shortest-path tree from A (Dijkstra) = {A–B, A–C}, weight 5, because the shortest A→C distance is 3.

Different goals, different trees.

6.5 Important examination points

Remember for exams
  • A spanning tree of V vertices has V − 1 edges; a complete graph Kn has nn−2 spanning trees.
  • Prim's and Kruskal's are greedy algorithms; both give an optimal MST.
  • Prim's: O(V²) with matrix, O(E log V) with binary heap. Kruskal's: O(E log E).
  • Kruskal's uses Disjoint Set Union to detect cycles; Prim's uses a priority queue.
  • Prim's → dense graphs; Kruskal's → sparse graphs.
  • Distinct weights ⇒ unique MST. Negative weights are allowed.
  • When tracing, always write the order in which edges are added and the total cost.

Python Implementation

All four programs are complete and runnable (Python 3.6+). The outputs shown are their real outputs on the worked example. Use the tabs to switch programs and Copy to copy the code.

prim_heap.py
# Prim's Algorithm using a Min-Heap (priority queue) — O(E log V)
# Graph is stored as an adjacency list: {vertex: [(neighbour, weight), ...]}

import heapq


def prim_mst(graph, start):
    in_mst = set()                     # vertices already in the tree
    mst_edges = []                     # (u, v, weight) edges chosen
    total = 0
    # heap entries: (edge weight, from-vertex, to-vertex)
    heap = [(0, None, start)]

    while heap and len(in_mst) < len(graph):
        w, u, v = heapq.heappop(heap)  # cheapest edge leaving the tree
        if v in in_mst:
            continue                   # stale entry: v was added already
        in_mst.add(v)
        if u is not None:
            mst_edges.append((u, v, w))
            total += w
        for nbr, wt in graph[v]:       # push edges to vertices outside tree
            if nbr not in in_mst:
                heapq.heappush(heap, (wt, v, nbr))
    return mst_edges, total


def build_graph(edges):
    graph = {}
    for u, v, w in edges:              # undirected: add both directions
        graph.setdefault(u, []).append((v, w))
        graph.setdefault(v, []).append((u, w))
    return graph


if __name__ == "__main__":
    edges = [("A", "B", 6), ("A", "C", 3), ("B", "C", 4), ("B", "D", 2),
             ("C", "D", 5), ("C", "E", 9), ("D", "E", 7), ("D", "F", 8),
             ("E", "F", 1)]
    graph = build_graph(edges)
    mst, cost = prim_mst(graph, "A")
    print("Prim's MST (start = A), edges in the order they were added:")
    for u, v, w in mst:
        print(f"  {u} - {v}   weight {w}")
    print("Total weight of MST =", cost)

How the code works

  • The heap stores (weight, from, to) tuples, so heappop always returns the cheapest edge leaving the tree.
  • Python's heapq has no decrease-key, so we simply push new entries and skip stale ones (vertices already in the tree).
  • build_graph adds each undirected edge in both directions.
prim_matrix.py
# Prim's Algorithm using an Adjacency Matrix — O(V^2)
# This is the version usually traced in exams: it keeps key[] and parent[] arrays.

INF = float('inf')


def prim_matrix(W, names, start=0):
    n = len(W)
    key = [INF] * n          # key[v] = cheapest edge joining v to the tree
    parent = [None] * n      # parent[v] = tree vertex at the other end
    in_mst = [False] * n
    key[start] = 0

    for step in range(n):
        # 1. pick the non-tree vertex with the smallest key
        u = min((v for v in range(n) if not in_mst[v]), key=lambda v: key[v])
        if key[u] == INF:
            print("Graph is disconnected!")
            break
        in_mst[u] = True

        # 2. update keys of its neighbours that are still outside the tree
        for v in range(n):
            if W[u][v] != INF and not in_mst[v] and W[u][v] < key[v]:
                key[v] = W[u][v]
                parent[v] = u

        keys = " ".join(f"{('-' if in_mst[v] else ('∞' if key[v] == INF else key[v])):>2}"
                        for v in range(n))
        print(f"Step {step + 1}: add {names[u]}   key = [{keys}]")

    total = 0
    print("MST edges:")
    for v in range(n):
        if parent[v] is not None:
            print(f"  {names[parent[v]]} - {names[v]}   weight {W[parent[v]][v]}")
            total += W[parent[v]][v]
    print("Total weight =", total)


if __name__ == "__main__":
    names = ["A", "B", "C", "D", "E", "F"]
    n = len(names)
    W = [[INF] * n for _ in range(n)]
    for u, v, w in [(0, 1, 6), (0, 2, 3), (1, 2, 4), (1, 3, 2), (2, 3, 5),
                    (2, 4, 9), (3, 4, 7), (3, 5, 8), (4, 5, 1)]:
        W[u][v] = W[v][u] = w          # undirected: symmetric matrix
    print("key order:", " ".join(f"{x:>2}" for x in names))
    prim_matrix(W, names, start=0)

How the code works

  • This is the classic exam version with key[], parent[] and in_mst[] arrays. The printed key rows match the worked example table in Section 3.
  • Finding the minimum key is a simple O(V) scan, done V times → O(V²). No heap is needed.
  • MST edges are read from parent[] at the end (in vertex order, not in the order they were added).
kruskal.py
# Kruskal's Algorithm with Disjoint Set Union (Union-Find) — O(E log E)

class DisjointSet:
    def __init__(self, vertices):
        self.parent = {v: v for v in vertices}   # every vertex is its own set
        self.rank = {v: 0 for v in vertices}

    def find(self, x):
        # path compression: point x directly at the root
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])
        return self.parent[x]

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False                         # same set -> would form a cycle
        # union by rank: attach the shorter tree under the taller one
        if self.rank[ra] < self.rank[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        if self.rank[ra] == self.rank[rb]:
            self.rank[ra] += 1
        return True


def kruskal_mst(vertices, edges):
    ds = DisjointSet(vertices)
    mst, total = [], 0
    for u, v, w in sorted(edges, key=lambda e: e[2]):    # 1. sort by weight
        if ds.union(u, v):                               # 2. no cycle -> take it
            mst.append((u, v, w))
            total += w
            print(f"  accept {u}-{v} ({w})")
            if len(mst) == len(vertices) - 1:            # 3. tree complete
                break
        else:
            print(f"  reject {u}-{v} ({w})  -> would form a cycle")
    return mst, total

# Prim vs Kruskal on the same graph + Minimum Spanning FOREST for a
# disconnected graph (Kruskal handles it naturally; Prim needs a restart).

import heapq


def kruskal(vertices, edges):
    parent = {v: v for v in vertices}

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]   # path halving
            x = parent[x]
        return x

    chosen = []
    for u, v, w in sorted(edges, key=lambda e: e[2]):
        ru, rv = find(u), find(v)
        if ru != rv:
            parent[ru] = rv
            chosen.append((u, v, w))
    return chosen


def prim_forest(vertices, edges):
    adj = {v: [] for v in vertices}
    for u, v, w in edges:
        adj[u].append((w, u, v))
        adj[v].append((w, v, u))
    seen, chosen, trees = set(), [], 0
    for s in vertices:                      # restart Prim in each component
        if s in seen:
            continue
        trees += 1
        seen.add(s)
        heap = list(adj[s])
        heapq.heapify(heap)
        while heap:
            w, u, v = heapq.heappop(heap)
            if v in seen:
                continue
            seen.add(v)
            chosen.append((u, v, w))
            for e in adj[v]:
                if e[2] not in seen:
                    heapq.heappush(heap, e)
    return chosen, trees


def weight(es):
    return sum(w for _, _, w in es)


if __name__ == "__main__":
    V = ["A", "B", "C", "D", "E", "F"]
    E = [("A", "B", 6), ("A", "C", 3), ("B", "C", 4), ("B", "D", 2),
         ("C", "D", 5), ("C", "E", 9), ("D", "E", 7), ("D", "F", 8),
         ("E", "F", 1)]
    k = kruskal(V, E)
    p, _ = prim_forest(V, E)
    print("Kruskal order:", [f"{u}{v}" for u, v, _ in k], "weight", weight(k))
    print("Prim order   :", [f"{u}{v}" for u, v, _ in p], "weight", weight(p))
    print("Same total weight?", weight(k) == weight(p))

    # disconnected graph: {P, Q, R} and {S, T}
    V2 = ["P", "Q", "R", "S", "T"]
    E2 = [("P", "Q", 4), ("Q", "R", 1), ("P", "R", 3), ("S", "T", 2)]
    f, trees = prim_forest(V2, E2)
    print("\nDisconnected graph -> spanning forest with", trees, "trees")
    print("Forest edges:", [f"{u}{v}({w})" for u, v, w in kruskal(V2, E2)],
          "weight", weight(f))
    print("Edges in forest = V - (number of trees) =", len(V2) - trees)

8.1 Conceptual questions

Q1. Define a minimum spanning tree. How many edges does it have?
A spanning tree of a connected, undirected, weighted graph whose total edge weight is the smallest possible. It has exactly V − 1 edges.
Q2. Why are Prim's and Kruskal's called greedy algorithms? Why does greedy work here?
At each step they take the cheapest edge that is currently safe and never undo the choice. Greedy works because of the cut property: the lightest edge crossing any cut is always part of some MST.
Q3. Why does Kruskal's need a Disjoint Set Union but Prim's does not?
Kruskal's may pick an edge anywhere in the graph, so it must check whether both ends are already connected (that would create a cycle). Prim's only adds edges from the tree to a vertex outside the tree, which can never create a cycle.
Q4. Can a graph have more than one MST? When is it unique?
Yes, when some edges have equal weights (e.g. a square with all weights 1 has 4 MSTs). If all edge weights are distinct, the MST is unique. All MSTs of a graph have the same total weight.
Q5. Which algorithm would you use for a graph with 10,000 vertices and 20,000 edges? Why?
The graph is sparse (E ≈ 2V). Kruskal's (O(E log E)) or Prim's with a binary heap (O(E log V)) are both fine; the O(V²) array version of Prim's (10⁸ steps) would be much slower. Kruskal's is the usual choice for sparse graphs.
