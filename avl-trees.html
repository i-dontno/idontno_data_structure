AVL trees: a BST that Balances Itself

A normal Binary Search Tree can become unbalanced and behave like a linked list. An AVL tree automatically balances itself after every insertion or deletion to keep searching fast.

1. The problem: drawbacks of a plain BST

A Binary Search Tree (BST) allows fast searching in O(log n) time only when the tree is balanced. However, a normal BST does not automatically balance itself, so it can become unbalanced and make searching slower, taking O(n) time.

Sorted input makes a chainInsert 1, 2, 3, 4, 5 and every key goes right. The tree becomes a linked list with height n.
Shape depends on insertion orderThe same seven keys can give height 3 or height 7. You cannot control what order data arrives in.
No self-correction after insert or deleteDeleting nodes from the shorter side, or inserting into the taller side, makes the tree more unbalanced, and nothing repairs it.
Worst case is O(n)Search, insert and delete all walk the longest path, so each can take n steps.
Deep recursionRecursive operations on a skewed tree use n stack frames and can overflow for large n.
Unpredictable timingAverage performance is usually O(log n), but it is not guaranteed. Real-time systems and databases need a guaranteed maximum time for operations.

A Binary Search Tree (BST) is a binary tree in which all values in the left subtree are smaller than the node, and all values in the right subtree are larger. Python: BST insertion and search 
class Node:
    def __init__(self, data):
        self.data = data
        self.left = None
        self.right = None

def insert(root, key):
    if root is None:
        return Node(key)

    if key < root.data:
        root.left = insert(root.left, key)
    elif key > root.data:
        root.right = insert(root.right, key)

    return root

def search(root, key):
    if root is None or root.data == key:
        return root

    if key < root.data:
        return search(root.left, key)

    return search(root.right, key)

def inorder(root):
    if root:
        inorder(root.left)
        print(root.data, end=" ")
        inorder(root.right)
The solution: keep the tree balanced automatically. An AVL tree (Adelson-Velsky and Landis, 1962, the first self-balancing BST) is a BST where, for every node, the heights of the left and right subtrees differ by at most 1. After any insert or delete that breaks this, it repairs the tree with rotations.

2. Balance factor

BF(node) = height(left subtree) − height(right subtree)
  • AVL rule: −1 ≤ BF ≤ +1 for every node, not just the root.
  • Balance Factor (BF): It tells us whether a node is balanced or leaning to one side.
    • BF = +1: The left subtree is taller by one.
    • BF = -1: The right subtree is taller by one.
    • BF = 0: Both subtrees have equal height.
  • Height: Height is measured by counting edges along the longest path from a node to a leaf. An empty subtree has height -1, and a leaf node has height 0.
  • When is a tree unbalanced? If a node has a balance factor of +2 or -2, it is unbalanced and needs rebalancing.
  • Finding the problem: After inserting or deleting a node, move upward through its ancestors to find the first unbalanced node.
  • Fast calculation: Each node stores its height, allowing its balance factor to be calculated in O(1) time.
  • In the lab: A tree is an AVL tree only if every node has a balance factor of -1, 0, or +1. If any node is marked red, the tree is unbalanced.

4. The four rotation cases

A rotation re-links a few pointers in O(1). It never breaks the BST order (inorder sequence stays sorted). Choose a case and step through it.

CaseWhere the new node wentImbalanced nodeFix
LLleft subtree of left childBF = +2, left child BF ≥ 0one right rotation
RRright subtree of right childBF = −2, right child BF ≤ 0one left rotation
LRright subtree of left childBF = +2, left child BF < 0left on the left child, then right on the node
RLleft subtree of right childBF = −2, right child BF > 0right on the right child, then left on the node
  • Memory trick: whichever case it is, the middle value of the three nodes involved becomes the new subtree root (20 in every example here).
  • Insertion: after at most one rotation (single or double) the whole tree is balanced again.
  • Deletion: a fix can shorten the subtree and cause a new violation higher up, so up to O(log n) rotations may be needed. This is why the doc compares AVL unfavourably with Red-Black trees on updates.

Drawbacks of AVL trees

  • More rebalancing work on updates, especially deletion, than Red-Black trees. Libraries such as Java's TreeMap and C++ std::map use Red-Black trees for that reason.
  • Extra memory for a height (or balance factor) in every node, and more complex code, especially deletion.
  • Not the choice for disk-based indexes: databases use B-trees or B+ trees, which are wide and shallow to reduce disk reads. AVL suits in-memory, lookup-heavy data.
  • Best when reads greatly outnumber writes (dictionaries, lookup tables, in-memory indexes).

7. Python implementation

class Node:
    def __init__(self, key):
        self.key, self.left, self.right, self.h = key, None, None, 1

def h(n):  return n.h if n else 0
def bf(n): return h(n.left) - h(n.right) if n else 0
def update(n): n.h = 1 + max(h(n.left), h(n.right))

def rotate_right(y):
    x = y.left
    y.left, x.right = x.right, y
    update(y); update(x)
    return x                      # x is the new subtree root

def rotate_left(x):
    y = x.right
    x.right, y.left = y.left, x
    update(x); update(y)
    return y

def rebalance(n):
    update(n)
    b = bf(n)
    if b > 1:                     # left heavy
        if bf(n.left) < 0:        # LR case: first fix the child
            n.left = rotate_left(n.left)
        return rotate_right(n)    # LL case (or LR step 2)
    if b < -1:                    # right heavy
        if bf(n.right) > 0:       # RL case
            n.right = rotate_right(n.right)
        return rotate_left(n)     # RR case (or RL step 2)
    return n

def insert(n, key):
    if n is None: return Node(key)
    if key < n.key:   n.left  = insert(n.left, key)
    elif key > n.key: n.right = insert(n.right, key)
    else: return n
    return rebalance(n)

def delete(n, key):
    if n is None: return None
    if key < n.key:   n.left  = delete(n.left, key)
    elif key > n.key: n.right = delete(n.right, key)
    else:
        if n.left is None:  return n.right
        if n.right is None: return n.left
        s = n.right                # inorder successor
        while s.left: s = s.left
        n.key = s.key
        n.right = delete(n.right, s.key)
    return rebalance(n)
  • Insert and delete are ordinary BST operations followed by rebalance on the way back up the recursion.
  • Search is identical to BST search, so reuse it unchanged.
