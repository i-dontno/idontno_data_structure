Introduction to Shortest Path Problems

Imagine a map of cities joined by roads, where each road has a travel time. A natural question is: what is the quickest way to get from one city to another? This is the shortest path problem, one of the most important problems in graph theory.

Definitions
  • A weighted graph G = (V, E) is a graph where every edge (u, v) has a number w(u, v) called its weight (cost, distance or time).
  • A path is a sequence of vertices v0 → v1 → … → vk where each consecutive pair is joined by an edge.
  • The weight of a path is the sum of its edge weights.
  • The shortest-path distance δ(u, v) is the minimum weight over all paths from u to v. If no path exists, δ(u, v) = ∞ (infinity).

Note that “shortest” means least total weight, not fewest edges. A path with four cheap edges can beat a single expensive edge.

Four versions of the problem

SSSP

Single-source

Distances from one source vertex to all other vertices. Solved by Dijkstra's algorithm (non-negative weights) or Bellman–Ford.

SDSP

Single-destination

Distances from every vertex to one target. Reverse all edges and it becomes single-source.

SPSP

Single-pair

Shortest path from u to v only. Usually solved by running a single-source algorithm and stopping early.

APSP

All-pairs

Shortest distance between every pair (u, v). This is what Floyd–Warshall solves.

In our previous post we studied Dijkstra's algorithm, which solves the single-source problem very efficiently. In this post we focus on the all-pairs problem and the classic algorithm for it: Floyd–Warshall.

Why do we need an all-pairs algorithm?

Many applications need a complete “distance table” rather than distances from just one place:

🗺️ Road atlases & maps

The city-to-city distance chart printed in road atlases is exactly an all-pairs shortest path table.

🌐 Network routing

Routers need the cheapest route between every pair of nodes in a (small) network.

🏥 Facility location

To place a hospital so the farthest town is as close as possible, you need all pairwise distances (the graph centre).

💱 Currency arbitrage

With weights −log(rate), a negative cycle means a profitable exchange loop. Floyd–Warshall can detect it.

🔗 Reachability

A small change gives Warshall's algorithm, which finds whether any path exists between each pair (transitive closure).

🎮 Games & AI

Small game maps often pre-compute all distances so characters can look up routes instantly.

A simple example

Look at the graph below. The direct road from A to B costs 7. But the route A → D → C → B costs 1 + 1 + 1 = 3. The direct edge is not the shortest path! Also notice the edge B → A has a negative weight (−1), which Dijkstra's algorithm cannot handle correctly. Floyd–Warshall can.

Core Concepts

2.1 Key terminology

TermMeaning
Intermediate vertexAny vertex on a path other than the first and last. In A → D → C → B, the intermediate vertices are D and C.
Distance matrix DAn n × n table where D[i][j] stores the best known distance from vertex i to vertex j.
Weight (cost) matrix WThe adjacency matrix with weights: W[i][j] = weight of edge i→j, 0 if i = j, and ∞ if there is no edge. This is the starting matrix D(0).
RelaxationTrying to improve a distance through another vertex: if going through k is shorter, update the distance.
Negative edgeAn edge with weight < 0 (e.g. a refund, a discount, or a downhill energy gain). Allowed in Floyd–Warshall.
Negative cycleA cycle whose total weight is < 0. Going around it repeatedly makes a path cheaper without limit, so shortest paths are undefined. Floyd–Warshall can detect it but cannot give meaningful distances.
Optimal substructureEvery part of a shortest path is itself a shortest path. This property allows dynamic programming.
Dynamic programming (DP)Solving a big problem by combining answers to smaller, overlapping subproblems that are stored in a table.

2.2 The key idea: “allow one more vertex at a time”

Number the vertices 1, 2, …, n. Floyd–Warshall builds a sequence of matrices D(0), D(1), …, D(n), where:

Meaning of D(k)

D(k)[i][j] = length of the shortest path from i to j that uses only vertices 1, 2, …, k as intermediate vertices.

  • D(0): no intermediate vertices allowed → only direct edges. So D(0) = W.
  • D(1): paths may pass through vertex 1.
  • D(2): paths may pass through vertices 1 and 2. And so on …
  • D(n): paths may pass through any vertex → these are the true shortest distances.

When we move from D(k−1) to D(k), the best path from i to j that may use vertex k has only two possibilities:

  1. It does not use k. Then its length is the old value D(k−1)[i][j].
  2. It does use k (exactly once, since there are no negative cycles). Then it splits into i ⇝ k and k ⇝ j, and both parts use only vertices 1…k−1. Its length is D(k−1)[i][k] + D(k−1)[k][j].

We take the smaller of the two.

2.3 The recurrence relation

This gives the famous DP recurrence — learn it by heart for exams:

D(0)[i][j] = w(i, j) // 0 if i = j, ∞ if no edge
D(k)[i][j] = min( D(k−1)[i][j] , D(k−1)[i][k] + D(k−1)[k][j] ) for k ≥ 1

2.4 Internal representation

Floyd–Warshall works on the adjacency matrix representation of a graph (see our Graph Representations post). An adjacency list is not convenient here, because the algorithm looks at every pair (i, j), including pairs with no direct edge. For our example graph (vertices A, B, C, D):

  • Row = “from” vertex, column = “to” vertex.
  • Diagonal entries are 0 (distance from a vertex to itself).
  • ∞ means “no direct edge”.
  • The matrix need not be symmetric because the graph is directed. For an undirected graph, store each edge in both directions.

The Floyd–Warshall Algorithm

The Floyd–Warshall algorithm (published by Robert Floyd in 1962, building on Stephen Warshall's transitive-closure algorithm of the same year; Bernard Roy described a similar method in 1959) is a dynamic programming algorithm that computes the shortest distances between all pairs of vertices in a weighted, directed graph. It works with negative edge weights, as long as there is no negative cycle.

3.1 Step-by-step working

  1. Initialise: create D = W. Put 0 on the diagonal, the edge weight where an edge exists, and ∞ elsewhere.
  2. Pick a pivot k (also called the intermediate vertex), starting from the first vertex.
  3. For every pair (i, j), check whether going through k is shorter: if D[i][k] + D[k][j] < D[i][j], replace D[i][j] with the smaller value.
  4. Repeat steps 2–3 for every vertex k = 1, 2, …, n.
  5. Finish: D now holds all shortest distances. If any diagonal entry D[v][v] < 0, the graph has a negative cycle.

3.2 Algorithm (pseudocode)

1FLOYD-WARSHALL(W, n)
2 D ← W // D(0): direct edges only
3 for k ← 1 to n do // intermediate vertex (OUTERMOST)
4 for i ← 1 to n do // source
5 for j ← 1 to n do // destination
6 if D[i][k] + D[k][j] < D[i][j] then
7 D[i][j] ← D[i][k] + D[k][j]
8 return D
Why can we use just one matrix?

The recurrence uses D(k−1), so it looks like we need n + 1 matrices. But during phase k, row k and column k never change (when there is no negative cycle): for example D[i][k] = min(D[i][k], D[i][k] + D[k][k]) = D[i][k] because D[k][k] = 0. Since every update in phase k only reads row k and column k, updating the matrix in place gives exactly the same result. This reduces space from Θ(n³) to Θ(n²).

3.3 Path reconstruction

The distance matrix tells us how far, but not which route. To recover the actual path, keep a second n × n matrix called next (also called the successor matrix):

  • Initially next[i][j] = j if there is an edge i → j, otherwise None.
  • Whenever D[i][j] is improved through k, set next[i][j] = next[i][k] (“to go from i to j, first head towards k”).
  • To print the path u ⇝ v: start at u and repeatedly jump u = next[u][v] until u = v.
Another convention you may see

Some textbooks store the intermediate vertex instead: P[i][j] = k. The path is then printed recursively as path(i, k) + path(k, j). Both methods are correct; just do not mix them.

Exam shortcut

To fill D(k) quickly by hand: copy row k and column k unchanged, then for every other cell compute (value in row i of column k) + (value in column j of row k), and keep it only if it is smaller than the current cell. If either term is ∞, skip the cell.

Comparison & Complexity Analysis

4.1 Time complexity

The algorithm has three nested loops, each running n = |V| times, and the body does constant work (one addition, one comparison, maybe one assignment):

T(n) = Σk=1..n Σi=1..n Σj=1..n O(1) = n · n · n = Θ(n³)
  • Best case: Θ(V³) — the loops always run fully, even if no update ever happens.
  • Average case: Θ(V³).
  • Worst case: Θ(V³).

The running time does not depend on the number of edges E. That is why Floyd–Warshall is a good choice for dense graphs (E close to V²) and a poor choice for large sparse graphs.

4.2 Space complexity

  • Θ(V²) for the in-place distance matrix (plus another Θ(V²) for the next matrix if paths are needed).
  • A naive version that stores every D(k) separately would need Θ(V³) space — unnecessary, as explained in Section 3.

4.3 Comparison with other shortest-path algorithms

For reference (beyond the usual syllabus): Johnson's algorithm re-weights edges with one Bellman–Ford run and then uses Dijkstra from every vertex, giving O(V² log V + VE) for sparse graphs with negative edges.

4.4 Floyd–Warshall vs Dijkstra at a glance

FeatureDijkstraFloyd–Warshall
OutputDistances from one sourceDistances between all pairs
ApproachGreedy: always finalise the nearest unvisited vertexDP: allow intermediate vertices one at a time
Negative weightsNot allowed (may give wrong answers)Allowed; negative cycles are detected
Data structureAdjacency list + priority queue (min-heap)Adjacency matrix (2-D array)
Best forLarge sparse graphs, one sourceSmall/dense graphs, all pairs
Code lengthModerateVery short (3 loops)

4.5 Why not just use Dijkstra with a negative edge?

Take edges S → A (2), S → B (5) and B → A (−4). Dijkstra starts at S, then picks the nearest vertex A (distance 2) and finalises it. Later it reaches B (distance 5) and discovers A could be reached for 5 − 4 = 1, but A is already final. Dijkstra reports δ(S, A) = 2, which is wrong.

Floyd–Warshall never “finalises” a value early; it keeps improving every cell, so it correctly finds δ(S, A) = 1.

Special Cases & Common Mistakes

5.1 Special cases and edge cases

SituationWhat happens / what to do
Negative cycleSome diagonal entry becomes negative (D[v][v] < 0). Distances involving that cycle are meaningless. Report “negative cycle” instead of distances. Try the “Negative cycle” preset in the visualizer.
Disconnected graphIf j cannot be reached from i, D[i][j] stays ∞. This is correct output, not an error.
Undirected graphPut every edge in both directions: W[u][v] = W[v][u] = w. The result is symmetric. Warning: one negative undirected edge u—v is already a negative cycle u → v → u.
Parallel (multiple) edgesKeep only the smallest weight: W[u][v] = min(W[u][v], w).
Self-loopsA positive self-loop is useless (diagonal stays 0). A negative self-loop is a negative cycle by itself.
TiesUpdate only when strictly smaller (<). Equal values are not an improvement; this keeps the first path found.
Single vertex / no edgesD is just the identity-like matrix of 0s and ∞s. The loops still run in Θ(V³).

5.2 Advantages and disadvantages

✅ Advantages

  • Solves the all-pairs problem in one run.
  • Handles negative edge weights.
  • Detects negative cycles for free (check the diagonal).
  • Very short and easy to code; no heap or queue needed.
  • Fast in practice on small dense graphs (simple loops, cache-friendly array).
  • Easily adapted: transitive closure, widest path, graph centre, etc.

❌ Disadvantages

  • Θ(V³) time is too slow for large graphs (V in the tens of thousands).
  • Θ(V²) memory, even if the graph has few edges.
  • Wasteful when you only need distances from one source.
  • Cannot give meaningful distances when a negative cycle exists.
  • Needs an adjacency matrix; sparse graphs must be converted.

5.3 Common implementation mistakes

Mistake 1 — Wrong loop order

The k loop must be outermost. If you write for i … for j … for k …, the value D[i][j] is finalised before the paths it depends on are ready. On our example graph, this wrong order gives D[A][B] = 7 instead of the correct 3. (We verified this by running both versions.)

Mistake 2 — Using 9999 (or similar) as “infinity”

With a fake infinity like 9999 and a negative edge, 9999 + (−2) = 9997 < 9999, so the algorithm invents paths that do not exist. In Python use float('inf') (∞ + any finite number is still ∞). In C/Java, add a guard: only relax if D[i][k] != INF and D[k][j] != INF — this also prevents integer overflow.

Mistake 3 — Diagonal not set to 0

If D[i][i] starts as ∞, many updates through k = i break, and negative-cycle detection no longer works.

Mistake 4 — Wrong path update

With the next (successor) matrix, the update is next[i][j] = next[i][k], not next[i][j] = k. Using k would skip the vertices between i and k.

Mistake 5 — Trusting distances after a negative cycle

Always check the diagonal before using the result. Path reconstruction can even loop forever if a negative cycle exists.

5.4 Related algorithm: Warshall's transitive closure

If we only care whether a path exists (not its length), replace numbers with 1/0 (true/false), min with OR, and + with AND:

R[i][j] = R[i][j] OR ( R[i][k] AND R[k][j] )

The result R is the reachability matrix (transitive closure). Same Θ(V³) time. See Tab 4 in Section 6.

5.5 Important examination points

Remember for exams
  • Floyd–Warshall solves the All-Pairs Shortest Path (APSP) problem using dynamic programming.
  • Recurrence: Dk[i][j] = min(Dk−1[i][j], Dk−1[i][k] + Dk−1[k][j]).
  • Time Θ(V³) in all cases; space Θ(V²).
  • Works with negative edges, not with negative cycles. Negative cycle ⇔ negative diagonal entry.
  • The k loop must be outermost. In phase k, row k and column k do not change (no negative cycle ⇒ D[k][k] = 0).
  • For n vertices you draw n + 1 matrices: D(0) … D(n).
  • Warshall's algorithm (transitive closure) is the Boolean version.

floyd_warshall.py
# Floyd–Warshall Algorithm: All-Pairs Shortest Paths
# Prints the distance matrix after every phase k (D0, D1, ... Dn).

INF = float('inf')          # "no edge" / "no path known yet"


def print_matrix(D, names, title):
    print(title)
    print("     " + "".join(f"{v:>5}" for v in names))
    for i, row in enumerate(D):
        cells = "".join(f"{('∞' if x == INF else x):>5}" for x in row)
        print(f"{names[i]:>5}" + cells)
    print()


def floyd_warshall(n, edges, names):
    # Step 1: build the initial distance matrix D0
    D = [[0 if i == j else INF for j in range(n)] for i in range(n)]
    for u, v, w in edges:
        D[u][v] = min(D[u][v], w)        # keep the lightest parallel edge
    print_matrix(D, names, "D0 (direct edges only)")

    # Step 2: allow vertex k as an intermediate vertex, one k at a time
    for k in range(n):                   # k MUST be the outermost loop
        for i in range(n):
            for j in range(n):
                if D[i][k] + D[k][j] < D[i][j]:
                    D[i][j] = D[i][k] + D[k][j]
        print_matrix(D, names, f"D{k + 1} (intermediate vertices allowed: "
                               f"{', '.join(names[:k + 1])})")
    return D


if __name__ == "__main__":
    names = ["A", "B", "C", "D"]
    # (from, to, weight)  — directed graph with one negative edge
    edges = [(0, 1, 7), (0, 3, 1), (1, 0, -1),
             (2, 0, 3), (2, 1, 1), (3, 2, 1)]
    floyd_warshall(len(names), edges, names)

How the code works

  • INF = float('inf') represents “no edge”. Python handles inf + x = inf correctly, even for negative x.
  • Initialisation builds D(0): 0 on the diagonal, ∞ elsewhere, then fills in the edge weights. min() keeps the lightest of any parallel edges.
  • The triple loop is the algorithm. The k loop is outermost, as required.
  • The matrix is printed after each phase so you can compare it with the worked example in Section 3.4 — they match exactly.
fw_path.py
# Floyd–Warshall with Path Reconstruction
# nxt[i][j] stores the NEXT vertex to visit after i on the shortest path i -> j.

INF = float('inf')


def floyd_warshall_with_path(n, edges):
    D = [[0 if i == j else INF for j in range(n)] for i in range(n)]
    nxt = [[j if i == j else None for j in range(n)] for i in range(n)]

    for u, v, w in edges:
        if w < D[u][v]:
            D[u][v] = w
            nxt[u][v] = v            # direct edge: next hop is v itself

    for k in range(n):
        for i in range(n):
            for j in range(n):
                if D[i][k] + D[k][j] < D[i][j]:
                    D[i][j] = D[i][k] + D[k][j]
                    nxt[i][j] = nxt[i][k]   # first go towards k
    return D, nxt


def get_path(nxt, u, v):
    """Return the list of vertices on the shortest path u -> v."""
    if nxt[u][v] is None:
        return []                     # v is unreachable from u
    path = [u]
    while u != v:
        u = nxt[u][v]
        path.append(u)
    return path


if __name__ == "__main__":
    names = ["A", "B", "C", "D"]
    edges = [(0, 1, 7), (0, 3, 1), (1, 0, -1),
             (2, 0, 3), (2, 1, 1), (3, 2, 1)]
    n = len(names)
    D, nxt = floyd_warshall_with_path(n, edges)

    for s in range(n):
        for t in range(n):
            if s != t:
                p = get_path(nxt, s, t)
                route = " -> ".join(names[x] for x in p) if p else "no path"
                print(f"{names[s]} to {names[t]}: cost = {D[s][t]:>2}   path: {route}")

How the code works

  • nxt[i][j] is the first step on the best known path from i to j. For a direct edge, it is simply j.
  • When the path through k is better, the first step from i towards j becomes the first step from i towards k: nxt[i][j] = nxt[i][k].
  • get_path follows the nxt pointers from u until it reaches v. It returns an empty list when v is unreachable.
  • Notice A → B costs 3 using the route A → D → C → B, not the direct edge of weight 7.

# Detecting a Negative-Weight Cycle with Floyd–Warshall
# After the algorithm, if D[v][v] < 0 for any v, then v lies on
# (or can reach and return through) a negative cycle.

INF = float('inf')


def floyd_warshall(n, edges):
    D = [[0 if i == j else INF for j in range(n)] for i in range(n)]
    for u, v, w in edges:
        D[u][v] = min(D[u][v], w)
    for k in range(n):
        for i in range(n):
            for j in range(n):
                if D[i][k] + D[k][j] < D[i][j]:
                    D[i][j] = D[i][k] + D[k][j]
    return D


def has_negative_cycle(D):
    return any(D[v][v] < 0 for v in range(len(D)))


if __name__ == "__main__":
    names = ["P", "Q", "R"]
    # Cycle P -> Q -> R -> P has total weight 2 + 3 + (-6) = -1
    edges = [(0, 1, 2), (1, 2, 3), (2, 0, -6)]
    D = floyd_warshall(3, edges)

    print("Diagonal entries:", {names[v]: D[v][v] for v in range(3)})
    if has_negative_cycle(D):
        bad = [names[v] for v in range(3) if D[v][v] < 0]
        print("Negative cycle detected! Vertices affected:", ", ".join(bad))
        print("Shortest distances are NOT defined for this graph.")
    else:
        print("No negative cycle. Distances are valid.")

Diagonal entries: {'P': -1, 'Q': -1, 'R': -2}
Negative cycle detected! Vertices affected: P, Q, R
Shortest distances are NOT defined for this graph.

How the code works

  • The cycle P → Q → R → P has total weight 2 + 3 − 6 = −1.
  • After the algorithm, a vertex on a negative cycle can “reach itself” with negative cost, so its diagonal entry becomes negative.
  • R shows −2 because the algorithm keeps updating with already-improved values; the exact negative numbers are meaningless — only the sign matters.
warshall_closure.py
# Warshall's Algorithm: Transitive Closure (Reachability Matrix)
# R[i][j] = 1 if there is ANY path from i to j, otherwise 0.
# Same triple loop as Floyd–Warshall, but uses OR / AND instead of min / +.


def warshall(adj):
    n = len(adj)
    R = [row[:] for row in adj]           # copy the adjacency matrix
    for i in range(n):
        R[i][i] = 1                       # every vertex reaches itself
    for k in range(n):
        for i in range(n):
            for j in range(n):
                R[i][j] = R[i][j] or (R[i][k] and R[k][j])
    return R


if __name__ == "__main__":
    names = ["1", "2", "3", "4"]
    #        1  2  3  4
    adj = [[0, 1, 0, 0],    # 1 -> 2
           [0, 0, 1, 0],    # 2 -> 3
           [0, 0, 0, 0],    # 3 has no outgoing edge
           [1, 0, 0, 0]]    # 4 -> 1
    R = warshall(adj)
    print("Reachability matrix:")
    print("   " + " ".join(names))
    for i in range(4):
        print(names[i] + "  " + " ".join(str(int(x)) for x in R[i]))
Output
Reachability matrix:
   1 2 3 4
1  1 1 1 0
2  0 1 1 0
3  0 0 1 0
4  1 1 1 1

How the code works

  • Same three loops, but with Boolean operations: “i reaches j” if it already did, or if i reaches k and k reaches j.
  • Vertex 4 reaches everything (4 → 1 → 2 → 3), while vertex 3 reaches only itself.
  • Here we set R[i][i] = 1 (reflexive closure). Some textbooks leave the diagonal as computed; check your syllabus convention.

7.1 Conceptual questions

Q1. What is the all-pairs shortest path problem? Name an algorithm that solves it.
Find the shortest distance δ(u, v) for every ordered pair of vertices (u, v) in a weighted graph. Floyd–Warshall solves it in Θ(V³) time.
Q2. Why is Floyd–Warshall called a dynamic programming algorithm?
It solves the problem using smaller overlapping subproblems — “shortest path from i to j using only vertices 1…k” — and builds the answer for k from the stored answers for k − 1. Shortest paths have optimal substructure, which makes this valid.
Q3. Why must the k loop be the outermost loop?
D(k) must be built entirely from D(k−1). With k outermost, every D[i][k] and D[k][j] is already final for “intermediate vertices 1…k−1” before any cell is updated through k. If k is innermost, D[i][j] is fixed before the paths it depends on are computed, giving wrong answers.
Q4. Can Floyd–Warshall handle negative edges? Negative cycles?
Negative edges: yes. Negative cycles: no — shortest paths are undefined, but the algorithm can detect them (some D[v][v] < 0 at the end).
Q5. When would you choose Dijkstra over Floyd–Warshall?
When all weights are non-negative and you need distances from one (or a few) sources, especially in a large sparse graph. Dijkstra with a heap takes O((V + E) log V) per source, much less than Θ(V³).
