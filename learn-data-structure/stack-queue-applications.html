Why Stacks and Queues Matter

Stacks and queues are simple structures, but a large part of everyday software is built on them. The choice between them comes down to one question:

Must the latest item be handled first?

Use a stack (LIFO). Examples: the operator that appeared most recently, the edit you made last, the function that was called last.

Must the oldest item be handled first?

Use a queue (FIFO). Examples: the job that arrived first, the oldest print request, the first customer in line.

The three applications in this post

Core Concepts

A. Expression notations

An arithmetic expression is made of operands (values or variables such as 5 or A) and operators (+, −, *, /, ^). The position of the operator gives three notations:

NotationOperator positionA + B(A + B) * CA + B * C
InfixBetween operandsA + B(A + B) * CA + B * C
Prefix (Polish)Before operands+ A B* + A B C+ A * B C
Postfix (Reverse Polish)After operandsA B +A B + C *A B C * +
Why do computers prefer postfix?
  • No parentheses needed: the order of operators already says what is computed first.
  • No precedence rules needed during evaluation: just apply each operator when you reach it.
  • One left-to-right scan with a stack evaluates it in O(n) time.

Infix is easy for humans but needs precedence rules and brackets. So a compiler typically converts infix to postfix (with an operator stack) and then evaluates postfix (with an operand stack).

Precedence and associativity

OperatorPrecedenceAssociativityMeaning
^3 (highest)Right to left2^3^2 = 2^(3^2) = 512
* / %2Left to right8/4/2 = (8/4)/2 = 1
+ −1 (lowest)Left to right9−4−2 = (9−4)−2 = 3

Associativity decides the order when two operators have the same precedence. This is why the conversion algorithm pops an operator of equal precedence for left-associative operators but not for ^.

Converting by hand (quick check method)

  1. Fully parenthesise according to precedence: A + B * C → (A + (B * C)).
  2. For postfix, move each operator to just before its closing bracket: (A (B C *) +) → A B C * +.
  3. For prefix, move each operator to just after its opening bracket: (+ A (* B C)) → + A * B C.

This is handy for checking answers. The stack algorithm in Section 3 does the same job mechanically.

B. The undo / redo model

  • Every change (typing a word, deleting, formatting) is stored as an action record describing what was done, so it can be reversed.
  • Undo stack: actions already performed. Undo pops the most recent one and reverses it.
  • Redo stack: actions that were undone. Redo pops the most recently undone one and applies it again.
  • Doing a new action clears the redo stack, because the old "future" no longer fits the document.
  • Real editors limit history (for example, the last 100 actions). A deque is ideal: push at one end and drop the oldest from the other end.

C. Job scheduling terms

TermMeaning
Job / processA unit of work waiting for a resource (CPU, printer).
Arrival timeWhen the job enters the ready queue.
Burst timeCPU time the job needs.
Finish (completion) timeWhen the job completes.
Turnaround time (TAT)Finish − arrival: total time spent in the system.
Waiting time (WT)TAT − burst: time spent waiting in the queue.
Time quantumMaximum time a job runs before being sent to the back of the queue (round robin).
Non-preemptive / preemptiveFCFS runs each job to completion (non-preemptive). Round robin interrupts jobs after each quantum (preemptive).

FCFS: First Come, First Served

A plain FIFO queue. Simple and fair by arrival, but one long job makes everyone behind it wait (convoy effect).

Round Robin (RR)

A circular queue with a time quantum. Every job gets regular turns, giving good response time for interactive systems.

1. Infix to postfix conversion O(n)

Operands go straight to the output. Operators wait on a stack until an operator of lower precedence (or a closing bracket) arrives, which tells us the waiting operator's operands are complete.

ALGORITHM INFIX_TO_POSTFIX(infix)
1. S ← empty stack;  postfix ← empty
2. for each token t of infix, from left to right:
3.     if t is an operand: append t to postfix
4.     else if t = "(": PUSH(S, t)
5.     else if t = ")":
6.         while TOP(S) ≠ "(": append POP(S) to postfix
7.         POP(S)    // discard the "("
8.     else:    // t is an operator
9.         while S not empty and TOP(S) ≠ "(" and POPS_BEFORE(TOP(S), t):
10.             append POP(S) to postfix
11.         PUSH(S, t)
12. while S not empty: append POP(S) to postfix
13. return postfix
POPS_BEFORE(top, t)

The operator on top of the stack is popped before pushing t if prec(top) > prec(t), or if prec(top) = prec(t) and t is left-associative. For right-associative ^, an equal-precedence ^ stays on the stack.

2. Evaluating a postfix expression O(n)

Scan left to right. Push operands. When an operator appears, its two operands are the top two stack values: pop the right operand first, then the left, compute, and push the result.

ALGORITHM EVALUATE_POSTFIX(postfix)
1. S ← empty stack
2. for each token t of postfix, from left to right:
3.     if t is an operand: PUSH(S, t)
4.     else:    // t is an operator
5.         B ← POP(S)    // right operand comes out first
6.         A ← POP(S)    // left operand
7.         PUSH(S, A t B)
8. return POP(S)    // exactly one value must remain
Worked example: 5 6 2 + * 12 4 / − (from 5*(6+2)−12/4)

3. Evaluating a prefix expression O(n)

Same idea, but scan right to left. Now the first value popped is the left operand.

1. S ← empty stack
2. for each token t of prefix, from RIGHT to LEFT:
3.     if t is an operand: PUSH(S, t)
4.     else:    // t is an operator
5.         A ← POP(S)    // left operand comes out first
6.         B ← POP(S)    // right operand
7.         PUSH(S, A t B)

Undo / redo with two stacks O(1) per operation

DO_ACTION records every change. UNDO and REDO simply move the top action from one stack to the other, reversing or re-applying it on the way.

ALGORITHM DO_ACTION(a)
1. apply action a to the document
2. PUSH(UndoStack, a)
3. make RedoStack empty    // a new action cancels the redo history
ALGORITHM UNDO()
1. if UndoStack is empty: print "Nothing to undo"; exit
2. a ← POP(UndoStack)    // most recent action
3. reverse action a on the document
4. PUSH(RedoStack, a)
ALGORITHM REDO()
1. if RedoStack is empty: print "Nothing to redo"; exit
2. a ← POP(RedoStack)
3. apply action a to the document again
4. PUSH(UndoStack, a)

FCFS scheduling with a queue O(n) after sorting

Jobs enter a FIFO queue in arrival order. The CPU always takes the job at the front and runs it to completion. If the next job hasn't arrived yet, the CPU is idle until it does.

ALGORITHM FCFS(jobs)
1. Q ← empty queue;  ENQUEUE every job in order of arrival
2. time ← 0
3. while Q not empty:
4.     j ← DEQUEUE(Q)    // oldest job
5.     if time < j.arrival: time ← j.arrival    // CPU idle
6.     j.start ← time;  time ← time + j.burst
7.     j.finish ← time
8. for each job: TAT ← finish − arrival;  WT ← TAT − burst

Round robin scheduling with a circular queue

The CPU takes the front job and runs it for at most one time quantum q. Jobs that arrived during that slice join the rear first; then the interrupted job, if unfinished, joins the rear behind them.

ALGORITHM ROUND_ROBIN(jobs, q)
1. Q ← empty queue;  time ← 0;  ENQUEUE jobs with arrival ≤ time
2. while Q not empty or some job has not arrived:
3.     if Q empty: time ← next arrival; ENQUEUE arrived jobs    // idle
4.     j ← DEQUEUE(Q)
5.     run ← min(q, j.remaining);  time ← time + run
6.     j.remaining ← j.remaining − run
7.     ENQUEUE jobs that arrived up to time    // new arrivals first
8.     if j.remaining > 0: ENQUEUE(Q, j)    // back to the rear
9.     else: j.finish ← time
10. for each job: TAT ← finish − arrival;  WT ← TAT − burst

Worked example: J1(0, 5), J2(1, 3), J3(2, 8), J4(3, 2)

More Applications, Advantages & Disadvantages

More applications at a glance

Stacks

Function calls and recursion (call stack) · bracket and tag matching · browser back button · backtracking (mazes, Sudoku, N-Queens) · depth-first search · string reversal · decimal-to-binary conversion · syntax parsing in compilers.

Queues

CPU and disk scheduling · printer spooling · breadth-first search · keyboard and I/O buffers · network packet queues · call-centre systems · message queues between services · streaming media buffers.

Advantages

✔ Postfix evaluation is fast and simple

One scan, one stack, O(n), with no brackets or precedence checks at evaluation time.

✔ Conversion is mechanical

The infix-to-postfix algorithm handles any depth of brackets and any mix of operators.

✔ Undo/redo in O(1)

Two stacks give instant undo and redo, and naturally preserve the correct order.

✔ Undo history is easy to limit

A deque can keep only the last k actions by dropping the oldest from the other end.

✔ Queues make scheduling fair

FCFS serves in arrival order; RR guarantees every job a regular turn.

✔ Queues decouple producers and consumers

A spooler accepts jobs instantly even while the printer is busy.

Disadvantages and limitations

✘ Postfix/prefix are hard to read

Humans write infix, so a conversion step is always needed.

✘ Basic algorithm skips unary minus

Expressions like −5 + 3 or functions like sin(x) need extra handling.

✘ Undo history costs memory

Every stored action uses space; large documents may need snapshots or limits.

✘ Linear undo only

Two stacks can only undo in strict reverse order; you can't undo an older action alone.

✘ FCFS convoy effect

Short jobs can wait a long time behind one long job.

✘ RR overhead

A small quantum causes frequent context switches; a large one makes RR behave like FCFS.

Common mistakes

Watch out
  • Popping operands in the wrong order in postfix evaluation: the first pop is the right operand. 8 2 − is 8 − 2 = 6, not −6.
  • In prefix evaluation the order flips: the first pop is the left operand.
  • Treating ^ as left-associative: 2^3^2 is 512, not 64.
  • Pushing ")" onto the stack: a closing bracket is never pushed; it triggers popping until "(".
  • Forgetting to empty the stack at the end of conversion: remaining operators must be appended.
  • Not clearing the redo stack after a new action: redo would then re-apply a change that no longer makes sense.
  • Using a stack for scheduling: the newest job would always run first, so old jobs could wait forever (starvation).
  • Waiting time = finish − burst is only correct when arrival is 0. In general WT = finish − arrival − burst.

Important examination points

Remember for exams
  • Infix → postfix uses an operator stack; postfix evaluation uses an operand stack.
  • Precedence: ^ > * / % > + −; ^ is right-associative.
  • Postfix is evaluated left to right (pop B then A); prefix right to left (pop A then B).
  • Always show the symbol / stack / output table when converting: examiners award marks for it.
  • Undo/redo = two stacks; a new action clears the redo stack.
  • FCFS = simple queue, non-preemptive; RR = circular queue, preemptive, time quantum.
  • TAT = finish − arrival; WT = TAT − burst.

# Program 1: Infix to postfix conversion and postfix evaluation using a stack

PREC = {'+': 1, '-': 1, '*': 2, '/': 2, '%': 2, '^': 3}
RIGHT_ASSOC = {'^'}                     # a^b^c means a^(b^c)

def tokenize(expr):
    """Split an infix string into numbers, single-letter names, operators and brackets."""
    tokens, i = [], 0
    while i < len(expr):
        ch = expr[i]
        if ch.isspace():
            i += 1
        elif ch.isdigit():
            j = i
            while j < len(expr) and expr[j].isdigit():
                j += 1
            tokens.append(expr[i:j]); i = j
        else:
            tokens.append(ch); i += 1
    return tokens

def infix_to_postfix(expr, show=False):
    stack, output = [], []
    if show:
        print(f"{'Symbol':8}{'Stack':14}Postfix")
    for t in tokenize(expr):
        if t.isalnum():                          # operand
            output.append(t)
        elif t == '(':
            stack.append(t)
        elif t == ')':
            while stack[-1] != '(':
                output.append(stack.pop())
            stack.pop()                          # discard '('
        else:                                    # operator
            while (stack and stack[-1] != '(' and
                   (PREC[stack[-1]] > PREC[t] or
                    (PREC[stack[-1]] == PREC[t] and t not in RIGHT_ASSOC))):
                output.append(stack.pop())
            stack.append(t)
        if show:
            print(f"{t:8}{''.join(stack):14}{' '.join(output)}")
    while stack:
        output.append(stack.pop())
    if show:
        print(f"{'(end)':8}{'':14}{' '.join(output)}")
    return ' '.join(output)

def apply(op, a, b):
    if op == '+': return a + b
    if op == '-': return a - b
    if op == '*': return a * b
    if op == '/':
        r = a / b
        return int(r) if r == int(r) else r     # keep whole results as integers
    if op == '%': return a % b
    if op == '^': return a ** b

def evaluate_postfix(postfix, show=False):
    stack = []
    for t in postfix.split():
        if t.isdigit():
            stack.append(int(t))                 # operand: push
        else:
            b = stack.pop()                      # right operand comes out FIRST
            a = stack.pop()
            r = apply(t, a, b)
            stack.append(r)
            if show:
                print(f"  {a} {t} {b} = {r:g}   stack: {stack}")
    return stack.pop()


print("Infix:  A+(B*C-(D/E^F)*G)*H")
print("Postfix:", infix_to_postfix("A+(B*C-(D/E^F)*G)*H", show=True))
print()
for e in ["a+b*c", "(a+b)*c", "a-b+c", "a^b^c", "3+4*2/(1-5)^2"]:
    print(f"{e:16} -> {infix_to_postfix(e)}")
print()
pf = infix_to_postfix("5*(6+2)-12/4")
print("5*(6+2)-12/4  ->  postfix:", pf)
result = evaluate_postfix(pf, show=True)
print("Result =", f"{result:g}")

            tokens.append(expr[i:j]); i = j
        else:
            tokens.append(ch); i += 1
    return tokens

def apply(op, a, b):
    if op == '+': return a + b
    if op == '-': return a - b
    if op == '*': return a * b
    if op == '/':
        r = a / b
        return int(r) if r == int(r) else r     # keep whole results as integers
    if op == '%': return a % b
    if op == '^': return a ** b


def infix_to_prefix(expr):
    """Reverse the infix, swap brackets, convert (with equal precedence popped only
    for right-associative ^), then reverse the result."""
    tokens = tokenize(expr)[::-1]
    tokens = ['(' if t == ')' else ')' if t == '(' else t for t in tokens]
    stack, output = [], []
    for t in tokens:
        if t.isalnum():
            output.append(t)
        elif t == '(':
            stack.append(t)
        elif t == ')':
            while stack[-1] != '(':
                output.append(stack.pop())
            stack.pop()
        else:
            # In the reversed scan, pop equal precedence only for right-associative ^
            while (stack and stack[-1] != '(' and
                   (PREC[stack[-1]] > PREC[t] or
                    (PREC[stack[-1]] == PREC[t] and t in RIGHT_ASSOC))):
                output.append(stack.pop())
            stack.append(t)
    while stack:
        output.append(stack.pop())
    return ' '.join(output[::-1])

def evaluate_prefix(prefix, show=False):
    stack = []
    for t in reversed(prefix.split()):           # scan RIGHT to LEFT
        if t.isdigit():
            stack.append(int(t))
        else:
            a = stack.pop()                      # LEFT operand comes out first
            b = stack.pop()
            r = apply(t, a, b)
            stack.append(r)
            if show:
                print(f"  {a} {t} {b} = {r:g}   stack: {stack}")
    return stack.pop()


for e in ["a+b*c", "(a+b)*c", "a-b+c", "a^b^c", "A+(B*C-(D/E^F)*G)*H"]:
    print(f"{e:22} prefix: {infix_to_prefix(e)}")
print()
pre = infix_to_prefix("5*(6+2)-12/4")
print("5*(6+2)-12/4  ->  prefix:", pre)

# Program 3: Undo / Redo in a simple text editor using TWO stacks

class TextEditor:
    def __init__(self):
        self.words = []             # the document, as a list of words
        self.undo_stack = []        # actions that can be undone (latest on top)
        self.redo_stack = []        # actions that were undone and can be redone

    # --- applying and reversing a single action ---
    def _apply(self, action):
        kind, word = action
        if kind == "type":
            self.words.append(word)
        else:                       # "delete": remove the last word
            self.words.pop()

    def _reverse(self, action):
        kind, word = action
        if kind == "type":
            self.words.pop()
        else:
            self.words.append(word)

    # --- user commands ---
    def type_word(self, word):
        self.do(("type", word))

    def delete_last(self):
        if not self.words:
            print("  (nothing to delete)"); return
        self.do(("delete", self.words[-1]))

    def do(self, action):
        self._apply(action)
        self.undo_stack.append(action)      # remember it for undo
        self.redo_stack.clear()             # a NEW action invalidates the redo history

    def undo(self):
        if not self.undo_stack:
            print("  Nothing to undo"); return
        action = self.undo_stack.pop()      # most recent action first (LIFO)
        self._reverse(action)
        self.redo_stack.append(action)

    def redo(self):
        if not self.redo_stack:
            print("  Nothing to redo"); return
        action = self.redo_stack.pop()
        self._apply(action)
        self.undo_stack.append(action)

    def show(self, label):
        fmt = lambda st: "[" + ", ".join(f"{k} '{w}'" for k, w in st) + "]"
        print(f"{label}:")
        print(f"   document   : {' '.join(self.words)!r}")
        print(f"   undo stack : {fmt(self.undo_stack)}   <- top is last")
        print(f"   redo stack : {fmt(self.redo_stack)}")

# Program 4: Job scheduling with queues
#  (a) FCFS (First Come, First Served): a simple FIFO queue
#  (b) Round Robin: a circular ready queue with a time quantum
#  (c) Printer spooler: jobs printed in the order they were submitted
from collections import deque

JOBS = [("J1", 0, 5), ("J2", 1, 3), ("J3", 2, 8), ("J4", 3, 2)]   # (name, arrival, burst)

def report(title, finish, gantt):
    print(title)
    print("  Gantt:", " ".join(gantt))
    tw = tt = 0
    for name, arr, burst in JOBS:
        tat = finish[name] - arr                # turnaround = finish - arrival
        wt = tat - burst                        # waiting = turnaround - burst
        tw += wt; tt += tat
        print(f"  {name}: arrival={arr} burst={burst} finish={finish[name]:2} TAT={tat:2} WT={wt:2}")
    print(f"  Average TAT = {tt/len(JOBS):.2f}, Average WT = {tw/len(JOBS):.2f}\n")

def fcfs(jobs):
    q = deque(sorted(jobs, key=lambda j: j[1]))   # queue in arrival order
    time, finish, gantt = 0, {}, []
    while q:
        name, arr, burst = q.popleft()            # dequeue the oldest job
        if time < arr:
            gantt.append(f"idle[{time}-{arr}]")
            time = arr                            # CPU waits for the job to arrive
        gantt.append(f"{name}[{time}-{time+burst}]")
        time += burst
        finish[name] = time
    return finish, gantt

def round_robin(jobs, quantum):
    pending = deque(sorted(jobs, key=lambda j: j[1]))  # not yet arrived
    remaining = {n: b for n, a, b in jobs}
    ready, time, finish, gantt = deque(), 0, {}, []

    def admit(upto):
        while pending and pending[0][1] <= upto:
            ready.append(pending.popleft()[0])     # newly arrived jobs join the rear

    admit(time)
    while ready or pending:
        if not ready:                              # CPU idle until the next arrival
            gantt.append(f"idle[{time}-{pending[0][1]}]")
            time = pending[0][1]
            admit(time)
        job = ready.popleft()
        run = min(quantum, remaining[job])
        gantt.append(f"{job}[{time}-{time+run}]")
        time += run
        remaining[job] -= run
        admit(time)                                # arrivals during this slice go first
        if remaining[job] > 0:
            ready.append(job)                      # unfinished job goes to the rear
        else:
            finish[job] = time
    return finish, gantt

report("FCFS scheduling:", *fcfs(JOBS))
report("Round Robin (quantum = 2):", *round_robin(JOBS, 2))

spool = deque()
for doc in ["report.pdf", "photo.png", "notes.txt"]:
    spool.append(doc); print("Submitted:", doc)
while spool:
    print("Printing :", spool.popleft())

Practice & Assessment

A. Conceptual questions

1. Why is postfix notation preferred for evaluation by computers?

It needs no brackets and no precedence rules: a single left-to-right scan with a stack evaluates it in O(n) time.

2. Why does the infix-to-postfix algorithm use a stack for operators?

An operator must wait until its right operand is complete. The most recently seen operator is the first that can be completed, which is LIFO behaviour.

3. Explain how undo and redo work with two stacks. Why is the redo stack cleared after a new action?

Actions are pushed on the undo stack. Undo pops one, reverses it and pushes it on the redo stack; redo does the opposite. After a new action the undone actions no longer apply to the changed document, so the redo stack is cleared.

4. Compare FCFS and round robin scheduling.

FCFS uses a simple queue and runs each job to completion (non-preemptive), which can cause the convoy effect. RR uses a circular queue and a time quantum (preemptive), giving better response time at the cost of more context switches.

5. Why would a stack be a bad choice for job scheduling?

A stack always serves the newest job first. Under a steady stream of new jobs, older jobs could wait forever (starvation), which is unfair.
