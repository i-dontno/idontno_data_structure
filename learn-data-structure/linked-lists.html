Introduction to Linked Lists

Definition

A linked list is a linear data structure made of a sequence of nodes. Each node stores data and a link (pointer) to the next node. The order of elements is decided by these links, not by their physical position in memory.

Think of a treasure hunt: each clue (node) contains a message (data) and tells you where the next clue is hidden (link). The clues can be anywhere in the park; what keeps them in order is that each one points to the next. You only need to know where the first clue is: that is the head of the list.

Figure 1: A singly linked list of 4 nodes. Each box is [data | next]. The numbers under the nodes are memory addresses: notice they are not consecutive. The last node's next field is NULL (shown as a slash).

Why do we need linked lists?

Arrays are excellent for random access, but they have three weaknesses that linked lists solve:

Problem with arraysHow a linked list solves it
Fixed size: capacity must be decided in advance.Nodes are created one at a time while the program runs, so the list grows and shrinks freely (dynamic size).
Costly insertion/deletion: elements must be shifted (O(n)).Only a few pointers are changed; no data moves. Inserting at the beginning is O(1).
Needs one contiguous block of memory.Nodes can be scattered anywhere; each just stores the address of the next.

Why are linked lists important?

  • They are the classic example of a dynamic data structure and teach how pointers/references work.
  • Stacks, queues, graphs (adjacency lists), hash tables (chaining) and polynomial arithmetic are commonly built using linked lists.
  • Operating systems use them to manage free memory blocks, processes and file blocks.

Core Concepts & Memory Representation

Terminology

TermMeaning
NodeThe building block of a linked list. It contains a data field and one or more link fields.
Data (INFO) fieldStores the actual value, e.g. 25.
Link (NEXT) field / pointerStores the address of the next node. In Python it holds a reference to the next node object.
PREV fieldIn a doubly linked list, stores the address of the previous node.
Head (START)A pointer variable that holds the address of the first node. Losing the head means losing the whole list.
Tail / Last nodeThe final node. Its next is NULL (or head, in a circular list).
NULL (None)A special value meaning "points to nothing". It marks the end of a linear list.
Empty listA list with no nodes: head = NULL.
Self-referential structureA structure that contains a pointer to a structure of the same type. A node is self-referential.

Node structure

Singly (SLL)

[ data | next ]

class Node:
    def __init__(self, data):
        self.data = data
        self.next = None
struct node {
    int data;
    struct node *next;
};

Doubly (DLL)

[ prev | data | next ]

class DNode:
    def __init__(self, data):
        self.prev = None
        self.data = data
        self.next = None
struct dnode {
    struct dnode *prev;
    int data;
    struct dnode *next;
};

Circular (CLL)

Same node as SLL; only the last link changes.

# same Node class as SLL
# last.next = head
# (instead of None)
struct node {
    int data;
    struct node *next;
};  /* last->next = head */

Types of linked lists

1. Singly linked list (SLL)

Each node has one link, next. You can move only forward. The last node's next is NULL.

2. Doubly linked list (DLL)

Each node has two links: prev (to the previous node) and next (to the next node). You can move forward and backward. The first node's prev and the last node's next are NULL. Blue arrows are prev links.

3. Circular linked list (CLL)

A singly linked list where the last node points back to the first node instead of NULL. There is no "end": starting from any node you can reach every other node.

Also good to know

A circular doubly linked list combines both ideas: last.next = head and head.prev = last. Many syllabi only ask for its definition; the algorithms follow the same patterns shown in Section 3.

How linked lists live in memory

Unlike an array, nodes are not stored side by side. Each node is allocated separately from free memory (the heap) whenever it's needed, so nodes end up scattered. The next field stores the address of the following node, which is how the list keeps its order.

  • Creating a node: in C, malloc(sizeof(struct node)); in Python, Node(x). Textbooks call this GETNODE: take a node from the list of free memory, often called the AVAIL list (free-storage list).
  • Deleting a node: in C, free(ptr) returns the memory to AVAIL. In Python, the garbage collector frees a node once nothing refers to it.
  • Overflow: GETNODE fails because no free memory is left (AVAIL = NULL). Underflow: trying to delete from an empty list (head = NULL).
Exam note: two-array representation

Many textbooks also show a linked list stored in two parallel arrays, INFO[] and LINK[], with a variable START. LINK[k] holds the index of the next node, and 0 or −1 plays the role of NULL. It is the same idea: order comes from the link values, not from the positions.

Creating a linked list

A list is created by starting with an empty list (head = NULL) and inserting nodes one at a time, usually at the end:

ALGORITHM CREATE_LIST(values[1..k])
1. head ← NULL
2. for each x in values:
3.     INSERT_END(head, x)          // see Section 3
4. return head

Operations & Algorithms

Every operation on a linked list is about moving a pointer to the right place and then re-linking a few fields. The algorithms below use these conventions:

  • Positions are 1-based: position 1 is the first node. For insertion, valid positions are 1 … n + 1; for deletion, 1 … n (n = number of nodes).
  • GETNODE() allocates a new node; FREE(p) releases a node's memory.
  • temp is a pointer used to walk through the list. It never modifies the list by itself.
The golden rule of re-linking

When inserting, connect the new node to the rest of the list first (newNode.next ← temp.next), and only then make the previous node point to it (temp.next ← newNode). Doing it the other way around loses the address of the rest of the list.

Traversal & Search

Traversal O(n)

Start a pointer at head and follow next links until it becomes NULL, processing each node on the way. Never move head itself, or you lose the list.

ALGORITHM TRAVERSE_SLL(head)
1. temp ← head
2. while temp ≠ NULL:
3.     PROCESS(temp.data)
4.     temp ← temp.next
5. exit

Search O(n)

Linked lists have no indices, so searching is always linear: compare each node's data with the key, counting positions. Binary search is not practical because you can't jump to the middle node in O(1).

ALGORITHM SEARCH_SLL(head, key)
1. temp ← head;  pos ← 1
2. while temp ≠ NULL:
3.     if temp.data = key: return pos    // found
4.     temp ← temp.next
5.     pos ← pos + 1
6. return −1    // not found

Example: searching 30 in 10 → 20 → 30 → 40 compares 10, 20, 30 and returns position 3.

Insertion

Insert at beginning O(1)

The new node points to the current first node, then head moves to the new node. Works for an empty list too (newNode.next becomes NULL).

ALGORITHM INSERT_BEGIN_SLL(head, item)
1. newNode ← GETNODE();  newNode.data ← item
2. newNode.next ← head
3. head ← newNode
4. exit

Insert at end O(n)

Walk temp to the last node (the one whose next is NULL), then attach the new node there. If the list is empty, the new node becomes the head.

ALGORITHM INSERT_END_SLL(head, item)
1. newNode ← GETNODE();  newNode.data ← item;  newNode.next ← NULL
2. if head = NULL: head ← newNode; exit
3. temp ← head
4. while temp.next ≠ NULL:    // find the last node
5.     temp ← temp.next
6. temp.next ← newNode
7. exit

Insert at a given position O(n)

Move temp to the node before the position (pos − 1), link the new node to temp's successor, then link temp to the new node.

ALGORITHM INSERT_POS_SLL(head, item, pos)
1. if pos < 1 or pos > n + 1: print "INVALID POSITION"; exit
2. if pos = 1: INSERT_BEGIN_SLL(head, item); exit
3. newNode ← GETNODE();  newNode.data ← item
4. temp ← head
5. repeat (pos − 2) times: temp ← temp.next  // node at pos − 1
6. newNode.next ← temp.next    // link to the rest FIRST
7. temp.next ← newNode
8. exit

Deletion

Delete at beginning O(1)

Save the first node in temp, move head to the second node, and free temp.

ALGORITHM DELETE_BEGIN_SLL(head)
1. if head = NULL: print "UNDERFLOW"; exit
2. temp ← head
3. head ← head.next
4. FREE(temp)
5. exit

Delete at end O(n)

In a singly list you can't step backwards, so you must stop at the second-last node (check temp.next.next) and set its next to NULL. A one-node list is a special case.

ALGORITHM DELETE_END_SLL(head)
1. if head = NULL: print "UNDERFLOW"; exit
2. if head.next = NULL: FREE(head); head ← NULL; exit
3. temp ← head
4. while temp.next.next ≠ NULL:    // stop at second-last node
5.     temp ← temp.next
6. last ← temp.next
7. temp.next ← NULL
8. FREE(last)

Delete at a given position O(n)

Move temp to the node before the target, make it skip over the target (temp.next ← target.next), then free the target.

1. if head = NULL: print "UNDERFLOW"; exit

6. target ← temp.next
7. temp.next ← target.next    // bypass target

What changes in a doubly linked list?

Every insertion or deletion must keep both directions correct. For each link you change in the forward direction, there is usually a matching prev link to fix. Always check whether the neighbour exists (≠ NULL) before touching its prev field.

Traversal & Search

Traversal (forward and backward) O(n)

Forward traversal follows next exactly like an SLL. Because each node also has prev, you can then walk backward from the last node to the first.

ALGORITHM TRAVERSE_DLL(head)
1. if head = NULL: print "EMPTY"; exit
2. temp ← head
3. while temp ≠ NULL:    // forward using next
4.     PROCESS(temp.data);  last ← temp
5.     temp ← temp.next
6. temp ← last
7. while temp ≠ NULL:    // backward using prev
8.     PROCESS(temp.data)
9.     temp ← temp.prev

Search O(n)

Identical to SLL search, following next links.

ALGORITHM SEARCH_DLL(head, key)
1. temp ← head;  pos ← 1
2. while temp ≠ NULL:
3.     if temp.data = key: return pos    // found
4.     temp ← temp.next
5.     pos ← pos + 1
6. return −1    // not found
Insertion

Insert at beginning O(1)

New node's next points to the old head; the old head's prev points back to the new node (if the list wasn't empty); head moves.

ALGORITHM INSERT_BEGIN_DLL(head, item)
1. newNode ← GETNODE();  newNode.data ← item;  newNode.prev ← NULL
2. newNode.next ← head
3. if head ≠ NULL: head.prev ← newNode
4. head ← newNode

Insert at end O(n)

Walk to the last node, set last.next = newNode and newNode.prev = last. (With an extra tail pointer this becomes O(1).)

ALGORITHM INSERT_END_DLL(head, item)
1. newNode ← GETNODE();  newNode.data ← item;  newNode.next ← NULL
2. if head = NULL: newNode.prev ← NULL; head ← newNode; exit
3. temp ← head
4. while temp.next ≠ NULL:    // find the last node
5.     temp ← temp.next
6. temp.next ← newNode
7. newNode.prev ← temp

Insert at a given position O(n)

Four links change when inserting between two nodes: newNode.next, newNode.prev, the successor's prev, and temp.next. Steps 6–8 must come before step 9, because step 9 overwrites temp.next.

ALGORITHM INSERT_POS_DLL(head, item, pos)
1. if pos < 1 or pos > n + 1: print "INVALID POSITION"; exit
2. if pos = 1: INSERT_BEGIN_DLL(head, item); exit
3. newNode ← GETNODE();  newNode.data ← item
4. temp ← head
5. repeat (pos − 2) times: temp ← temp.next  // node at pos − 1
6. newNode.next ← temp.next
7. newNode.prev ← temp
8. if temp.next ≠ NULL: temp.next.prev ← newNode
9. temp.next ← newNode

Deletion

Delete at beginning O(1)

Move head to the second node and set its prev to NULL (if it exists).

ALGORITHM DELETE_BEGIN_DLL(head)
1. if head = NULL: print "UNDERFLOW"; exit
2. temp ← head
3. head ← head.next
4. if head ≠ NULL: head.prev ← NULL
5. FREE(temp)

Delete at end O(n)

Walk to the last node. Thanks to its prev link, you don't need to stop one node early as in an SLL: just set temp.prev.next ← NULL.

ALGORITHM DELETE_END_DLL(head)
1. if head = NULL: print "UNDERFLOW"; exit
2. temp ← head
3. while temp.next ≠ NULL:    // find the last node
4.     temp ← temp.next
5. if temp.prev = NULL: head ← NULL    // it was the only node
6. else: temp.prev.next ← NULL
7. FREE(temp)

Delete at a given position O(n)

Here temp goes to the target node itself (pos − 1 moves), because prev gives access to its predecessor. Its neighbours are then linked to each other in both directions.

ALGORITHM DELETE_POS_DLL(head, pos)
1. if head = NULL: print "UNDERFLOW"; exit
2. if pos < 1 or pos > n: print "INVALID POSITION"; exit
3. if pos = 1: DELETE_BEGIN_DLL(head); exit
4. temp ← head
5. repeat (pos − 1) times: temp ← temp.next  // node AT pos
6. temp.prev.next ← temp.next
7. if temp.next ≠ NULL: temp.next.prev ← temp.prev
8. FREE(temp)

What changes in a circular linked list?

There is no NULL at the end, so loops stop when the pointer returns to head. A do … while loop is used so that the head node itself is processed. Any operation that changes the first node must also update the last node's next to keep the circle closed.

Traversal & Search

Traversal O(n)

A plain while temp ≠ head loop would stop immediately (temp starts at head), so the condition is tested after the first visit.

ALGORITHM TRAVERSE_CLL(head)
1. if head = NULL: print "EMPTY"; exit
2. temp ← head
3. do:
4.     PROCESS(temp.data)
5.     temp ← temp.next
6. while temp ≠ head    // back at the start: stop

Search O(n)

Compare each node until the key is found or the pointer comes full circle back to head.

ALGORITHM SEARCH_CLL(head, key)
1. if head = NULL: return −1
2. temp ← head;  pos ← 1
3. do:
4.     if temp.data = key: return pos    // found
5.     temp ← temp.next;  pos ← pos + 1
6. while temp ≠ head
7. return −1    // full circle: not found
Insertion

Insert at beginning O(n)*

Besides updating head, the last node must point to the new first node, so we first walk to the last node. A list with one node points to itself.

ALGORITHM INSERT_BEGIN_CLL(head, item)
1. newNode ← GETNODE();  newNode.data ← item
2. if head = NULL: newNode.next ← newNode; head ← newNode; exit
3. last ← head
4. while last.next ≠ head:    // find the last node
5.     last ← last.next
6. newNode.next ← head
7. last.next ← newNode
8. head ← newNode

* O(1) if the program keeps a pointer to the last node (a common design for circular lists).

Walk to the last node, attach the new node, and make the new node point back to head.

ALGORITHM INSERT_END_CLL(head, item)
1. newNode ← GETNODE();  newNode.data ← item
2. if head = NULL: newNode.next ← newNode; head ← newNode; exit
3. last ← head
4. while last.next ≠ head:    // find the last node
5.     last ← last.next
6. last.next ← newNode
7. newNode.next ← head    // close the circle

Complexity Analysis & Comparison

Time complexity (only a head pointer is kept)

OperationSinglyDoublyCircular (singly)Reason
Access k-th nodeO(k)O(k)O(k)Must follow k − 1 links; no random access
TraversalΘ(n)Θ(n)Θ(n)Every node visited once
SearchO(n)O(n)O(n)Linear; best case O(1) if key is first
Insert at beginningO(1)O(1)O(n)*CLL must also update the last node
Insert at endO(n)O(n)O(n)Walk to the last node
Insert at position posO(pos)O(pos)O(pos)Walk pos − 2 links, then O(1) re-linking
Delete at beginningO(1)O(1)O(n)*CLL must also update the last node
Delete at endO(n)O(n)O(n)Find the last / second-last node
Delete at position posO(pos)O(pos)O(pos)Walk to the position, then O(1) re-linking
Delete a node, given a pointer to itO(n)O(1)O(n)DLL already knows the predecessor via prev

* Becomes O(1) when the program also maintains a pointer to the last node.

Effect of a tail (last) pointer
  • Insert at end becomes O(1) for all three types.
  • Delete at end becomes O(1) only for a DLL (tail.prev gives the new last node). An SLL or CLL still needs O(n) to find the second-last node.
  • Circular lists are often stored with only a last pointer: head is simply last.next, so insertion at both ends is O(1).

Space complexity

  • A list of n nodes needs O(n) space.
  • Overhead per node: one pointer (SLL, CLL) or two pointers (DLL), in addition to the data. On a 64-bit machine each pointer is 8 bytes.
  • All the operations above use only a few pointer variables (temp, newNode, last): O(1) auxiliary space.

Applications, Advantages & Disadvantages

Applications of linked lists

1. Implementing stacks and queues

A stack pushes/pops at the head in O(1); a queue inserts at the tail and deletes at the head. No fixed capacity.

2. Polynomial representation

Each node stores a (coefficient, exponent) pair; polynomial addition merges two lists (see Program 4).

3. Sparse matrices

Store only the non-zero elements as nodes (row, column, value), saving huge amounts of memory.

4. Graphs: adjacency lists

Each vertex keeps a linked list of its neighbours, which is efficient for sparse graphs.

5. Hash tables: chaining

Keys that hash to the same slot are kept in a linked list at that slot.

6. Dynamic memory management

Operating systems keep free memory blocks in a linked "free list" (the AVAIL list).

7. Browser history, undo/redo (DLL)

Moving backward and forward between states needs both prev and next links.

8. Round-robin scheduling (CLL)

Processes sit in a circle; the scheduler keeps moving to the next one forever.

9. Music playlists & slideshows (CLL)

After the last item, playback continues from the first.

10. Large-number arithmetic

Numbers too big for built-in types are stored digit by digit in a list.

Advantages of linked lists

✔ Dynamic size

No need to know the size in advance; memory is allocated only when a node is created.

✔ Fast insertion/deletion

Once the position is known, only a few pointers change. No elements are shifted.

✔ No contiguous memory needed

Nodes can use any free blocks, so large lists can be built even with fragmented memory.

✔ No wasted capacity

Exactly n nodes exist for n elements.

✔ Flexible building block

Easily implements stacks, queues, graphs and other dynamic structures.

✔ Two-way / circular variants

DLL gives backward travel; CLL gives continuous cycling, with no special end case.

Disadvantages of linked lists

✘ No random access

To reach the k-th node you must follow k − 1 links: O(n). Binary search isn't practical.

✘ Extra memory for pointers

Every node stores 1 or 2 addresses, which can exceed the data size for small items.

✘ Poor cache performance

Scattered nodes mean the CPU cache helps far less than with arrays.

✘ Reverse traversal is hard (SLL)

A singly list can't move backwards without extra work or a doubly list.

✘ More complex code

Pointer mistakes cause lost nodes, memory leaks, crashes or infinite loops.

✘ Allocation overhead

Creating and freeing many small nodes is slower than working inside one array.

Single-node listDeleting it must set head = NULL. In SLL delete-at-end, temp.next.next would fail, so it is handled first.
Insert at position 1Head changes, so use the insert-at-beginning algorithm.
Insert at position n + 1Valid: same as insert at end. In a DLL, the "successor's prev" step is skipped because temp.next is NULL.
Delete at position nValid: same as delete at end. In a DLL, the "successor's prev" step is skipped.
Position < 1 or too largeReport INVALID POSITION before moving any pointer.
Circular list loopsMust stop when the pointer returns to head, not at NULL (there is no NULL).

Common mistakes

Watch out
  • Wrong order of re-linking: temp.next ← newNode before newNode.next ← temp.next makes the new node point to itself and loses the rest of the list (see Practice Q4 in Section 7).
  • Moving head while traversing: always use a separate pointer (temp).
  • Not checking for NULL before using temp.next or temp.next.prev: causes a crash (in Python, AttributeError: 'NoneType' object has no attribute ...).
  • Forgetting to update prev links in a DLL: forward traversal looks fine, but backward traversal is broken.
  • Using while temp ≠ NULL on a circular list: it never ends (infinite loop).
  • Not updating the last node in a CLL after inserting/deleting at the beginning: the circle points to a removed or wrong node.
  • Forgetting FREE in C after deleting a node: memory leak.

Important examination points

Remember for exams
  • A node is a self-referential structure: [data | link].
  • Linked list = sequential access; array = random access.
  • Insert/delete at beginning of SLL and DLL is O(1); anything that needs the last node is O(n) without a tail pointer.
  • For insertion/deletion at position pos in an SLL, stop at node pos − 1. In a DLL, deletion can stop at pos.
  • Inserting in the middle of a DLL changes 4 links; deleting from the middle changes 2 links.
  • Circular traversal uses a do-while loop that stops when temp == head.
  • Always write the UNDERFLOW check (head = NULL) and the INVALID POSITION check in algorithms.

# Program 1: Singly Linked List (SLL)
# Operations: traversal, search, insert & delete at beginning / end / position
# Positions are 1-based: position 1 is the first node.

class Node:
    def __init__(self, data):
        self.data = data      # the value stored in the node
        self.next = None      # link to the next node (None = NULL)


class SinglyLinkedList:
    def __init__(self):
        self.head = None      # empty list

    # ---------- traversal ----------
    def traverse(self):
        temp = self.head
        parts = []
        while temp is not None:
            parts.append(str(temp.data))
            temp = temp.next
        print("  " + " -> ".join(parts + ["NULL"]))

    def length(self):
        count, temp = 0, self.head
        while temp:
            count += 1
            temp = temp.next
        return count

    # ---------- search ----------
    def search(self, key):
        """Return the 1-based position of key, or -1 if not found."""
        temp, pos = self.head, 1
        while temp is not None:
            if temp.data == key:
                return pos
            temp = temp.next
            pos += 1
        return -1

    # ---------- insertion ----------
    def insert_at_beginning(self, data):
        new_node = Node(data)
        new_node.next = self.head     # 1. new node points to old first node
        self.head = new_node          # 2. head now points to new node

    def insert_at_end(self, data):
        new_node = Node(data)
        if self.head is None:         # empty list: new node becomes head
            self.head = new_node
            return
        temp = self.head
        while temp.next is not None:  # walk to the LAST node
            temp = temp.next
        temp.next = new_node

    def insert_at_position(self, data, pos):
        if pos < 1 or pos > self.length() + 1:
            raise IndexError(f"Invalid position {pos}")
        if pos == 1:
            self.insert_at_beginning(data)
            return
        temp = self.head
        for _ in range(pos - 2):      # stop at node (pos - 1)
            temp = temp.next
        new_node = Node(data)
        new_node.next = temp.next     # link new node to the rest FIRST
        temp.next = new_node          # then link previous node to new node

    # ---------- deletion ----------
    def delete_at_beginning(self):
        if self.head is None:
            raise IndexError("Underflow: list is empty")
        temp = self.head
        self.head = temp.next         # head moves to the second node
        return temp.data              # Python frees 'temp' automatically

    def delete_at_end(self):
        if self.head is None:
            raise IndexError("Underflow: list is empty")
        if self.head.next is None:    # only one node
            data = self.head.data
            self.head = None
            return data
        temp = self.head
        while temp.next.next is not None:   # stop at SECOND-LAST node
            temp = temp.next
        data = temp.next.data
        temp.next = None
        return data

    def delete_at_position(self, pos):
        if self.head is None:
            raise IndexError("Underflow: list is empty")
        if pos < 1 or pos > self.length():
            raise IndexError(f"Invalid position {pos}")
        if pos == 1:
            return self.delete_at_beginning()
        temp = self.head
        for _ in range(pos - 2):      # stop at node (pos - 1)
            temp = temp.next
        target = temp.next
        temp.next = target.next       # bypass the target node
        return target.data

# Program 2: Doubly Linked List (DLL)
# Each node has two links: prev (to the previous node) and next (to the next node).
# Positions are 1-based.

class DNode:
    def __init__(self, data):
        self.prev = None
        self.data = data
        self.next = None


class DoublyLinkedList:
    def __init__(self):
        self.head = None

    def traverse_forward(self):
        temp, parts = self.head, []
        while temp:
            parts.append(str(temp.data))
            temp = temp.next
        print("  NULL <-> " + " <-> ".join(parts) + " <-> NULL" if parts else "  (empty)")

    def traverse_backward(self):
        if self.head is None:
            print("  (empty)"); return
        temp = self.head
        while temp.next:              # go to the last node
            temp = temp.next
        parts = []
        while temp:                   # follow prev links back to the head
            parts.append(str(temp.data))
            temp = temp.prev
        print("  Backward: " + " <-> ".join(parts))

    def length(self):
        n, temp = 0, self.head
        while temp:
            n += 1
            temp = temp.next
        return n

    def search(self, key):
        temp, pos = self.head, 1
        while temp:
            if temp.data == key:
                return pos
            temp, pos = temp.next, pos + 1
        return -1

    # ---------- insertion ----------
    def insert_at_beginning(self, data):
        new_node = DNode(data)
        new_node.next = self.head
        if self.head is not None:
            self.head.prev = new_node    # old first node points back to new node
        self.head = new_node

    def insert_at_end(self, data):
        new_node = DNode(data)
        if self.head is None:
            self.head = new_node
            return
        temp = self.head
        while temp.next:
            temp = temp.next
        temp.next = new_node
        new_node.prev = temp

    def insert_at_position(self, data, pos):
        if pos < 1 or pos > self.length() + 1:
            raise IndexError(f"Invalid position {pos}")
        if pos == 1:
            self.insert_at_beginning(data)
            return
        temp = self.head
        for _ in range(pos - 2):         # node at position pos-1
            temp = temp.next
        new_node = DNode(data)
        new_node.next = temp.next        # 1
        new_node.prev = temp             # 2
        if temp.next is not None:
            temp.next.prev = new_node    # 3 (skip when inserting at the end)
        temp.next = new_node             # 4

    # ---------- deletion ----------
    def delete_at_beginning(self):
        if self.head is None:
            raise IndexError("Underflow: list is empty")
        temp = self.head
        self.head = temp.next
        if self.head is not None:
            self.head.prev = None
        return temp.data

    def delete_at_end(self):
        if self.head is None:
            raise IndexError("Underflow: list is empty")
        temp = self.head
        while temp.next:                 # go to the last node
            temp = temp.next
        if temp.prev is None:            # it was the only node
            self.head = None
        else:
            temp.prev.next = None
        return temp.data

    def delete_at_position(self, pos):
        if self.head is None:
            raise IndexError("Underflow: list is empty")
        if pos < 1 or pos > self.length():
            raise IndexError(f"Invalid position {pos}")
        if pos == 1:
            return self.delete_at_beginning()
        temp = self.head
        for _ in range(pos - 1):         # node AT position pos
            temp = temp.next
        temp.prev.next = temp.next
        if temp.next is not None:
            temp.next.prev = temp.prev
        return temp.data

# Program 3: Circular (Singly) Linked List (CLL)
# The last node's next points back to the head instead of NULL.
# Positions are 1-based.

class Node:
    def __init__(self, data):
        self.data = data
        self.next = None


class CircularLinkedList:
    def __init__(self):
        self.head = None

    def _last(self):
        """Return the last node (the one whose next is head)."""
        temp = self.head
        while temp.next is not self.head:
            temp = temp.next
        return temp

    def traverse(self):
        if self.head is None:
            print("  (empty)"); return
        parts, temp = [], self.head
        while True:                       # do-while: visit head at least once
            parts.append(str(temp.data))
            temp = temp.next
            if temp is self.head:
                break
        print("  " + " -> ".join(parts) + f" -> (back to {self.head.data})")

    def length(self):
        if self.head is None:
            return 0
        n, temp = 1, self.head.next
        while temp is not self.head:
            n += 1
            temp = temp.next
        return n

    def search(self, key):
        if self.head is None:
            return -1
        temp, pos = self.head, 1
        while True:
            if temp.data == key:
                return pos
            temp, pos = temp.next, pos + 1
            if temp is self.head:         # came full circle: not found
                return -1

    # ---------- insertion ----------
    def insert_at_beginning(self, data):
        new_node = Node(data)
        if self.head is None:
            new_node.next = new_node      # single node points to itself
            self.head = new_node
            return
        last = self._last()
        new_node.next = self.head
        last.next = new_node              # last node must point to the NEW head
        self.head = new_node

    def insert_at_end(self, data):
        new_node = Node(data)
        if self.head is None:
            new_node.next = new_node
            self.head = new_node
            return
        last = self._last()
        last.next = new_node
        new_node.next = self.head         # close the circle

    def insert_at_position(self, data, pos):
        if pos < 1 or pos > self.length() + 1:
            raise IndexError(f"Invalid position {pos}")
        if pos == 1:
            self.insert_at_beginning(data)
            return
        temp = self.head
        for _ in range(pos - 2):
            temp = temp.next
        new_node = Node(data)
        new_node.next = temp.next
        temp.next = new_node

    # ---------- deletion ----------
    def delete_at_beginning(self):
        if self.head is None:
            raise IndexError("Underflow: list is empty")
        data = self.head.data
        if self.head.next is self.head:   # only one node
            self.head = None
            return data
        last = self._last()
        self.head = self.head.next
        last.next = self.head             # keep the circle closed
        return data

    def delete_at_end(self):
        if self.head is None:
            raise IndexError("Underflow: list is empty")
        if self.head.next is self.head:
            data = self.head.data
            self.head = None
            return data
        temp = self.head
        while temp.next.next is not self.head:   # second-last node
            temp = temp.next
        data = temp.next.data
        temp.next = self.head
        return data

    def delete_at_position(self, pos):
        if self.head is None:
            raise IndexError("Underflow: list is empty")
        if pos < 1 or pos > self.length():
            raise IndexError(f"Invalid position {pos}")
        if pos == 1:
            return self.delete_at_beginning()
        temp = self.head
        for _ in range(pos - 2):
            temp = temp.next
        target = temp.next
        temp.next = target.next
        return target.data

# Program 4: Applications of linked lists
#  (a) Reverse a singly linked list in place
#  (b) Find the middle node with slow/fast pointers
#  (c) Polynomial addition using linked lists

class Node:
    def __init__(self, data, nxt=None):
        self.data = data
        self.next = nxt

def build(values):
    head = None
    for v in reversed(values):
        head = Node(v, head)            # insert at beginning, in reverse order
    return head

def show(head):
    out = []
    while head:
        out.append(str(head.data))
        head = head.next
    return " -> ".join(out + ["NULL"])

# (a) Reverse: turn every arrow around, one node at a time
def reverse(head):
    prev = None
    curr = head
    while curr:
        nxt = curr.next     # remember the rest of the list
        curr.next = prev    # reverse this node's link
        prev = curr         # move prev one step forward
        curr = nxt          # move curr one step forward
    return prev             # prev is the new head

# (b) Middle: fast moves 2 steps while slow moves 1
def middle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
    return slow.data

# (c) Polynomial: each node stores (coefficient, exponent), exponents decreasing
class Term:
    def __init__(self, coeff, exp):
        self.coeff, self.exp, self.next = coeff, exp, None

def make_poly(pairs):
    head = tail = None
    for c, e in pairs:
        t = Term(c, e)
        if head is None:
            head = tail = t
        else:
            tail.next = t
            tail = t
    return head

def poly_str(p):
    terms = []
    while p:
        if p.exp == 0:
            terms.append(f"{p.coeff}")
        elif p.exp == 1:
            terms.append(f"{p.coeff}x")
        else:
            terms.append(f"{p.coeff}x^{p.exp}")
        p = p.next
    return " + ".join(terms)

def add_poly(p, q):
    result = []
    while p and q:
        if p.exp > q.exp:
            result.append((p.coeff, p.exp)); p = p.next
        elif p.exp < q.exp:
            result.append((q.coeff, q.exp)); q = q.next
        else:                               # same exponent: add coefficients
            if p.coeff + q.coeff != 0:
                result.append((p.coeff + q.coeff, p.exp))
            p, q = p.next, q.next
    while p:
        result.append((p.coeff, p.exp)); p = p.next
    while q:
        result.append((q.coeff, q.exp)); q = q.next
    return make_poly(result)


head = build([10, 20, 30, 40, 50])
print("Original :", show(head))
print("Middle   :", middle(head))
head = reverse(head)
print("Reversed :", show(head))

p1 = make_poly([(5, 3), (4, 2), (2, 0)])      # 5x^3 + 4x^2 + 2
p2 = make_poly([(3, 2), (7, 1), (6, 0)])      # 3x^2 + 7x + 6
print("\nP1       :", poly_str(p1))
print("P2       :", poly_str(p2))
print("P1 + P2  :", poly_str(add_poly(p1, p2)))

Practice & Assessment

A. Conceptual questions

1. What is a linked list? How is it different from an array?

A linear collection of nodes where each node holds data and a link to the next node. Unlike an array, its nodes need not be contiguous, its size is dynamic, insertion/deletion only changes pointers, but there is no random access.

2. Why is a node called a self-referential structure?

Because it contains a pointer to another structure of the same type (struct node *next inside struct node).

3. Why is deleting the last node O(n) even in a singly list with a tail pointer?

After deletion, the second-last node must become the new tail and its next must be set to NULL. A singly list has no prev link, so finding the second-last node requires walking from the head.

4. What are the advantages of a doubly linked list over a singly linked list?

Two-way traversal, O(1) deletion of a node when a pointer to it is given, and easier insertion before a node. The cost is an extra pointer per node and more links to maintain.

5. How do you detect the end of a circular linked list during traversal?

There is no NULL; stop when the traversal pointer comes back to the head (use a do-while loop so the head is processed first).
