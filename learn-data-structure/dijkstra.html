Find the cheapest route with Dijkstra’s algorithm

Learn how to find the shortest path in a weighted graph by watching every comparison happen, then solve problems yourself.

Dijkstra’s algorithm (published in 1959 by Edsger Dijkstra) finds the cheapest route from one starting vertex to every other vertex, as long as no edge has a negative weight. It is behind many route planners and network routing tools.

1. What is Dijkstra’s algorithm?

It finds the cheapest route from one starting vertex to all the others.

A weighted graph has a number (a weight) on every edge. The weight is the cost of using that edge: distance, time, money, or anything else. Dijkstra’s algorithm picks a source vertex and finds the route with the smallest total weight to every other vertex. The routes together form a shortest-path tree.

Key idea: “shortest” means the smallest total weight, not the fewest edges. A route with more edges can be cheaper.

Where is it used?

Road navigationRoads are edges and junctions are vertices. Real map apps add live traffic and faster variants, so a fixed weighted graph is only a simplified model.
Network routingLink-state routing protocols such as OSPF run a shortest-path calculation like this to choose routes.
Cost optimisationCheapest chain of flights, shipping legs or transfers, when each leg has a cost.
Games and robotsFinding the cheapest way across a map. A* is a close relative that adds a guess about the remaining distance.

Any path versus the cheapest path

  • Finding any path only asks: can I get there? A traversal such as BFS or DFS answers that.
  • Finding the cheapest path asks: which route has the smallest total weight? That is Dijkstra’s job.
  • BFS finds the route with the fewest edges. That is the cheapest route only when every edge costs the same.

  • Weighted graph: every edge has a cost.
  • Dijkstra: single source, cheapest path to every vertex, weights must be 0 or more.
  • Cheapest path ≠ fewest edges.

2. Core concepts and the graph lab

Learn the vocabulary, then build and run your own graph.

Graph, vertex, edgeA graph is a set of vertices (points) joined by edges (connections).
WeightThe cost of travelling along one edge. Here it is 0 or more.
PathA sequence of connected vertices. Its cost is the sum of its edge weights.
SourceThe vertex where we start.
DistanceThe best total cost found from the source to a vertex. Written dist[v].
Tentative distanceThe best distance found so far. It can still improve until the vertex is settled.
RelaxationChecking whether an edge gives a cheaper route to a vertex.
Predecessor (parent)The vertex just before v on the best route found so far. Written parent[v].
Priority queueA structure that always hands back the entry with the smallest distance first.
Settled vertexA vertex whose shortest distance is final. It will never change again.
Infinity (∞)“Not found yet.” At the end, a vertex with ∞ is unreachable. It is not a real distance.
Shortest-path treeAll the parent links together. Following them back from any vertex gives its cheapest route.

The relaxation rule

if dist[u] + w(u, v) < dist[v]: dist[v] = dist[u] + w(u, v); parent[v] = u

We have just settled u. The edge from u to v offers a route of cost dist[u] + w(u, v). We update v only if that route is strictly cheaper. If it only ties, we keep the old parent. This stops needless updates and keeps the result stable.

Relaxation calculator. Type numbers (use inf for ∞).
The starting state: dist(source) = 0, every other distance = ∞, every parent is empty, nothing is settled, and the priority queue holds only the entry (0, source).
The main loop: remove the entry with the smallest distance. If its vertex is already settled it is a stale entry (an older, longer route that was later beaten), so ignore it. Otherwise the vertex becomes settled, because with non-negative weights no later route can be cheaper. Then relax its outgoing edges.

4. Complexity and comparisons

The running time depends on how the graph and the priority queue are stored.

Let V = number of vertices and E = number of edges.

ImplementationTimeExtra spaceNotes
Adjacency list + binary heap with lazy duplicates (the code in section 6)O((V + E) log V)Heap can hold up to E entries: O(E)Each successful relaxation pushes a new entry. Stale entries are skipped. For a simple graph, log E is at most 2 log V.
Adjacency list + binary heap with decrease-keyO((V + E) log V)Heap holds at most V entries: O(V)Needs a heap that can lower an entry’s key. A Fibonacci heap improves it to O(E + V log V).
Adjacency matrix + linear scan for the minimumO(V2)Graph storage O(V2)Each of V rounds scans V vertices. Good for very dense graphs.

Space in every version: the graph itself takes O(V + E) as a list or O(V2) as a matrix. The distance, parent and settled arrays each take O(V).

No single bound fits every implementation. Always say which graph storage and which priority queue you assume.

Compared with other algorithms

AlgorithmUse it whenTime (typical)Caveat
BFSUnweighted graph, or every edge costs the sameO(V + E)Counts edges, so it is wrong for different positive weights.
DijkstraNon-negative weightssee the table aboveInvalid with negative weights.
Bellman-FordNegative weights are possibleO(V × E)Detects a negative cycle. If one is reachable from the source, shortest distances are not defined.

Revision notes
  • List + heap: O((V + E) log V). Matrix + scan: O(V2).
  • Sparse graph (E small): list + heap. Very dense graph: matrix can be competitive.
  • Negative weights: use Bellman-Ford.

5. Special cases and common mistakes

Small graphs, with results computed live by the same algorithm.

Cycles are fine. A graph with cycles still works, as long as the weights are not negative. A negative edge is the problem, not a cycle.

Other cases to remember

  • Zero-weight edges are allowed. They cost nothing but still count as steps in the path.
  • Unreachable vertices end with distance ∞ and no parent. Never invent a path for them.
  • Equal-length shortest paths can exist. The shortest distance is unique, but the shortest path may not be. The parent you get depends on the strict comparison and the queue order.
  • Directed edges can only be used one way, so distances from A to B and from B to A may differ.
  • Stale entries must be ignored. Skipping this check can process a vertex twice.

Common mistakes

  • Using BFS when edges have different positive weights.
  • Writing the relaxation test the wrong way round, or updating on a tie.
  • Forgetting to update the parent when the distance changes.
  • Stopping when the destination is first discovered. Stop only when it is settled (removed from the queue).
  • Treating a tentative distance as final.
  • Printing ∞ as if it were a real distance.
  • Mixing up “fewest edges” with “smallest total weight”.

Revision notes
  • Negative edge → Dijkstra can give wrong answers (use Bellman-Ford).
  • Zero edges and cycles are fine.
  • Stop only when the destination is settled.

6. Python implementation

The same algorithm as the visualiser, using the Home to School graph.

DIJKSTRA(Graph, source):          // all weights must be >= 0
  for each vertex v:  dist[v] ← ∞;  parent[v] ← none
  dist[source] ← 0
  settled ← empty set
  PQ ← min-priority queue containing (0, source)

  while PQ is not empty:
    (d, u) ← remove the entry with the smallest d
    if u is in settled:  continue        // stale entry
    add u to settled                      // dist[u] = d is final
    for each edge (u, v) with weight w:
      if v is in settled:  continue
      if d + w < dist[v]:                 // strictly shorter
        dist[v]   ← d + w
        parent[v] ← u
        insert (dist[v], v) into PQ
  return dist, parent
import heapq
from math import inf

def build_graph(vertices, edges, directed=False):
    """Return an adjacency list: {vertex: [(neighbour, weight), ...]}."""
    graph = {v: [] for v in vertices}          # isolated vertices are kept
    for u, v, w in edges:
        if w < 0:
            raise ValueError("Dijkstra needs non-negative weights")
        graph[u].append((v, w))
        if not directed:
            graph[v].append((u, w))
    return graph

def dijkstra(graph, source):
    """Single-source shortest paths. Returns (dist, parent)."""
    dist = {v: inf for v in graph}
    parent = {v: None for v in graph}
    dist[source] = 0
    heap = [(0, source)]                        # (distance, vertex)
    settled = set()
    while heap:
        d, u = heapq.heappop(heap)              # smallest distance first
        if u in settled:                        # stale entry: ignore it
            continue
        settled.add(u)                          # d is now final
        for v, w in graph[u]:
            if v in settled:
                continue
            nd = d + w                          # candidate distance
            if nd < dist[v]:                    # strictly shorter: relax
                dist[v] = nd
                parent[v] = u
                heapq.heappush(heap, (nd, v))
    return dist, parent

def shortest_path(parent, source, target, dist):
    """Return the path as a list, or None if target is unreachable."""
    if dist[target] == inf:
        return None
    path = [target]
    while path[-1] != source:
        path.append(parent[path[-1]])
    return path[::-1]
# H = Home, T = School; A to F are road junctions
vertices = ["H", "A", "B", "C", "D", "E", "F", "T"]
edges = [("H", "C", 5), ("H", "B", 2), ("H", "A", 3),
         ("A", "D", 3), ("B", "D", 1), ("B", "E", 6),
         ("C", "E", 2), ("D", "F", 4), ("E", "F", 1),
         ("E", "T", 4), ("F", "T", 2)]

graph = build_graph(vertices, edges)           # undirected
dist, parent = dijkstra(graph, "H")

for v in vertices:
    print(v, dist[v], parent[v])
path = shortest_path(parent, "H", "T", dist)
print("Path:", " -> ".join(path), "cost", dist["T"])

  • An unreachable vertex keeps inf and parent None, and shortest_path returns None for it.
  • heapq compares tuples, so equal distances are ordered by vertex name. The visualiser uses the same rule, so both give the same parents.
  • The check u in settled is what handles stale heap entries.
Revision notes
  • Heap entries are (distance, vertex).
  • Ignore stale entries; relax only when strictly shorter.
  • Rebuild the path by following parent backwards.
