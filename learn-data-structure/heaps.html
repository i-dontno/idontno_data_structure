Heaps: always one step from the top

In a heap, you can quickly reach the most important value, because it is always at the top.

  • Max heap: the biggest number is at the top.
  • Min heap: the smallest number is at the top.

A heap always keeps the biggest (or smallest) value at the top. Build one, change it, and watch each step happen.

1. What is a heap?

A heap is a tree that follows two rules.

Shape rule
It is a type of complete binary tree. Every level is full, except maybe the last level. The last level is filled from left to right.
Order rule (how the nodes are arranged)
A parent is always bigger than or equal to its children (max heap), or always smaller than or equal to its children (min heap).
Max heap  90, 70, 80, 40, 50, 60
The biggest value is at the top.
Min heap  10, 20, 15, 30, 40, 25
The smallest value is at the top.
A heap is not a BST. In a BST, everything on the left is smaller and everything on the right is bigger than the parent. In a heap, only a parent and its own children are compared. Example: in the max heap above, 80 is on the right side of 90 even though 80 is smaller. That is fine in a heap, but not in a BST.
  • A heap is usually stored in an array. No pointers are needed (see section 3).
  • Heaps are used for priority queues, heap sort, shortest-path algorithms and scheduling.

2. Properties of a heap

#PropertyMeaning

8Duplicates allowedThe same value can appear more than once

Height calculator

h = ⌊log₂ n⌋   (height is counted in edges; the root is at level 0)
  • A binary tree of height h has at most 2h+1 − 1 nodes. Level l holds at most 2l nodes. A complete tree of height h has at least 2h nodes.
  • These formulas count height in edges and need at least one node.
  • If there is a gap on the left of the last level but a node on its right, the tree is not complete. So it cannot be a heap.

5. Insertion (sift-up)

Put the new value at the end, then move it up until the order is correct.

  1. Put the new value at the end of the array.
  2. Find its parent at index ⌊(i − 1)/2⌋.
  3. If the new value is bigger than its parent (max heap), swap them.
  4. Repeat until the parent is bigger or equal, or the value reaches the top.

Worked example: insert 60 into [50, 30, 40, 10, 20]

Time: O(log n), because the value moves up at most as many levels as the height. This is also called sift-up or bubble-up.

6. Deleting the top (sift-down)

When the top is removed, there is an empty place. Move the last value to the top, then push it down.

  1. Check that the heap is not empty. Save the top value.
  2. Move the last value to the top and remove the last place.
  3. Compare the new top with its two children.
  4. Swap it with the bigger child (max heap) if that child is bigger.
  5. Keep moving down until the order is correct. Then return the saved value.

Worked example: delete 90 from [90, 70, 80, 40, 50, 60]

InsertionDelete root
First actionAdd at the endMove last value to the top
DirectionUpward (sift-up)Downward (sift-down)
Worst caseO(log n)O(log n)

7. Heapify and building a heap

Heapify fixes one node when both of its subtrees are already heaps. Build-heap uses heapify on many nodes to turn any list into a heap.

Max-heapify of [40, 70, 60, 10, 20]

  1. Assume the node itself is the biggest: largest = i. Find the left child (2i + 1) and the right child (2i + 2).
  2. If the left child exists and is bigger, it becomes largest. Do the same for the right child.
  3. If largest is not i, swap them. Then repeat for the child that changed.

Building a heap from [4, 10, 3, 5, 1]

Start at the last node that has children, index ⌊n/2⌋ − 1 (here 1). Then go backwards to index 0. Leaves have no children, so they are already fine. Working from the bottom up means the subtrees below are already heaps when we fix a parent.

Build-heap takes O(n) time, not O(n log n). Most nodes are near the bottom, so they move very little. See the calculator in section 10.

8. Heap sort

First build a max heap. Then swap the top with the last value of the heap, and make the heap one smaller. The sorted part (green) grows from the right.

  1. Build a max heap.
  2. Swap the top (the biggest) with the last value in the heap.
  3. Make the heap one smaller.
  4. Fix the top using heapify.
  5. Repeat until one value is left.
CaseTime
Best / average / worstO(n log n)
Extra space (done in place)O(1)
  • For small-to-big order, use a max heap. For big-to-small order, use a min heap.
  • Heap sort works in place, but it is not stable. Equal values may change their order.

9. Python programs

These programs use plain Python lists and index formulas, so you can see how it works.

class MaxHeap:
    def __init__(self):
        self.heap = []

    def insert(self, value):
        self.heap.append(value)                  # add at the end
        i = len(self.heap) - 1
        while i > 0:                             # sift up
            parent = (i - 1) // 2
            if self.heap[i] > self.heap[parent]:
                self.heap[i], self.heap[parent] = self.heap[parent], self.heap[i]
                i = parent
            else:
                break

    def heapify_down(self, i):
        n = len(self.heap)
        while True:
            largest = i
            left, right = 2 * i + 1, 2 * i + 2
            if left < n and self.heap[left] > self.heap[largest]:
                largest = left
            if right < n and self.heap[right] > self.heap[largest]:
                largest = right
            if largest == i:
                break
            self.heap[i], self.heap[largest] = self.heap[largest], self.heap[i]
            i = largest

    def delete_max(self):
        if not self.heap:
            raise IndexError("heap is empty")
        root = self.heap[0]
        last = self.heap.pop()
        if self.heap:
            self.heap[0] = last                  # last element becomes root
            self.heapify_down(0)                 # sift down
        return root

print("After insertion:")
print("Heap array:", h.heap)            # [60, 30, 50, 10, 20, 40]
print("Deleted maximum:", h.delete_max())   # 60
print("After deletion:")
print("Heap array:", h.heap)            # [50, 30, 40, 10, 20]
def heapify(arr, n, i):
    largest = i
    left, right = 2 * i + 1, 2 * i + 2
    if left < n and arr[left] > arr[largest]:
        largest = left
    if right < n and arr[right] > arr[largest]:
        largest = right
    if largest != i:
        arr[i], arr[largest] = arr[largest], arr[i]
        heapify(arr, n, largest)

def build_max_heap(arr):
    n = len(arr)
    for i in range(n // 2 - 1, -1, -1):          # from the last node with children up to the top
        heapify(arr, n, i)

def heap_sort(arr):
    n = len(arr)
    build_max_heap(arr)
    print("Max heap:", arr)
    for i in range(n - 1, 0, -1):
        arr[0], arr[i] = arr[i], arr[0]          # move the biggest value to its final place
        heapify(arr, i, 0)                       # active heap is now size i
        print("After extraction:", arr)
    print("Sorted array:", arr)

11. Applications, advantages and disadvantages of heap

A heap is used when you need the biggest or smallest value again and again, quickly. Click an application to see how a heap helps.

Top k biggest valuesMin heap of size kO(n log k)
Median of a streamOne max heap and one min heapO(log n) per new number
Merge k sorted listsMin heap of size kO(N log k)
Huffman codingMin heapO(n log n)

Advantages and disadvantages

Advantages
  • Fast access to the top. The biggest (max heap) or smallest (min heap) value is always at index 0. Time: O(1).
  • Fast insert and remove-top. Both take O(log n) because the tree is short.
  • Fast build. Any array becomes a heap in O(n) time with bottom-up build-heap.
  • Saves memory. It is stored in an array. No pointers are needed and there are no gaps.
  • Always balanced. The shape is a complete binary tree, so it can never turn into a long chain like a BST can.
  • Safe heap sort. Heap sort is O(n log n) even in the worst case, and it needs no extra array.
  • Easy to write. You only need index formulas and a swap.
Disadvantages
  • Slow search. Finding a given value takes O(n), because only a parent and its children are in order.
  • Not sorted. To get the values in sorted order, you must remove them one by one, which costs O(n log n).
  • Only one end is fast. A min heap gives the minimum quickly, but finding its maximum takes O(n).
  • Changing a value in the middle is hard. You must first find its index. Updating priorities needs extra index tracking.
  • Not good for neighbours or ranges. Questions like "next bigger value" or "all values between 10 and 20" suit a BST better.
  • Heap sort is not stable. Equal values may change their order. It is also often slower than quicksort in practice, because it jumps around the array.
  • Resizing cost. With a fixed array, growing it means copying all the values.

12. Max heap vs min heap, mistakes, and quiz

Max heapMin heap
OrderParent ≥ childrenParent ≤ children
RootMaximumMinimum
Insert moves up ifgreater than parentsmaller than parent
Delete swaps withlarger childsmaller child
Priority queueHighest firstLowest first
Heap sort givesAscendingDescending

Common mistakes

  • Thinking a heap is a BST. The two children of a node can be in any order.
  • Breaking the shape. Always insert at the end, and move the last value to the top when removing.
  • Using wrong child formulas. With 0-based indexing, left = 2i + 1 and right = 2i + 2.
  • Swapping with the wrong child. Choose the bigger child (max heap) or the smaller child (min heap).
  • Starting build-heap from the top. Start from index n // 2 − 1 instead.
  • Forgetting to make the heap smaller in heap sort.
  • Thinking a heap is sorted. Only parents and children are in order.

Where heaps are used

  • Priority queues: the operating system picks the next task, and a hospital sees the most urgent patient first.
  • Graph algorithms: Dijkstra and Prim pick the smallest option at each step.
  • Top-k: keep a min heap of size k to find the k biggest values in a list.
  • Middle value (median): use a max heap for the smaller half and a min heap for the bigger half.
