Introduction to Hashing & Hash Tables

Definition

Hashing is a technique that converts a key into a number with a hash function and uses that number to decide where to store (or find) the data. A hash table is the array-based data structure that stores key-value pairs this way.

Why is hashing important?

  • Searching an unsorted list takes O(n); a sorted list with binary search takes O(log n); a hash table takes O(1) on average.
  • It powers Python's dict and set, database indexes, caches and compilers.
  • It turns many "search" problems into one pass over the data (counting, duplicates, two-sum).

Real-world examples

Phone contacts

Jump straight to a name instead of scanning the list.

Library shelves

A book code tells you the shelf directly.

Dictionary / cache

The word or URL itself decides where its data lives.

Understanding hash tables

  • Key-value pairs: data is stored as (key, value), e.g. roll number → student.
  • Table size (m): the number of slots in the underlying array.
  • Array-based storage: a Python list of m slots, each reachable by index in O(1).
  • Index calculation: index = hash(key) % m.
  • Operations: insert (compute index, store), search (compute index, read), delete (compute index, remove).

Example: student information stored with index = roll % 5:

How hashing works, step by step

  1. Take an input key.
  2. Pass it to the hash function.
  3. Get a hash value (an integer).
  4. Convert it to a valid table index (usually % m).
  5. Store the value at that index.
  6. Retrieve with the same process: the same key always leads to the same slot.

Practical example with keys 10, 25, 32, 45, table size 10 and h(k) = k % 10:

Each key is sent through h(k). Keys 25 and 45 land on index 5: a collision (red). Collisions are the topic of Part 3.
m = 10                                         # table size
keys = [10, 25, 32, 45]
table = [None] * m
for k in keys:
    index = k % m                              # hash function: division method
    print(f"key {k:2} -> h({k}) = {k} % {m} = {index}", end="")
    if table[index] is None:
        table[index] = k
        print("  -> stored")
    else:
        print(f"  -> COLLISION with {table[index]}")
print(table)
Output

Why it is fast

To find key 32 we do not look at 10, 25 or 45. We compute 32 % 10 = 2 and open slot 2 directly. The work does not grow with the number of stored items.

Hash Functions: Properties & Types

Definition

A hash function h maps a key of any kind to a fixed range of integers: h(key) → hash value. A table index is that value reduced to the table: index = h(key) mod m.

Hash valueTable index
The raw integer a hash function returns (can be huge or negative)A number from 0 to m − 1 that selects a slot

Properties of a good hash function

PropertyMeaningWhy it matters
DeterministicSame key → same value, always (within a run)Otherwise you could never find stored data

A good hash function keeps chains short or probe sequences short, so operations stay near O(1). A poor one degrades the table to O(n).

Types of hash functions

1. Division method

  • Definition: the remainder of dividing the key by the table size.
  • Formula: h(k) = k mod m
  • Advantage: very fast and simple.
  • Limitation: if m shares factors with the keys (for example m = 10 and keys ending in 0), many keys collide. Choose m as a prime.
def division_hash(k, m):
    return k % m
Example

division_hash(1234, 7) = 1234 % 7 = 2
bad choice m=10 on keys ending in 0: [0, 0, 0, 0, 0]

2. Multiplication method

  • Definition: multiply the key by a constant A (0 < A < 1), keep the fractional part, then scale by m.
  • Formula: h(k) = floor(m × ((k × A) mod 1)), with A ≈ 0.6180339887.
  • Advantage: works well for any m (even a power of 2). Limitation: a little slower; needs floating-point or fixed-point arithmetic.
def multiplication_hash(k, m, A=0.6180339887):          # A = (sqrt(5) - 1) / 2, Knuth's suggestion
    return math.floor(m * ((k * A) % 1))

3. Mid-square method

  • Definition: square the key and take the middle digits.
  • Formula: h(k) = middle r digits of k²
  • Example: 4567² = 20857489, middle two digits = 57.
  • Advantage: the middle digits depend on all digits of the key. Limitation: keys with many zeros or a very small key give poor results.
def mid_square_hash(k, m):
    r = len(str(m - 1))                                  # number of digits needed for an index
    square = str(k * k)
    start = (len(square) - r) // 2                       # take r digits from the middle
    return int(square[start:start + r]) % m
Example (m = 100)

k=1234: k^2 = 1522756, middle 2 digits -> index 22
k=9999: k^2 = 99980001, middle 2 digits -> index 80

4. Folding method

  • Definition: split the key into equal parts, add the parts (shift folding), or reverse alternate parts before adding (boundary folding), then reduce with mod.
  • Formula: h(k) = (part1 + part2 + ...) mod m
  • Advantage: uses every digit; good for long keys (phone, ID numbers). Limitation: different keys with the same parts in another order collide (shift folding).
def folding_hash(k, m, size=2):
    digits = str(k)
    parts = [int(digits[i:i + size]) for i in range(0, len(digits), size)]
    return sum(parts) % m                                # shift folding: add the groups

5. Digit extraction method

  • Definition: select certain digit positions of the key and join them.
  • Formula: h(k) = digits of k at chosen positions
  • Advantage: excellent when you know which digits vary (for example the last digits of an ID). Limitation: only works if the key format is known and fixed.
def digit_extraction_hash(k, positions=(0, 2, 4), width=6):
    digits = str(k).zfill(width)
    return int("".join(digits[p] for p in positions))    # keep only selected digits

6. Polynomial rolling hash (for strings)

  • Definition: treat the string as a number in base p, so position matters.
  • Formula: h(s) = (s[0]·p^(n−1) + s[1]·p^(n−2) + ... + s[n−1]) mod M, computed with Horner's rule.
  • Advantage: order-sensitive ('abc' ≠ 'cab') and it can roll: sliding a window needs O(1) work per step (used in Rabin-Karp string search). Limitation: needs a good base p and large modulus M.
def polynomial_hash(s, p=31, m=1_000_000_009):
    h = 0
    for ch in s:
        h = (h * p + ord(ch)) % m                        # Horner's rule
    return h

Hash Functions in Python

Python has a built-in hash() function that returns an integer for any hashable (immutable) object. Dictionaries and sets call it internally.

print(hash(3) == hash(3.0), hash(True), hash(0))
print(hash((1, 2)) == hash((1, 2)))
print(hash("hello") == hash("hello"))     # same inside one run
try:

except TypeError as e:

True

  • Integers: small non-negative ints hash to themselves; hash(-1) is -2 because -1 is reserved internally.
  • Equal numbers hash equally: hash(3) == hash(3.0), matching 3 == 3.0.
  • Strings: hashed from all characters; randomised per process (below).
  • Immutable objects: tuples of hashables are hashable; lists, dicts and sets are not.

The relationship between hash() and __eq__()

Rule

If a == b then hash(a) == hash(b). The reverse need not hold: equal hashes do not imply equal objects (that is a collision). If you define __eq__, also define __hash__ (from the same fields), or the class becomes unhashable.

class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y
    def __eq__(self, other):
        return isinstance(other, Point) and (self.x, self.y) == (other.x, other.y)
    def __hash__(self):
        return hash((self.x, self.y))      # equal objects MUST have equal hashes

a, b = Point(1, 2), Point(1, 2)
print(a == b, hash(a) == hash(b))
print(len({a, b}))                          # the set sees one point

class Bad:
    def __eq__(self, other):                # defining __eq__ alone removes the default __hash__
        return True
try:
    {Bad()}
except TypeError as e:
    print("TypeError:", e)

Creating a custom hash function

Combine every character and its position, then reduce with % m:

def my_hash(text, m):
    total = 0
    for ch in text:
        total = (total * 31 + ord(ch)) % m     # polynomial hash with base 31
    return total

for word in ["cat", "dog", "act", "tac", "hello"]:
    print(f"{word:6} -> {my_hash(word, 10)}")
print(my_hash("cat", 10) == my_hash("cat", 10))   # deterministic: same input, same output

Hash randomisation

For security (to defeat attacks that craft many colliding strings), Python randomises string and bytes hashes each time the interpreter starts. The same string can have different hashes in two runs. Integers are not randomised. You can fix it with the environment variable PYTHONHASHSEED.

import os, subprocess, sys
code = "print(hash('hello'))"
for seed in ("1", "2"):
    out = subprocess.run([sys.executable, "-c", code], capture_output=True, text=True,
                         env={**os.environ, "PYTHONHASHSEED": seed})
    print("PYTHONHASHSEED =", seed, "->", out.stdout.strip())
Output
PYTHONHASHSEED = 1 -> -1712148659304476210
PYTHONHASHSEED = 2 -> -2276782357261739453
Not for passwords or IDs

Python's hash() exists to support dicts and sets. It is not secure (not one-way or collision-resistant), it changes between runs, and it should never be used for password storage or persistent identifiers. Use hashlib or a password-hashing algorithm instead (Section 10).

Hash Collisions & Resolution Techniques

Definition

A collision occurs when two different keys produce the same table index.

Why do collisions occur?

  • There are far more possible keys than table slots. By the pigeonhole principle some keys must share a slot.
  • Even with few keys, collisions appear sooner than expected (the birthday paradox).
  • Reducing a hash value with % m throws away information.

Example: size 7, h(k) = k % 7, keys 10, 17, 24, 31, 15:

10, 17, 24 and 31 all give index 3 (10 = 7+3, 17 = 14+3, ...). Four keys fight for one slot.
m = 7
keys = [10, 17, 24, 31, 15]
table = [None] * m
for k in keys:
    index = k % m
    if table[index] is not None:
        print(f"key {k}: index {index} already holds {table[index]} -> collision, data overwritten!")
    table[index] = k
print(table)
Output
key 17: index 3 already holds 10 -> collision, data overwritten!
key 24: index 3 already holds 17 -> collision, data overwritten!
key 31: index 3 already holds 24 -> collision, data overwritten!
[None, 15, None, 31, None, None, None]

Collisions are unavoidable

import random
random.seed(1)
m = 50
keys = random.sample(range(10_000), 10)
indexes = [k % m for k in keys]
print("10 random keys into 50 slots, distinct indexes:", len(set(indexes)))

# The birthday effect: expected collisions appear much earlier than you think
for n in (5, 10, 20):
    p_no = 1.0
    for i in range(n):
        p_no *= (m - i) / m
    print(f"{n} keys in {m} slots: chance of at least one collision = {1 - p_no:.1%}")
Output

5 keys in 50 slots: chance of at least one collision = 18.6%
10 keys in 50 slots: chance of at least one collision = 61.8%
20 keys in 50 slots: chance of at least one collision = 98.8%

Effects on performance

  • More comparisons per lookup, because several keys share the same location.
  • In the worst case (all keys collide) every operation becomes O(n).
  • Without a resolution method, data is lost (overwritten).

Collision resolution techniques

A hash table must always handle collisions. There are two families:

A. Separate chaining

Each slot holds a list of all keys that map to it. Colliding keys live outside the array in chains.

B. Open addressing

Every key lives inside the array. On a collision, probe other slots in a fixed order: linear probing, quadratic probing or double hashing.

FeatureSeparate chainingOpen addressing

Separate Chaining

Definition

Separate chaining resolves collisions by keeping a collection (usually a linked list) at every table index. All keys with the same index are stored in that index's chain.

  • Insert: compute the index, check the chain for the key (update if found), else add to the chain.
  • Search: compute the index, walk along that chain only.
  • Delete: compute the index, find the node in the chain, remove it (no side effects on other keys).
  • Chains can also be Python lists (as below), balanced trees (Java 8 HashMap converts long chains to trees) or other collections.
Keys 10, 17, 24, 31 share index 3 and form a chain; 15 sits alone at index 1.

Python implementation

A list of m buckets; each bucket is a list of [key, value] pairs. Method by method:

class HashTable:
    """Hash table using separate chaining (each bucket is a list of [key, value] pairs)."""
    def __init__(self, size=7):
        self.size = size
        self.buckets = [[] for _ in range(size)]    # one empty chain per index
        self.count = 0

    def _hash(self, key):                            # hash function + index calculation
        return hash(key) % self.size if not isinstance(key, int) else key % self.size

    def insert(self, key, value=None):
        index = self._hash(key)
        for pair in self.buckets[index]:             # key already present? then update it
            if pair[0] == key:
                pair[1] = value
                return
        self.buckets[index].append([key, value])     # otherwise add at the end of the chain
        self.count += 1

    def search(self, key):
        index = self._hash(key)
        for k, v in self.buckets[index]:             # walk along the chain
            if k == key:
                return v
        return None

    def delete(self, key):
        index = self._hash(key)
        chain = self.buckets[index]
        for i, (k, v) in enumerate(chain):
            if k == key:
                del chain[i]
                self.count -= 1
                return True
        return False

    def display(self):
        for i, chain in enumerate(self.buckets):
            items = " -> ".join(str(k) for k, v in chain) if chain else "empty"
            print(f"  [{i}] {items}")

    def load_factor(self):
        return self.count / self.size
  • _hash(key): hash function + modulo gives the index (integers directly, other keys through hash()).
  • insert: scans the chain; updates the value if the key exists, otherwise appends. This prevents duplicate keys.
  • search: scans one chain and returns the value or None.
  • delete: removes the pair from its chain and reports success.
  • display: prints every bucket. load_factor: items / size.

Open Addressing & Linear Probing

Definition

Open addressing stores every key inside the hash table array itself (no lists). When the home slot is taken, the algorithm probes a fixed sequence of other slots until it finds an empty one. Searching follows the same sequence.

Separate chainingOpen addressing
StorageArray of listsArray only
On collisionAdd to the chainProbe for another slot
Needs load factorany (can be above 1)below 1

A. Linear probing

Formula

h(k, i) = (h(k) + i) mod m, for i = 0, 1, 2, ...
Try the home slot, then the next slot, then the next, wrapping around the end of the table.

Example: m = 7, keys 10, 17, 24, 31, 15 (the same keys as in chaining). The orange cell is the slot just filled; the note shows which attempt found it.

Final table. 10, 17, 24, 31 all start at index 3, so they fill 3, 4, 5, 6 in order. 15 (h = 1) goes straight to index 1.

Insert 24 (h = 3)

Implementation

All three probing methods share one base class that handles insert, search, delete and display. Each subclass only defines probe(key, i). Deleted slots are marked with a tombstone.

DELETED = object()                      # tombstone marker for removed slots

class OpenAddressingTable:
    """Base class: all items live inside the array. Subclasses define the probe sequence."""
    def __init__(self, size=7):
        self.size = size
        self.slots = [None] * size      # None = never used, DELETED = tombstone
        self.count = 0

    def h1(self, key):
        return key % self.size

    def probe(self, key, i):            # index to try on the i-th attempt (i = 0, 1, 2, ...)
        raise NotImplementedError

    def insert(self, key, value=None, verbose=False):
        first_free = None
        for i in range(self.size):
            idx = self.probe(key, i)
            slot = self.slots[idx]
            if verbose:
                print(f"    probe {i}: index {idx} -> {'empty' if slot is None else 'deleted' if slot is DELETED else slot[0]}")
            if slot is None:                                   # end of the probe sequence
                target = idx if first_free is None else first_free
                self.slots[target] = (key, value)
                self.count += 1
                return target
            if slot is DELETED:
                if first_free is None:
                    first_free = idx                           # reuse the first tombstone later
            elif slot[0] == key:                               # duplicate key: update
                self.slots[idx] = (key, value)
                return idx
        if first_free is not None:
            self.slots[first_free] = (key, value)
            self.count += 1
            return first_free
        raise OverflowError(f"no free slot found for {key} after {self.size} probes")

    def search(self, key):
        for i in range(self.size):
            idx = self.probe(key, i)
            slot = self.slots[idx]
            if slot is None:                    # a never-used slot ends the search: key is absent
                return None
            if slot is not DELETED and slot[0] == key:
                return slot[1]
        return None

    def delete(self, key):
        for i in range(self.size):
            idx = self.probe(key, i)
            slot = self.slots[idx]
            if slot is None:
                return False
            if slot is not DELETED and slot[0] == key:
                self.slots[idx] = DELETED       # tombstone, NOT None
                self.count -= 1
                return True
        return False

    def display(self):
        for i, slot in enumerate(self.slots):
            text = "empty" if slot is None else "deleted" if slot is DELETED else str(slot[0])
            print(f"  [{i}] {text}")


class LinearProbingTable(OpenAddressingTable):

Primary clustering

Occupied slots form long runs. A new key hashing anywhere into the run must walk to its end and then extends the run, so runs grow faster and faster. In the example above, slots 3 to 6 became one block of four.

  • Simple to implement
  • Cache-friendly (neighbouring slots)
  • No extra memory for pointers

Disadvantages

  • Primary clustering
  • Performance collapses as α → 1
  • Needs tombstones for deletion

B. Quadratic probing

Formula

h(k, i) = (h(k) + c1·i + c2·i²) mod m
The step grows quadratically: with c1 = 0, c2 = 1 the probes are h, h+1, h+4, h+9, ... (mod m).

C. Double hashing

Formula

h(k, i) = (h1(k) + i·h2(k)) mod m
A second hash function gives each key its own step size.

Why two functions? With one function, keys that share a home slot share the whole probe path. With a second, key-dependent step, even keys with the same h1 usually follow different paths, so clusters hardly form.

  • Example functions: h1(k) = k mod m, h2(k) = 1 + (k mod (m − 1)) (m prime).
  • Conditions for h2: it must never return 0 (you would not move), and it should be coprime with m so the probe visits every slot (a prime m guarantees this).

Example: m = 7, keys 10, 17, 24, 31, 15:

10, 17, 24 and 31 share h1 = 3 but have different steps h2 = 5, 6, 1, 4, so they scatter across the table.

    t = cls(size)
    total = 0

        for i in range(size):
            idx = t.probe(k, i)
            if t.slots[idx] is None:

                total += i + 1
                break
    return total

Why search is faster than in an unsorted array

An unsorted array must compare the target with items one by one: O(n). A hash table computes the index from the key and looks only there (and in a very short chain): O(1) on average. The worst case O(n) happens only when nearly all keys collide.

Rehashing

Definition

Rehashing means creating a larger table (usually about double, often a prime) and re-inserting every key with the new size. It is triggered when the load factor passes a threshold.

  • Why resize? To bring the load factor back down so collisions and probe lengths stay small.
  • Why re-insert, not copy? The index is hash(key) % m. When m changes, almost every key moves to a different index.
  • Hashing vs rehashing: hashing computes an index for a key with the current size; rehashing rebuilds the whole table for a new size.

Automatic resizing in action (max load factor 0.7, initial size 5):

def is_prime(n):
    if n < 2:
        return False
    for d in range(2, int(n ** 0.5) + 1):
        if n % d == 0:
            return False
    return True

def next_prime(n):
    while not is_prime(n):
        n += 1
    return n

class ResizingHashTable:
    def __init__(self, size=5, max_load=0.7):
        self.size, self.max_load = size, max_load
        self.buckets = [[] for _ in range(size)]
        self.count = 0

    def insert(self, key):
        self.buckets[key % self.size].append(key)
        self.count += 1
        if self.count / self.size > self.max_load:          # too crowded?
            self._rehash()

    def _rehash(self):
        old_items = [k for chain in self.buckets for k in chain]
        self.size = next_prime(self.size * 2)                # about double, prime
        self.buckets = [[] for _ in range(self.size)]
        for k in old_items:                                  # EVERY key gets a new index
            self.buckets[k % self.size].append(k)
        print(f"  *** rehash: new size {self.size}, load factor {self.count / self.size:.2f}")

Python Dictionaries, Sets & Practical Programs

Python dictionaries and sets

A dictionary stores key-value pairs; a set is essentially a dictionary with keys only. Both are hash tables, which is why membership tests are O(1) on average.

  • How keys are hashed: Python calls hash(key), then uses the result to pick a starting slot.
  • Retrieval: compute the hash, probe from that slot, compare using ==.
  • Why keys must be hashable: the hash must not change while the key is stored, so keys must be immutable (or have a stable __hash__).
  • Mutable vs immutable: ints, strs, tuples and frozensets work; lists, dicts and sets do not.
  • Collisions (high level): CPython uses open addressing with a perturbed probe sequence, a compact entries array that preserves insertion order, and resizes when about two thirds full.

Why passwords need dedicated algorithms

  • General hashes like SHA-256 are too fast: an attacker can test billions of guesses per second.
  • Password hashing algorithms (Argon2, scrypt, bcrypt, or PBKDF2) are deliberately slow and memory-hungry, and use a random salt so identical passwords give different hashes.
  • Python's standard library offers hashlib.pbkdf2_hmac and hashlib.scrypt; Argon2 and bcrypt come from third-party packages (argon2-cffi, bcrypt).
import hashlib, hmac, os

def hash_password(password):
    salt = os.urandom(16)                                                   # random salt per user
    digest = hashlib.pbkdf2_hmac("sha256", password.encode(), salt, 200_000)  # deliberately slow
    return salt, digest

def verify(password, salt, digest):
    test = hashlib.pbkdf2_hmac("sha256", password.encode(), salt, 200_000)
    return hmac.compare_digest(test, digest)                                # constant-time compare

salt, stored = hash_password("correct horse")

How collisions and load factor affect performance

  • As α grows, chains lengthen (chaining: expected 1 + α comparisons) or probe sequences lengthen (linear probing: about ½(1 + 1/(1−α)²) probes for a miss).
  • A bad hash function can send every key to one index and turn the table into a linked list: O(n).

class HashTable:
    """Hash table using separate chaining (each bucket is a list of [key, value] pairs)."""
    def __init__(self, size=7):
        self.size = size
        self.buckets = [[] for _ in range(size)]    # one empty chain per index
        self.count = 0

    def _hash(self, key):                            # hash function + index calculation
        return hash(key) % self.size if not isinstance(key, int) else key % self.size

    def insert(self, key, value=None):
        index = self._hash(key)
        for pair in self.buckets[index]:             # key already present? then update it
            if pair[0] == key:
                pair[1] = value
                return
        self.buckets[index].append([key, value])     # otherwise add at the end of the chain
        self.count += 1

    def search(self, key):
        index = self._hash(key)
        for k, v in self.buckets[index]:             # walk along the chain
            if k == key:
                return v
        return None

    def delete(self, key):
        index = self._hash(key)
        chain = self.buckets[index]
        for i, (k, v) in enumerate(chain):
            if k == key:
                del chain[i]
                self.count -= 1
                return True
        return False

    def display(self):
        for i, chain in enumerate(self.buckets):
            items = " -> ".join(str(k) for k, v in chain) if chain else "empty"
            print(f"  [{i}] {items}")

    def load_factor(self):
        return self.count / self.size

    ht.insert(k)

B. 20 interview questions

Q1. What is hashing?

Hashing converts a key into a number (hash value) with a hash function, and uses it to decide where to store or find the data. It gives average O(1) insert, search and delete.

Q2. What is a hash table?

A data structure that stores key-value pairs in an array. The index of each pair is computed from its key by a hash function.

Q3. What is a hash function?

A function that maps a key of any size to a fixed-range integer. For hash tables it must be deterministic and fast and should spread keys evenly.

Q4. What is a collision?

When two different keys produce the same table index. By the pigeonhole principle collisions cannot be avoided when there are more possible keys than slots.

Q5. What is collision resolution?

The method used to store and find keys that map to the same index. The two main families are separate chaining and open addressing.

Q6. What is separate chaining?

Each slot holds a collection (usually a linked list) of all keys that hash to it. Insert adds to the chain; search and delete walk along it.

Q7. What is open addressing?

All keys are stored inside the array itself. On a collision the algorithm probes other slots in a fixed sequence until it finds an empty one.

Q8. What is linear probing?

Open addressing with probe sequence (h(k) + i) mod m: try the next slot, then the next, and so on. Simple and cache-friendly, but causes primary clustering.

Q9. What is quadratic probing?

Probe sequence (h(k) + c1*i + c2*i²) mod m. It jumps farther each time, reducing primary clustering, but keys with the same start follow the same sequence (secondary clustering).

Q10. What is double hashing?

Probe sequence (h1(k) + i*h2(k)) mod m. The step size depends on the key, so keys with the same h1 usually follow different paths. h2(k) must never be 0 and should be coprime with m.

Q11. What is load factor?

α = n / m, the number of stored items divided by the table size. It measures how full the table is and controls collision frequency.

Q12. What is rehashing?

Creating a larger table and re-inserting every key with the new size, because indexes depend on m. It is triggered when the load factor passes a threshold.

Q13. What is clustering?

Long runs of occupied slots. Primary clustering (linear probing) makes runs grow; secondary clustering (quadratic) happens when keys with the same start share the same probe path.

Q14. Why are hash tables efficient?

The index is computed directly from the key, so no scanning or comparison with many items is needed. With a good hash function and small load factor, operations take O(1) on average.

Q15. What is the difference between hashing and encryption?

Encryption is reversible with a key; hashing is one-way and cannot be reversed. Encryption protects confidentiality, hashing summarises data for lookup or integrity checks.

Q16. How do Python dictionaries work?

A dict is a hash table using open addressing with a perturbed probe sequence. It stores keys, hashes and values in a compact array, keeps insertion order, and resizes when about two thirds full.

Q17. What makes an object hashable in Python?

It has a __hash__ method that returns the same integer for the object's lifetime, and a consistent __eq__. Equal objects must have equal hashes. Immutable built-ins (int, str, tuple of hashables, frozenset) qualify.

Q18. What is the average search complexity of a hash table?

O(1) on average (O(1 + α) for chaining). The worst case is O(n) if all keys collide.

Q19. What are cryptographic hash functions?

Hash functions such as SHA-256 designed to be one-way, collision-resistant and to show the avalanche effect. They are slower than table hashes and are used for integrity checks and signatures.

Q20. What are common applications of hashing?

Dictionaries and sets, database indexes, caches, symbol tables in compilers, duplicate detection, file integrity checks, password verification (with dedicated algorithms) and distributed systems.

class LinearTable:

        self.slots = [None] * size
    def insert(self, key):
        for i in range(self.size):
            idx = (key % self.size + i) % self.size
            if self.slots[idx] is None or self.slots[idx] == key:
                self.slots[idx] = key
                return idx
        raise OverflowError("table full")
    def search(self, key):
        for i in range(self.size):
            idx = (key % self.size + i) % self.size
            if self.slots[idx] is None:
                return False
            if self.slots[idx] == key:
                return True
        return False

    for x in s:
        if x - 1 not in s:                 # x starts a new run

            while x + length in s:
                length += 1

    return best

C. Frequently asked questions

What is hashing in data structures?

Hashing maps a key to a table index with a hash function so that data can be stored and found in average constant time. A hash table is the data structure built on this idea.

What is a collision in hashing and how is it resolved?

A collision happens when two keys map to the same index. It is resolved with separate chaining (a list per slot) or open addressing (probing for another free slot with linear probing, quadratic probing or double hashing).

What is the difference between separate chaining and open addressing?

Chaining stores colliding keys in a list outside the array and tolerates a load factor above 1. Open addressing stores everything inside the array, needs load factor below 1 and uses probe sequences.

What is load factor and why does it matter?

Load factor is items divided by table size. A higher value means more collisions and slower operations, so tables are resized (rehashed) when it passes a threshold such as 0.7 or 0.75.

Are Python dictionaries hash tables?

Yes. Python dicts and sets are hash tables with open addressing, and keys must be hashable (immutable). Average lookup, insert and delete are O(1).

Remember
