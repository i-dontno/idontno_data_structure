Introduction to Sorting

What is sorting?

Sorting means arranging the elements of a collection (an array or list) in a defined order, based on a key. The key is the value used to decide the order, such as a number, a name or a date. For example, sorting [38, 27, 43, 3] gives [3, 27, 38, 43].

Why is sorting required?

  • Faster searching: Binary search runs in O(log n), but it works only on sorted data.
  • Easier processing: In sorted data, duplicates sit next to each other. The minimum, maximum and median are also easy to find.
  • Readable output: People find sorted reports, rank lists and directories much easier to read.
  • Building block: Many algorithms sort their data first, for example Kruskal's MST, which sorts the edges by weight.

Internal and external sorting

Internal sorting
All the data fits in main memory (RAM) during sorting. All five algorithms in this blog are internal sorting algorithms.
External sorting
The data is too large for RAM and stays on disk. Chunks are sorted in memory and then merged. External merge sort is the classic method, and it is based on the merge step you will learn in Section 6.

Stable and unstable sorting

A sorting algorithm is stable if records with equal keys keep their original relative order. Stability matters when you sort records by one field after they were already sorted by another.

Original (sorted by name)Sort by marks: stable resultSort by marks: possible unstable result
(Asha, 80), (Ravi, 80), (Meera, 60)(Meera, 60), (Asha, 80), (Ravi, 80)(Meera, 60), (Ravi, 80), (Asha, 80)

Asha and Ravi both have 80. A stable sort keeps Asha before Ravi, as in the original list. Selection Sort actually produces the unstable result here. You will check this in an output-prediction question in Section 8.

Try it in the PlaygroundClick the Duplicates preset. Equal values get small tags (for example 4a, 4b), and when the run ends the visualizer tells you whether their order was preserved. Bubble, Insertion and Merge Sort are stable. Selection and Quick Sort are unstable.

In-place and out-of-place sorting

In-place
Sorts inside the original array using only a constant (or very small) amount of extra memory. Bubble, Selection and Insertion use O(1) extra memory. Quick Sort is also called in-place: its partitioning uses O(1) extra memory, although its recursion stack uses some memory (see Section 5).
Out-of-place (not in-place)
Needs extra memory proportional to n. Merge Sort copies elements into temporary arrays while merging, so it needs O(n) auxiliary space.

Key terms used throughout this blog

ComparisonChecking the order of two elements, e.g. arr[j] > arr[j+1]. It reads values but changes nothing.
SwapExchanging two elements: a[i], a[j] = a[j], a[i]. Used by Bubble, Selection and Quick Sort.
ShiftCopying one element one place to the right: a[j+1] = a[j]. Used by Insertion Sort.
Move (write)Writing an element into the array. In Merge Sort we count each write from a temporary array back into arr.
Auxiliary spaceExtra memory the algorithm uses, not counting the input array.
Total spaceInput array + auxiliary space. All five algorithms need O(n) total space, because the input itself has n elements.
AdaptiveRuns faster when the input is already (nearly) sorted.
PassOne complete scan of the unsorted part of the array.
Counting rule (important for exams and for this blog)A comparison and a swap are different operations, and we never count them together. Exact counts depend on the implementation and on the input. This blog uses one fixed implementation per algorithm, which is the Python code shown in each section. The visualizers run the same logic in JavaScript, so their counts match the Python counts.

Bubble Sort

Concept and working

Bubble Sort repeatedly compares adjacent elements and swaps them if they are in the wrong order. After pass 1, the largest element has "bubbled up" to the last index. After pass 2, the second largest is at the second-last index, and so on. Each pass therefore scans one element fewer than the one before.

Early termination: If a whole pass makes zero swaps, every adjacent pair is in order, so the array is sorted and the algorithm stops. A boolean flag swapped detects this.

Python implementation

def bubble_sort(arr):
    """Sort arr in ascending order (in place) using Bubble Sort."""
    n = len(arr)
    for p in range(n - 1):              # p = pass number (0-based)
        swapped = False
        for j in range(n - 1 - p):      # last p elements are already in place
            if arr[j] > arr[j + 1]:     # adjacent pair in wrong order
                arr[j], arr[j + 1] = arr[j + 1], arr[j]
                swapped = True
        if not swapped:                 # no swap in a full pass -> sorted
            break
    return arr

Space: O(1) auxiliary (only p, j and swapped). Total space is O(n) because of the input. Every swap fixes exactly one inversion (a pair i < j with a[i] > a[j]), so the swap count always equals the number of inversions. A has 11 inversions, which is why we counted 11 swaps.

Advantages and disadvantages

✅ Advantages

  • Very simple to understand and code.
  • Stable and in-place (O(1) extra memory).
  • Adaptive: O(n) on sorted input with the swapped flag.
  • Easy to see when an array is already sorted.

❌ Disadvantages

  • O(n²) average and worst case, so it is too slow for large n.
  • Makes many swaps (one per inversion).
  • Usually slower than Insertion Sort, even on small inputs.
Exam pointsWithout the swapped flag, the best case becomes O(n²). Using >= instead of > would swap equal elements and make Bubble Sort unstable. After k passes, the k largest elements are in their final positions.

Selection Sort

Concept and working

Selection Sort divides the array into a sorted portion (left) and an unsorted portion (right). In each pass, it selects the minimum element of the unsorted portion and swaps it into the first unsorted position. The sorted portion then grows by one. Elements in the sorted portion are already in their final positions.

Selecting the minimum element

To fill index i, first assume min_idx = i. Then scan j = i+1 … n−1. Whenever a[j] < a[min_idx], update min_idx = j. This scan always takes n − 1 − i comparisons, whatever the data. At the end of the scan, do at most one swap. For descending order, select the maximum instead.

SelectionSort(A, n) 1 for i ← 0 to n − 2 2 min_idx ← i 3 for j ← i + 1 to n − 1 4 if A[j] < A[min_idx] ▷ use > for descending 5 min_idx ← j 6 if min_idx ≠ i 7 swap A[i] and A[min_idx]

Python implementation

def selection_sort(arr):
    """Sort arr in ascending order (in place) using Selection Sort."""
    n = len(arr)
    for i in range(n - 1):              # position to be filled
        min_idx = i                     # assume arr[i] is the minimum
        for j in range(i + 1, n):       # search the unsorted portion
            if arr[j] < arr[min_idx]:
                min_idx = j
        if min_idx != i:                # one swap per pass (at most)
            arr[i], arr[min_idx] = arr[min_idx], arr[i]
    return arr

def selection_sort(arr, ascending=True):
    """Sort arr in place. Returns (comparisons, swaps)."""
    n = len(arr)
    comparisons = swaps = 0
    for i in range(n - 1):
        best = i          # index of minimum (ascending) or maximum (descending)
        for j in range(i + 1, n):
            comparisons += 1
            if ascending:
                better = arr[j] < arr[best]
            else:
                better = arr[j] > arr[best]
            if better:
                best = j
        if best != i:
            arr[i], arr[best] = arr[best], arr[i]
            swaps += 1
    return comparisons, swaps

Time and space complexity

The comparison count is the same for every input: (n−1) + (n−2) + … + 1 = n(n−1)/2. That is why Selection Sort is not adaptive. Space: O(1) auxiliary.

Advantages and disadvantages

✅ Advantages

  • At most n − 1 swaps, the fewest writes of the five algorithms. Useful when writing to memory is expensive.
  • In-place, O(1) extra memory.
  • Simple and predictable: the same comparison count every time.

❌ Disadvantages

  • O(n²) even when the input is already sorted.
  • Unstable: the long-distance swap can jump an element over an equal one. Example: [4ₐ, 4ᵦ, 2] → [2, 4ᵦ, 4ₐ].
  • Not adaptive.
Exam points"Number of comparisons in Selection Sort for n elements" = n(n−1)/2. For n = 10, that is 45. After k passes, the first k positions hold the k smallest elements in their final order.

Insertion Sort

Concept and working

Insertion Sort works the way most people sort playing cards in their hand. Take the next card (the key), slide the larger cards in the hand one place to the right, and drop the key into the gap.

Sorted and unsorted portions

Before iteration i, the portion a[0..i−1] is sorted among itself, and a[i..n−1] is unsorted. Unlike Selection Sort, the sorted portion is not final: a later key may still be inserted into the middle of it. Each iteration grows the sorted portion by one element.

Algorithm / pseudocode

InsertionSort(A, n) 1 for i ← 1 to n − 1 2 key ← A[i] 3 j ← i − 1 4 while j ≥ 0 and A[j] > key ▷ use < for descending 5 A[j + 1] ← A[j] ▷ shift right 6 j ← j − 1 7 A[j + 1] ← key ▷ insert into the gap

Python implementation

def insertion_sort(arr):
    """Sort arr in ascending order (in place) using Insertion Sort."""
    for i in range(1, len(arr)):        # arr[0..i-1] is the sorted portion
        key = arr[i]                    # element to be inserted
        j = i - 1
        while j >= 0 and arr[j] > key:  # shift larger elements right
            arr[j + 1] = arr[j]
            j -= 1
        arr[j + 1] = key                # insert key into the gap
    return arr

def insertion_sort(arr, ascending=True):
    """Sort arr in place. Returns (comparisons, shifts)."""
    comparisons = shifts = 0
    for i in range(1, len(arr)):
        key = arr[i]
        j = i - 1
        while j >= 0:
            comparisons += 1
            if ascending:
                should_shift = arr[j] > key
            else:
                should_shift = arr[j] < key
            if not should_shift:
                break
            arr[j + 1] = arr[j]     # shift one place right
            shifts += 1
            j -= 1
        arr[j + 1] = key            # place the key in the gap
    return comparisons, shifts

✅ Advantages

  • Adaptive: O(n) on sorted or nearly sorted input.
  • Stable and in-place.
  • Online: it can sort data as it arrives, one element at a time.
  • Very fast for small n. Hybrid algorithms (e.g. Python's built-in Timsort) use it for small runs.

❌ Disadvantages

  • O(n²) average and worst case.
  • Many shifts when the data is in reverse order.

Quick Sort

Concept and working

Quick Sort is a Divide and Conquer algorithm. It picks one element as the pivot and partitions the subarray so that every element ≤ pivot is on its left and every element > pivot is on its right. The pivot is then in its final position. Quick Sort recursively sorts the left and right parts, and no merge step is needed.

Pivot selection

This blog's implementation uses the last element as the pivot (the Lomuto scheme), because it is the simplest to trace in exams. Other common choices are the first element, the middle element, a random element, or the median of three (the median of the first, middle and last elements).

Pivot selection affects performanceA good pivot splits the subarray into two nearly equal halves, which gives O(n log n). A bad pivot (always the smallest or largest value) leaves one side empty, which gives O(n²). With a last-element pivot, an already sorted or reverse sorted array is the worst case. Choose a pivot rule in the visualizer and the Comparison Lab to see the difference: on sorted input of size 1000, last-element pivot needs 499,500 comparisons, while median-of-three needs only about 9,000.

Partitioning process (Lomuto)

  1. Let pivot = a[high] and i = low − 1. The index i marks the end of the "≤ pivot" region.
  2. For j = low … high−1: if a[j] ≤ pivot, increase i and swap a[i] ↔ a[j]. This implementation skips the swap when i = j.
  3. Finally, swap a[i+1] ↔ a[high]. The pivot now sits at index i+1, which is its final index.

Recursive calls

After partitioning returns p, call quick_sort(low, p−1) and quick_sort(p+1, high). The recursion stops when low ≥ high, that is, when the subarray has 0 or 1 elements.

Python implementation

def partition(arr, low, high):
    """Lomuto partition: last element is the pivot."""
    pivot = arr[high]
    i = low - 1                         # end of the "<= pivot" region
    for j in range(low, high):
        if arr[j] <= pivot:
            i += 1
            if i != j:
                arr[i], arr[j] = arr[j], arr[i]
    if i + 1 != high:                   # put pivot in its final place
        arr[i + 1], arr[high] = arr[high], arr[i + 1]
    return i + 1


def quick_sort(arr, low, high):
    if low < high:                      # 2 or more elements
        p = partition(arr, low, high)
        quick_sort(arr, low, p - 1)     # left of pivot
        quick_sort(arr, p + 1, high)    # right of pivot
    return arr

            i += 1
            if i != j:
                arr[i], arr[j] = arr[j], arr[i]
                stats["swaps"] += 1
    if i + 1 != high:
        arr[i + 1], arr[high] = arr[high], arr[i + 1]
        stats["swaps"] += 1
    return i + 1


def quick_sort(arr, low, high, ascending=True, stats=None):
    """Sort arr[low..high] in place. Returns {'comparisons', 'swaps'}."""
    if stats is None:
        stats = {"comparisons": 0, "swaps": 0}
    if low < high:
        p = partition(arr, low, high, ascending, stats)
        quick_sort(arr, low, p - 1, ascending, stats)
        quick_sort(arr, p + 1, high, ascending, stats)
    return stats

Recursion limit in PythonPython's default recursion limit is about 1000. With a last-element pivot, an already sorted list makes the recursion n levels deep. So this program raises RecursionError for a sorted list of around 1000 or more elements (we tested 1500). Using a random or median-of-three pivot, or recursing on the smaller part first, avoids the problem.

Advantages and disadvantages

✅ Advantages

  • O(n log n) on average and very fast in practice (good cache behaviour, few swaps).
  • In-place partitioning, so no extra arrays.
  • Widely used in standard libraries (often as part of hybrid algorithms).

❌ Disadvantages

  • O(n²) worst case with poor pivots.
  • Unstable: long-distance swaps reorder equal keys.
  • Lomuto partition slows down badly when there are many duplicate keys.
  • Deep recursion on bad inputs.
Exam pointsAfter one partition, only the pivot is guaranteed to be in its final position. Quick Sort does its work before the recursion (partitioning), while Merge Sort does its work after the recursion (merging).

Merge Sort

Concept and working

Merge Sort splits the array into two halves, sorts each half recursively, and then merges the two sorted halves into one sorted array. An array with one element is already sorted, which is the base case.

Divide and Conquer approach

1. Divide
Find mid = (low + high) // 2 and split into a[low..mid] and a[mid+1..high].
2. Conquer
Recursively sort both halves until each part has one element.
3. Combine
Merge the two sorted halves into one sorted subarray.

mid = (0+6)//2 = 3, so the left half has 4 elements and the right half has 3.

Merging sorted subarrays

Keep one pointer i in the left half and one pointer j in the right half. Compare left[i] with right[j], write the smaller one into arr[k], and advance that pointer. When one half runs out, copy the rest of the other half. These leftover copies need no comparisons. Using <= takes the left element when values are equal, and this is what keeps Merge Sort stable.

Final merge in detail

3 vs 9 → take 3 · 27 vs 9 → take 9 · 27 vs 10 → take 10 · 27 vs 82 → take 27 · 38 vs 82 → take 38 · 43 vs 82 → take 43 · the left half is exhausted → copy 82 (no comparison). That is 6 comparisons and 7 moves.

Algorithm / pseudocode

MergeSort(A, low, high) 1 if low < high 2 mid ← ⌊(low + high) / 2⌋ 3 MergeSort(A, low, mid) 4 MergeSort(A, mid + 1, high) 5 Merge(A, low, mid, high) Merge(A, low, mid, high) 1 L ← A[low..mid]; R ← A[mid+1..high] ▷ temporary copies 2 i ← 0; j ← 0; k ← low 3 while i < |L| and j < |R| 4 if L[i] ≤ R[j] then A[k] ← L[i]; i ← i + 1 5 else A[k] ← R[j]; j ← j + 1 6 k ← k + 1 7 copy remaining L[i..] then remaining R[j..] into A[k..]

def merge(arr, low, mid, high):
    left = arr[low:mid + 1]             # copy of sorted left half
    right = arr[mid + 1:high + 1]       # copy of sorted right half
    i = j = 0
    k = low
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:         # '<=' keeps Merge Sort stable
            arr[k] = left[i]
            i += 1
        else:
            arr[k] = right[j]
            j += 1
        k += 1
    while i < len(left):                # copy leftovers
        arr[k] = left[i]
        i += 1
        k += 1
    while j < len(right):
        arr[k] = right[j]
        j += 1
        k += 1


def merge_sort(arr, low, high):
    if low < high:
        mid = (low + high) // 2
        merge_sort(arr, low, mid)       # sort left half
        merge_sort(arr, mid + 1, high)  # sort right half
        merge(arr, low, mid, high)      # merge the two halves
    return arr

    right = arr[mid + 1:high + 1]
    i = j = 0
    k = low

Time and space complexity

CaseComparisonsMoves (writes into arr)Time
Best≈ (n/2) log₂ n (each merge stops when one side runs out early)≈ n log₂ nO(n log n)
Average≈ n log₂ n≈ n log₂ nO(n log n)
Worst≤ n⌈log₂ n⌉ − 2⌈log₂ n⌉ + 1≈ n log₂ nO(n log n)

The recursion has about log₂ n levels, and each level merges all n elements, which gives n log n. The recurrence is T(n) = 2T(n/2) + O(n), which solves to T(n) = O(n log n) for every input.

Additional memory requirementThe temporary left and right lists together hold up to n elements during the final merge, so auxiliary space is O(n). The recursion stack adds O(log n), which does not change the overall O(n). That is why Merge Sort is out-of-place. (The moves column counts only writes back into arr. Copying into the temporary lists is extra work that we do not count.)

Advantages and disadvantages

✅ Advantages

  • Guaranteed O(n log n) in every case.
  • Stable.
  • Ideal for linked lists and for external sorting of huge files.
  • Predictable performance.

❌ Disadvantages

  • Needs O(n) extra memory.
  • Not adaptive in this standard form: sorted input still takes O(n log n).
  • Copying overhead makes it slower than Insertion Sort for very small arrays.

Practice and Assessment

A. Conceptual questions

1. Why is Insertion Sort preferred over Bubble Sort for nearly sorted data, even though both are O(n²)?Both make one swap or shift per inversion, but Insertion Sort stops scanning as soon as it finds the key's place, so it makes fewer comparisons. A shift is also one assignment, while a swap is three. On nearly sorted data, Insertion Sort runs in close to O(n).
2. Explain why Selection Sort is not stable, with an example.The swap in each pass can carry an element far to the right, past an equal element. For [4ₐ, 4ᵦ, 2]: pass 1 swaps 4ₐ with 2, giving [2, 4ᵦ, 4ₐ]. Pass 2 makes no swap. The final order 4ᵦ, 4ₐ reverses the original order of the two 4s.
3. What is the difference between auxiliary space and total space? Give both for Merge Sort.Auxiliary space is the extra memory beyond the input. Total space = input + auxiliary. For Merge Sort, auxiliary space is O(n) (temporary lists, plus an O(log n) stack), and total space is O(n) + O(n) = O(n).
4. Why does Quick Sort with a last-element pivot perform worst on an already sorted array?The last element is the largest, so every partition puts all other elements on the left and none on the right. Subarray sizes shrink by only one per call: n−1, n−2, …, 1. That gives n(n−1)/2 comparisons, which is O(n²), and a recursion depth of n.
5. Quick Sort and Merge Sort are both Divide and Conquer. How do they differ?Quick Sort does the hard work before recursing (partitioning) and needs no combine step. Its split can be unbalanced, so it can degrade to O(n²). Merge Sort always splits in the middle and does the work after recursing (merging). It always runs in O(n log n), but it needs O(n) extra memory.
6. Which algorithm would you use to sort 1 million records that do not fit in RAM? Why?External merge sort. Sort chunks that fit in memory, write them to disk as sorted "runs", then merge the runs. Merging reads each run sequentially, which suits disk access.

Q1. Bubble Sort counts

def bubble_sort(arr):
    n = len(arr)
    comparisons = swaps = 0
    for p in range(n - 1):
        swapped = False
        for j in range(n - 1 - p):
            comparisons += 1
            if arr[j] > arr[j + 1]:
                arr[j], arr[j + 1] = arr[j + 1], arr[j]
                swaps += 1
                swapped = True
        if not swapped:
            break
    return comparisons, swaps

Q2. Insertion Sort on sorted and reverse input

Python
def insertion_sort(arr):
    comparisons = shifts = 0
    for i in range(1, len(arr)):
        key = arr[i]
        j = i - 1
        while j >= 0:
            comparisons += 1
            if arr[j] <= key:
                break
            arr[j + 1] = arr[j]
            shifts += 1
            j -= 1
        arr[j + 1] = key
    return comparisons, shifts

print(insertion_sort([10, 20, 30, 40, 50]))
print(insertion_sort([50, 40, 30, 20, 10]))
Show output
(4, 0)

Sorted input: one comparison per key and no shifts, so n − 1 = 4 comparisons. Reverse input: every key moves to the front: 1+2+3+4 = 10 comparisons and 10 shifts = n(n−1)/2.

Q3. Is Selection Sort stable?

Python
def selection_sort_by_marks(rec):
    n = len(rec)
    for i in range(n - 1):
        m = i
        for j in range(i + 1, n):
            if rec[j][1] < rec[m][1]:
                m = j
        if m != i:
            rec[i], rec[m] = rec[m], rec[i]
    return rec

Pass 1 swaps Asha (index 0) with Meera (index 2), which moves Asha behind Ravi. Both have 80, so their original order is lost. This shows that Selection Sort is unstable.

Q4. Lomuto partition

Python
def partition(arr, low, high):
    pivot = arr[high]
    i = low - 1
    for j in range(low, high):
        if arr[j] <= pivot:
            i += 1
            if i != j:
                arr[i], arr[j] = arr[j], arr[i]
    if i + 1 != high:
        arr[i + 1], arr[high] = arr[high], arr[i + 1]
    return i + 1

data = [7, 2, 9, 4, 5]
p = partition(data, 0, len(data) - 1)
print(p, data)
Show output
2 [2, 4, 5, 7, 9]
Pivot = 5. 7 stays; 2 → i=0, swap with 7; 9 stays; 4 → i=1, swap with 7. Finally the pivot is swapped into index 2. Here one partition happens to sort the whole list. That is just a coincidence of this input.

Q5. Merging two sorted lists

def merge_lists(left, right):
    result = []
    i = j = comparisons = 0
    while i < len(left) and j < len(right):
        comparisons += 1
        if left[i] <= right[j]:
            result.append(left[i]); i += 1
        else:
            result.append(right[j]); j += 1
    result.extend(left[i:])
    result.extend(right[j:])
    return result, comparisons

print(merge_lists([1, 4, 9], [2, 3, 10]))

The comparisons are 1-2, 4-2, 4-3, 4-10 and 9-10. After that, the left list is empty, and 10 is copied without a comparison.
