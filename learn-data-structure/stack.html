Introduction to Stacks

Definition

A stack is a linear data structure in which elements are inserted and deleted at only one end, called the top. The element inserted last is the first one to be removed. This principle is called LIFO: Last In, First Out (equivalently, FILO: First In, Last Out).

Picture a pile of plates in a canteen. You put a clean plate on the top of the pile, and you also take a plate from the top. You can't pull a plate out from the middle or the bottom without first removing everything above it. That restriction, one entry point that is also the exit point, is exactly what defines a stack.

Figure 1: A stack holding 10, 20, 30, 40. Push adds on top; pop removes from the top. 40 went in last, so it comes out first.

Why do we need a stack?

Many problems naturally need to remember things and come back to them in reverse order:

  • When function A calls B, and B calls C, the computer must return to B first, then A: the most recent call finishes first.
  • When you press Undo, the latest change is reversed first.
  • When checking { [ ( ) ] }, the most recently opened bracket must be the first one closed.

A stack gives exactly this behaviour with very simple, very fast operations.

Why are stacks important?

  • Every running program uses a call stack to manage function calls, local variables and recursion.
  • Compilers use stacks to parse and evaluate expressions and to check syntax.
  • All core operations take O(1) time, so stacks are among the most efficient data structures.
  • Stacks are a classic example of an Abstract Data Type (ADT): defined by behaviour, implementable in several ways.

Core Concepts & Representations

Terminology

TermMeaning
TopThe end where all insertions and deletions happen. In an array it is an index; in a linked list it is a pointer to the first node.
PushInsert an element on top of the stack.
PopRemove and return the top element.
Peek / TopReturn the top element without removing it.
isEmptyTrue if the stack has no elements.
isFullTrue if a fixed-size (array) stack has no free space. A linked stack is full only when memory runs out.
OverflowError: trying to push onto a full stack.
UnderflowError: trying to pop (or peek) from an empty stack.
MAX / capacityThe maximum number of elements an array stack can hold.

Stack as an Abstract Data Type (ADT)

An ADT specifies what operations a data type supports and how they behave, without saying how they are implemented. The Stack ADT is:

OperationDescriptionError condition
push(x)Place x on topOverflow if full
pop()Remove and return top elementUnderflow if empty
peek()Return top element, stack unchangedEmpty stack
isEmpty()Is the stack empty?none
isFull()Is the stack full? (array version)none
size()Number of elementsnone

The same ADT can be implemented in two standard ways, with an array / list or with a linked list.

1. Array (list) representation

The elements are stored in an array S[0 … MAX−1] and an integer variable top holds the index of the top element.

  • Empty stack: top = −1
  • Full stack: top = MAX − 1
  • Number of elements: top + 1
  • The bottom element is always S[0]; the stack grows toward higher indices.

In Python, a list can play this role directly: append() pushes and pop() pops at the end of the list, and len(list) − 1 is the top index. Because a Python list grows automatically, a list stack never overflows; to study overflow, Program 2 uses a fixed-capacity list.

2. Linked list representation

Each element is a node [data | next]. A pointer top points to the first node, which is the top of the stack.

  • Push = insert at beginning of the linked list.
  • Pop = delete at beginning of the linked list.
  • Empty stack: top = NULL. There is no fixed MAX: the stack grows until memory is exhausted.
Why the beginning, not the end?

In a singly linked list, inserting and deleting at the beginning are O(1). Deleting at the end needs the second-last node, which costs O(n). So the head of the list is always used as the top of the stack.

Operations & Algorithms

Below are the algorithms for every stack operation, for both implementations. Array algorithms use 0-based indexing with top = −1 for an empty stack. GETNODE() allocates a node and FREE(p) releases one.

PUSH O(1)

First check for overflow. Then move top up by one and store the item in that cell. The order matters: increment first, then store. (Storing at S[top] before incrementing would overwrite the current top.)

ALGORITHM PUSH(S, top, MAX, item)          // array / list
1. if top = MAX − 1: print "OVERFLOW"; exit
2. top ← top + 1
3. S[top] ← item
4. exit

POP O(1)

First check for underflow. Read the top item, then move top down by one. The value is not physically erased; the cell is simply treated as free and will be overwritten by the next push.

ALGORITHM POP(S, top)                      // array / list
1. if top = −1: print "UNDERFLOW"; exit
2. item ← S[top]
3. top ← top − 1
4. return item

PEEK (TOP) O(1)

Return S[top] without changing top. Useful when you need to look at the latest element before deciding what to do, for example comparing operator precedence during expression conversion.

ALGORITHM PEEK(S, top)                     // array / list
1. if top = −1: print "STACK EMPTY"; exit
2. return S[top]

IS_EMPTY and IS_FULL O(1)

Both just compare top with a boundary value.

ALGORITHM IS_EMPTY(top)                   // array / list
1. if top = −1: return TRUE
2. else: return FALSE
ALGORITHM IS_FULL(top, MAX)                // array / list
1. if top = MAX − 1: return TRUE
2. else: return FALSE

DISPLAY (traversal) O(n)

Print elements from top down to index 0, so the output shows the stack in pop order.

ALGORITHM DISPLAY(S, top)                  // array / list
1. if top = −1: print "STACK EMPTY"; exit
2. i ← top
3. while i ≥ 0:
4.     print S[i]
5.     i ← i − 1

PUSH O(1)

Create a node, make it point to the current top, then move top to the new node. This is "insert at beginning" of a singly linked list. Overflow happens only if no memory is available.

ALGORITHM PUSH(top, item)                  // linked list
1. newNode ← GETNODE()
2. if newNode = NULL: print "OVERFLOW (no free memory)"; exit
3. newNode.data ← item
4. newNode.next ← top
5. top ← newNode

POP O(1)

Check for underflow, remember the top node in temp, move top to the next node, then free the old node. This is "delete at beginning".

ALGORITHM POP(top)                         // linked list
1. if top = NULL: print "UNDERFLOW"; exit
2. temp ← top
3. item ← temp.data
4. top ← top.next
5. FREE(temp)
6. return item

PEEK (TOP) O(1)

ALGORITHM PEEK(top)                        // linked list
1. if top = NULL: print "STACK EMPTY"; exit
2. return top.data

IS_EMPTY O(1)

A linked stack has no IS_FULL operation in the usual sense: it is full only when GETNODE fails.

ALGORITHM IS_EMPTY(top)                    // linked list
1. if top = NULL: return TRUE
2. else: return FALSE

DISPLAY (traversal) O(n)

ALGORITHM DISPLAY(top)                     // linked list
1. if top = NULL: print "STACK EMPTY"; exit
2. temp ← top
3. while temp ≠ NULL:
4.     print temp.data
5.     temp ← temp.next

* When a Python list runs out of reserved space, append copies all elements to a bigger block (O(n)). This happens rarely, so the average cost per push stays O(1): this is called amortised O(1).

There are no best/average/worst-case differences for push, pop and peek: they always do a fixed amount of work.

Space complexity

  • Array stack: O(MAX) memory is reserved up front, even when the stack holds fewer elements.
  • Linked stack: O(n) memory for n elements, plus one pointer per node.
  • Each operation uses O(1) auxiliary space.

Applications, Advantages & Disadvantages

Applications of stacks

1. Function calls & recursion

Each call pushes an activation record (parameters, local variables, return address) onto the call stack; returning pops it. Too deep recursion causes a stack overflow.

2. Balanced brackets / syntax checking

Compilers and editors push opening brackets and pop on closing ones to verify that ( ) [ ] { } match.

3. Expression conversion

Infix expressions (a + b * c) are converted to postfix (a b c * +) or prefix using an operator stack.

4. Expression evaluation

Postfix expressions are evaluated with an operand stack: push numbers, and on an operator pop two, compute, push the result.

5. Undo / redo

Each action is pushed; Undo pops the latest. A second stack holds actions for Redo.

6. Browser back / forward

Back pops from the history stack and pushes onto a forward stack.

7. Reversing data

Push all characters of a word, then pop them: they come out reversed.

8. Backtracking

Maze solving, puzzles (N-Queens) and depth-first search remember choices on a stack so they can go back.

9. Number conversion

Decimal to binary: push remainders of division by 2, then pop to read the binary digits in the correct order.

10. Memory management

Local variables of functions are allocated on the program's stack memory and released automatically on return.

Advantages of stacks

✔ Very fast operations

push, pop, peek, isEmpty all run in O(1) time.

✔ Simple to implement

An array with a top index, or a linked list with a top pointer, is enough.

✔ Natural for reversal and nesting

Matches problems where the latest item must be handled first.

✔ Controlled access

Only the top is reachable, which prevents accidental changes to other elements.

✔ Automatic memory handling

The call stack allocates and frees local variables without programmer effort.

✔ Backbone of many algorithms

Recursion, DFS, parsing and expression evaluation rely on stacks.

Disadvantages of stacks

✘ No random access

To reach an element in the middle, everything above it must be popped first.

✘ Fixed size (array version)

Overflow occurs at MAX; reserving too much wastes memory.

✘ Extra memory (linked version)

Each node needs a pointer in addition to the data.

✘ Searching is slow

Finding a value requires scanning (and, strictly, popping) elements: O(n).

✘ Stack overflow in recursion

Very deep or infinite recursion exhausts the call stack and crashes the program.

✘ Limited operations

Not suitable when elements must be inserted or removed in the middle.

Special cases & edge cases

SituationCorrect behaviour
Pop or peek on an empty stackReport UNDERFLOW / STACK EMPTY; do not change top.
Push when top = MAX − 1 (array)Report OVERFLOW; the stack is unchanged.
Stack with one elementAfter pop, top becomes −1 (array) or NULL (linked list).
Python list stackNever overflows (it resizes), but pop() on an empty list raises IndexError: check isEmpty first.
MAX = 0Every push overflows: the stack is always both empty and full.

Common mistakes

Watch out
  • Wrong order in PUSH: writing S[top] ← item before top ← top + 1 overwrites the current top element.
  • Wrong order in POP: decrementing top before reading S[top] returns the wrong element.
  • Starting top at 0 while also using the "top = −1 means empty" checks: the first element is lost or the empty test fails.
  • Using the front of a Python list (insert(0, x) / pop(0)) as the top: still LIFO, but each operation becomes O(n).
  • Using the tail of a singly linked list as top: pop becomes O(n). Always push and pop at the head.
  • Forgetting the underflow / overflow checks in algorithms: examiners expect both.

Important examination points

Remember for exams
  • Stack = LIFO; all insertions and deletions at the top.
  • Array stack: empty when top = −1, full when top = MAX − 1, size = top + 1.
  • Linked stack: push = insert at beginning, pop = delete at beginning, empty when top = NULL.
  • push, pop, peek, isEmpty are all O(1) in both implementations.
  • For a sequence of pushes and pops, a value can only be popped after everything pushed after it has been popped. This rule decides which output orders are possible.
  • The system call stack is why recursion works and why infinite recursion causes "stack overflow".

# Program 1: Stack using a Python list (dynamic size)
# The END of the list is the TOP of the stack, so push and pop are O(1).

class ListStack:
    def __init__(self):
        self.items = []                 # empty stack

    def is_empty(self):
        return len(self.items) == 0

    def push(self, item):
        self.items.append(item)         # add on top

    def pop(self):
        if self.is_empty():
            raise IndexError("Underflow: stack is empty")
        return self.items.pop()         # remove from top

    def peek(self):
        if self.is_empty():
            raise IndexError("Stack is empty")
        return self.items[-1]           # read top without removing

    def size(self):
        return len(self.items)

    def display(self):
        if self.is_empty():
            print("  (empty stack)")
            return
        print("  TOP ->", " | ".join(str(x) for x in reversed(self.items)), "<- BOTTOM")


s = ListStack()
print("Empty?", s.is_empty())
for x in [10, 20, 30]:
    s.push(x)
    print(f"push({x})")
s.display()
print("peek() ->", s.peek())
print("pop()  ->", s.pop())
s.display()
print("size() ->", s.size())
s.pop(); s.pop()
print("Empty?", s.is_empty())
try:
    s.pop()
except IndexError as e:
    print("pop() ->", e)

# Program 2: Stack using a fixed-size array (list of fixed capacity)
# This follows the textbook algorithms exactly: a 'top' index that starts at -1,
# with OVERFLOW when the array is full and UNDERFLOW when it is empty.

class ArrayStack:
    def __init__(self, max_size):
        self.MAX = max_size
        self.S = [None] * max_size      # reserve all cells up front
        self.top = -1                   # -1 means the stack is empty

    def is_empty(self):
        return self.top == -1

    def is_full(self):
        return self.top == self.MAX - 1

    def push(self, item):
        if self.is_full():
            print(f"  push({item}) -> OVERFLOW: stack is full")
            return
        self.top += 1                   # 1. move top up
        self.S[self.top] = item         # 2. store the item there
        print(f"  push({item}) -> top = {self.top}")

    def pop(self):
        if self.is_empty():
            print("  pop() -> UNDERFLOW: stack is empty")
            return None
        item = self.S[self.top]         # 1. read the top item
        self.S[self.top] = None         #    (optional: clear the cell)
        self.top -= 1                   # 2. move top down
        print(f"  pop() -> {item}, top = {self.top}")
        return item

    def peek(self):
        if self.is_empty():
            return None
        return self.S[self.top]

    def display(self):
        if self.is_empty():
            print("  (empty stack)")
            return
        for i in range(self.top, -1, -1):          # from top down to 0
            marker = "  <- top" if i == self.top else ""
            print(f"  S[{i}] = {self.S[i]}{marker}")


st = ArrayStack(4)
for x in [5, 15, 25, 35, 45]:          # the 5th push overflows

print("Stack contents:")
st.display()
print("peek() ->", st.peek())
for _ in range(5):                     # the 5th pop underflows
    st.pop()
print("is_empty() ->", st.is_empty())

# Program 3: Stack using a singly linked list
# 'top' plays the role of head: push = insert at beginning, pop = delete at beginning.
# Both are O(1), and there is no fixed capacity.

class Node:
    def __init__(self, data):
        self.data = data
        self.next = None


class LinkedStack:
    def __init__(self):
        self.top = None                 # empty stack
        self.count = 0

    def is_empty(self):
        return self.top is None

    def push(self, item):
        new_node = Node(item)           # GETNODE (Python raises MemoryError if none)
        new_node.next = self.top        # new node points to the old top
        self.top = new_node             # top now points to the new node
        self.count += 1

    def pop(self):
        if self.is_empty():
            raise IndexError("Underflow: stack is empty")
        temp = self.top
        self.top = temp.next            # second node becomes the top
        self.count -= 1
        return temp.data                # temp is freed automatically

    def peek(self):
        if self.is_empty():
            raise IndexError("Stack is empty")
        return self.top.data

    def size(self):
        return self.count

    def display(self):
        temp, parts = self.top, []
        while temp:
            parts.append(str(temp.data))
            temp = temp.next
        print("  top -> " + " -> ".join(parts + ["NULL"]))


ls = LinkedStack()
for x in ["A", "B", "C", "D"]:
    ls.push(x)
    print(f"push({x!r})")
ls.display()
print("peek() ->", ls.peek(), "| size() ->", ls.size())
print("pop()  ->", ls.pop())
print("pop()  ->", ls.pop())
ls.display()
print("size() ->", ls.size())
while not ls.is_empty():
    ls.pop()
ls.display()
try:
    ls.peek()
except IndexError as e:
    print("peek() ->", e)

Four classic stack applications: bracket matching, string reversal, decimal-to-binary conversion and postfix evaluation.

# Program 4: Applications of stacks
#  (a) Balanced brackets checker
#  (b) Reverse a string
#  (c) Decimal to binary conversion
#  (d) Evaluate a postfix expression

def is_balanced(expr):
    pairs = {')': '(', ']': '[', '}': '{'}
    stack = []
    for ch in expr:
        if ch in '([{':
            stack.append(ch)                    # opening bracket: push
        elif ch in ')]}':
            if not stack or stack[-1] != pairs[ch]:
                return False                    # nothing to match, or wrong type
            stack.pop()                         # matched: pop its partner
    return len(stack) == 0                      # leftovers mean unmatched '('

def reverse_string(text):
    stack = []
    for ch in text:
        stack.append(ch)                        # push every character
    out = ""
    while stack:
        out += stack.pop()                      # pop gives them back in reverse
    return out

def to_binary(n):
    if n == 0:
        return "0"
    stack = []
    while n > 0:
        stack.append(n % 2)                     # push remainders
        n //= 2
    return "".join(str(stack.pop()) for _ in range(len(stack)))

def eval_postfix(tokens):
    stack = []
    for tok in tokens.split():
        if tok.lstrip('-').isdigit():
            stack.append(int(tok))              # operand: push
        else:
            b = stack.pop()                     # right operand comes off first
            a = stack.pop()
            if tok == '+': stack.append(a + b)
            elif tok == '-': stack.append(a - b)
            elif tok == '*': stack.append(a * b)
            elif tok == '/': stack.append(a // b)
    return stack.pop()


for e in ["{[a+b]*(c-d)}", "(a+b))", "([)]", "((a)"]:
    print(f"{e:16} balanced? {is_balanced(e)}")
print("reverse('STACK')  =", reverse_string("STACK"))
print("binary of 13      =", to_binary(13))
print("postfix 2 3 4 * + =", eval_postfix("2 3 4 * +"))
print("postfix 5 1 2 + 4 * + 3 - =", eval_postfix("5 1 2 + 4 * + 3 -"))

Practice & Assessment

A. Conceptual questions

1. Define a stack. Why is it called a LIFO structure?

A stack is a linear data structure where insertion and deletion happen only at one end, the top. The last element inserted is the first removed, hence Last In, First Out.

2. What are overflow and underflow? When does each occur in array and linked implementations?

Overflow: pushing onto a full stack (array: top = MAX − 1; linked list: no free memory, GETNODE returns NULL). Underflow: popping from an empty stack (array: top = −1; linked list: top = NULL).

3. Why is the head of a singly linked list used as the top of a stack?

Insertion and deletion at the head are O(1). Using the tail would make pop O(n), because the second-last node must be found.

4. Explain how a stack is used in function calls.

Each call pushes an activation record (parameters, locals, return address) onto the call stack. When the function returns, its record is popped and control goes back to the caller, whose record is now on top.

5. Compare the array and linked list implementations of a stack.

Array: fixed size, overflow at MAX, no pointer overhead, better cache use, possible wasted space. Linked list: dynamic size, no overflow until memory runs out, extra pointer per node. Both give O(1) push and pop.

Q2. A stack's output order is to be "3 2 1" after pushing 1, 2, 3 in that order. Is "3 1 2" also possible?

Show answer

"3 2 1": push 1, 2, 3, then pop three times. "3 1 2" is not possible: to pop 3 first, 1 and 2 must still be in the stack with 2 above 1, so 2 must come out before 1.
