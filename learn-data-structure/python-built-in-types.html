Introduction to Python Data Types

Definition

A data type tells Python what kind of value an object holds and what you are allowed to do with it. For example, you can add two numbers, join two strings, or loop over a list, but you cannot divide a string by a list. Every value in Python is an object, and every object has a type.

Why are data types important?

  • Correct operations: 5 + 3 adds numbers, "5" + "3" joins text. The type decides the meaning of the operator.
  • Memory and speed: choosing a set for lookups or a list for ordered items changes how fast your program runs.
  • Fewer bugs: knowing whether a value can change (mutable) or not (immutable) prevents surprising results.
  • Foundation for DSA: stacks, queues, graphs and hash tables are all built from lists, dictionaries and sets.

How Python handles types: dynamic typing

In Python you never declare a type. You just write x = 10. The type belongs to the object, not to the name. A name is just a label that can point to a different object later. Python checks types at run time, which is why this is called dynamic typing.

x = 10
print(x, type(x))
x = "ten"
print(x, type(x))
x = [1, 2, 3]
print(x, type(x))
Output
10 <class 'int'>
ten <class 'str'>
[1, 2, 3] <class 'list'>
Strongly typed too

Python is dynamically typed and strongly typed. It will not silently mix incompatible types: "5" + 5 raises a TypeError instead of guessing. You will see this in Section 6.

Real-world example: one student, many types

A single student record uses almost every common type. Each field is stored in the type that fits it best.

student = {
    "name": "Asha",                          # str
    "age": 20,                               # int
    "cgpa": 8.7,                             # float
    "is_placed": False,                      # bool
    "subjects": ["DSA", "Python", "DBMS"],   # list
    "mentor": None,                          # NoneType
}
for key, value in student.items():
    print(f"{key:10} -> {value!r:32} {type(value).__name__}")
Output
name       -> 'Asha'                           str
age        -> 20                               int
cgpa       -> 8.7                              float
is_placed  -> False                            bool
subjects   -> ['DSA', 'Python', 'DBMS']        list
mentor     -> None                             NoneType

Numeric & Boolean Types

Numbers are the simplest data. Python has three numeric types, and the boolean type is closely related to integers. All four are immutable: an operation such as x += 1 creates a new object and rebinds the name.

A · Numeric types

int immutable

A whole number, positive, negative or zero, with no size limit (it grows as large as memory allows).

Syntax: x = 25   x = int("25")   also 0b1010 (binary), 0o17 (octal), 0xFF (hex), 1_000_000
a = 25
b = -7
big = 2 ** 100
print(a + b, a // 4, a % 4, a ** 2)
print(big)
print(type(big))
print(0b1010, 0o17, 0xFF, 1_000_000)
Output

Important characteristics

  • No overflow: 2 ** 100 works.
  • / always gives a float, // gives the floor-divided integer.
  • Underscores can be used for readability.

Real-world use cases

  • Counting items, ages, marks, IDs
  • Loop counters and list indexes
  • Exact money calculations in paise or cents

float immutable

A number with a decimal point, stored in 64-bit binary floating-point format.

Important characteristics

  • Precision is limited to about 15-16 digits.
  • Some decimals (like 0.1) cannot be stored exactly, so 0.1 + 0.2 != 0.3.
  • Compare floats with math.isclose() or round(), not ==.

Real-world use cases

  • Prices, averages, percentages
  • Scientific measurements
  • Graphics and physics calculations

complex immutable

A number with a real part and an imaginary part, written with the suffix j.

Syntax: z = 3 + 4j   z = complex(3, 4)
z = 3 + 4j
w = complex(1, -2)
print(z + w, z * w)

Important characteristics

  • Parts are available as .real and .imag (both floats).
  • abs(z) gives the magnitude.
  • Python uses j, not i.

Real-world use cases

  • Electrical engineering (AC circuits)
  • Signal processing, Fourier transforms
  • Mathematics and simulations
E · Boolean type

bool immutable

A value that is either True or False. It is a subclass of int: True equals 1 and False equals 0.

Syntax: flag = True   flag = bool(value)   results of comparisons such as 5 > 3
print(True + True, True * 10)
print(isinstance(True, int))
print(bool(0), bool(""), bool([]), bool(None))
print(bool(5), bool("False"), bool([0]))
print(5 > 3, 5 == 3)
Output
2 10
True

True True True
True False

Important characteristics

  • Only two values exist, and they are capitalised.
  • Falsy values: 0, 0.0, '', [], (), {}, set(), None. Everything else is truthy, even the string "False".
  • Because bool is an int, True + True is 2.

Real-world use cases

  • Conditions in if and while
  • Flags such as is_logged_in
  • Filtering data (any(), all())
Exam point

int, float, complex and bool are all immutable and hashable. They hold a single value, so "ordered" and "duplicates" do not apply to them.

Sequence Types

A sequence is an ordered collection whose items can be reached by position (index), starting at 0. Negative indexes count from the end (-1 is the last item). Slicing x[start:stop:step] works on all sequences.

B · Sequence types

str immutable

An ordered sequence of Unicode characters used to store text.

Syntax: s = 'hello'   s = "hello"   s = '''multi-line'''   s = str(100)
s = "Data Structures"
print(len(s), s[0], s[-1], s[5:])
print(s.upper(), s.lower())
print(s.replace("Data", "Python"))
print(s.split())
print("-".join(["a", "b", "c"]))
print(f"Course: {s}")
try:
    s[0] = "d"
except TypeError as e:
    print("Error:", e)
Output
15 D s Structures
DATA STRUCTURES data structures
Python Structures
['Data', 'Structures']
a-b-c
Course: Data Structures
Error: 'str' object does not support item assignment

Important characteristics

  • Immutable: methods like upper() or replace() return a new string.
  • Supports indexing, slicing, len(), in, and f-strings.
  • Duplicates are allowed ('aab').

Real-world use cases

  • Names, messages, file paths
  • Reading and cleaning user input
  • Parsing text and building output

list mutable

An ordered, changeable collection that can hold items of any type, even mixed.

Syntax: nums = [10, 20, 30]   nums = list("abc")   empty = []
nums = [10, 20, 30]
nums.append(40)
nums.insert(1, 15)
nums.remove(30)
print(nums, len(nums))
nums[0] = 5
print(nums, nums[-1], nums[1:3])
nums.sort(reverse=True)
print(nums)
print([n * 2 for n in nums])
Output
[10, 15, 20, 40] 4
[5, 15, 20, 40] 40 [15, 20]
[40, 20, 15, 5]
[80, 40, 30, 10]

Important characteristics

  • Ordered, mutable, allows duplicates.
  • Grows and shrinks automatically (dynamic array).
  • append() is O(1) on average; insert() and remove() are O(n).

Real-world use cases

  • Shopping cart, to-do list, marks of a class
  • Implementing stacks and queues
  • Storing results while looping

tuple immutable

An ordered, unchangeable collection. Use it for a fixed group of related values.

Syntax: p = (3, 4)   p = 3, 4   one = (5,) (comma required)   p = tuple([3, 4])
point = (3, 4)
single = (5,)
x, y = point
print(point, x, y, point[0])
print(type(single), type((5)))
print(point + (5, 6), point * 2)
try:
    point[0] = 9
except TypeError as e:
    print("Error:", e)
Output
(3, 4) 3 4 3
<class 'tuple'> <class 'int'>
(3, 4, 5, 6) (3, 4, 3, 4)
Error: 'tuple' object does not support item assignment

Important characteristics

  • Ordered, immutable, allows duplicates.
  • Hashable if all its items are hashable, so it can be a dict key.
  • Supports easy unpacking: x, y = point. Functions that "return two values" really return a tuple.

Real-world use cases

  • Coordinates, RGB colours, (latitude, longitude)
  • Dictionary keys such as (row, col)
  • Protecting data from accidental change

range immutable

An immutable sequence of integers generated on demand. It stores only start, stop, step, so even range(10**9) uses tiny memory.

Syntax: range(stop)   range(start, stop)   range(start, stop, step) (stop is excluded)
r = range(1, 10, 2)
print(r, list(r), len(r))
print(list(range(5)), list(range(10, 0, -3)))
print(7 in r, 4 in r)
for i in range(3):
    print("Round", i)
Output
range(1, 10, 2) [1, 3, 5, 7, 9] 5
[0, 1, 2, 3, 4] [10, 7, 4, 1]
True False
Round 0
Round 1
Round 2

Important characteristics

  • Ordered, immutable; values never repeat.
  • Memory use is constant, whatever the length.
  • Convert with list(range(5)) to see the numbers.

Real-world use cases

  • for loops that run a fixed number of times
  • Generating indexes and number series
  • Stepping through every k-th item
List vs tuple: how to choose

If the collection will grow, shrink or be edited, use a list. If it is a fixed record that should never change, use a tuple. When in doubt, start with a list.

Mapping, Set, Binary & None Types

C · Mapping type

dict mutable

A collection of key : value pairs. You look up a value by its key, not by a position.

Syntax: d = {"name": "Ravi", "age": 21}   d = dict(name="Ravi")   empty = {}
student = {"name": "Ravi", "age": 21}
student["cgpa"] = 8.4
student["age"] = 22
print(student)
print(student["name"], student.get("phone", "N/A"))
print(list(student.keys()), list(student.values()))
del student["cgpa"]
print(student, len(student))
print("name" in student)
Output
{'name': 'Ravi', 'age': 22, 'cgpa': 8.4}
Ravi N/A
['name', 'age', 'cgpa'] ['Ravi', 22, 8.4]
{'name': 'Ravi', 'age': 22} 2
True

Important characteristics

  • Keys are unique and must be hashable (str, int, tuple...). Values can be anything and can repeat.
  • Keeps insertion order (Python 3.7+).
  • Lookup, insert and delete are O(1) on average (it is a hash table).

Real-world use cases

  • Records such as a student or product
  • Counting frequencies, caching, JSON-like data
  • Fast lookups by ID
D · Set types

set mutable

An unordered collection of unique items. Adding an existing item changes nothing.

Syntax: s = {1, 2, 3}   s = set([1, 2, 2])   empty = set() (not {})
a = {1, 2, 3, 3, 2}
b = {3, 4, 5}
print(a, len(a))
print(a | b, a & b, a - b, a ^ b)
a.add(10)
a.discard(1)
print(a)
print(set(), type({}), type(set()))
Output
{1, 2, 3} 3
{1, 2, 3, 4, 5} {3} {1, 2} {1, 2, 4, 5}
{10, 2, 3}
set() <class 'dict'> <class 'set'>

Important characteristics

  • Unordered, mutable, no duplicates, no indexing.
  • Items must be hashable (no lists inside a set).
  • Membership test x in s is O(1) on average. Supports union |, intersection &, difference -, symmetric difference ^.

Real-world use cases

  • Removing duplicates
  • Fast membership checks
  • Finding common or different items between two groups

frozenset immutable

An immutable version of set. Once created it cannot be changed, so it is hashable.

Syntax: fs = frozenset([1, 2, 3])
fs = frozenset([1, 2, 2, 3])
print(fs, type(fs))
print(2 in fs, fs | {9})
d = {fs: "locked"}
print(d[frozenset([1, 2, 3])])
try:
    fs.add(4)
except AttributeError as e:
    print("Error:", e)
Output

True frozenset({1, 2, 3, 9})
locked
Error: 'frozenset' object has no attribute 'add'

Important characteristics

  • Same unique, unordered behaviour as a set, but no add() or remove().
  • Can be a dictionary key or an item of another set.

Real-world use cases

  • Constant collections of allowed values
  • Keys that are themselves sets
  • Sets of sets (e.g. graph groups)
F · Binary types

Binary types store raw bytes (numbers 0 to 255). You meet them when reading files, sending data over a network, or encoding text.

bytes immutable

An immutable sequence of bytes.

Syntax: b = b"Hello"   b = bytes([72, 101])   "text".encode("utf-8")
b = b"Hello"
print(b, b[0], list(b))
print("Hello".encode("utf-8"), "caf\u00e9".encode("utf-8"))
print(b.decode("utf-8"), len(b))
try:
    b[0] = 72
except TypeError as e:
    print("Error:", e)
Output
b'Hello' 72 [72, 101, 108, 108, 111]
b'Hello' b'caf\xc3\xa9'
Hello 5
Error: 'bytes' object does not support item assignment

Important characteristics

  • Each item is an int from 0 to 255.
  • Convert back to text with .decode().

Real-world use cases

  • Reading binary files (images, PDFs)
  • Network data and encryption
  • Encoding text to UTF-8

bytearray mutable

A changeable version of bytes.

Syntax: ba = bytearray(b"Hello")   ba = bytearray(10) (ten zero bytes)
ba = bytearray(b"Hello")
ba[0] = 74
ba.append(33)
print(ba, bytes(ba))
Output
bytearray(b'Jello!') b'Jello!'

Important characteristics

  • Supports item assignment, append() and slicing like a list.
  • Efficient for editing binary data in place.

Real-world use cases

  • Building a network packet piece by piece
  • Editing image or file data in memory

memoryview depends on the buffer

A window onto another object's memory. It lets you slice and read (or change) binary data without copying it.

Syntax: view = memoryview(data)   where data is bytes or bytearray
data = bytearray(b"ABCDEF")
view = memoryview(data)
part = view[1:4]
part[0] = 90
print(bytes(part), data)
print(view[0], len(view))
Output
b'ZCD' bytearray(b'AZCDEF')
65 6

Important characteristics

  • Changing a slice of the view changes the original (if the original is mutable, like bytearray).
  • Saves memory and time with large data.

Real-world use cases

  • Processing very large files without copying
  • Fast slicing of binary buffers
G · None type

NoneType immutable

The type of the single value None, which means "no value here". It is Python's version of null.

Syntax: result = None   test with if result is None:

print(result, type(result))

Important characteristics

  • There is exactly one None object in a program.
  • A function with no return gives back None.
  • Falsy, but None == 0 is False. Always test with is None.

Real-world use cases

  • Default value for "not set yet"
  • A function that returns "nothing found"
  • Empty pointers such as next = None in a linked list

B. Mutable vs immutable

Definition

A mutable object can be changed in place after it is created, and it keeps the same identity (id). An immutable object can never be changed. Any "change" creates a new object and the name is re-pointed to it.

MutableImmutable
Typeslist, dict, set, bytearrayint, float, complex, bool, str, tuple, frozenset, bytes, range, None
Change in place?YesNo (a new object is created)
Same id after a change?YesNo
Hashable (usable as dict key / set item)?NoYes (if all items inside are hashable)
RiskShared references: a change shows up everywhereSlightly slower when building big values by repeated change
nums = [1, 2, 3]
before = id(nums)
nums.append(4)
print(nums, id(nums) == before)     # True: the same object was changed

text = "abc"
before = id(text)
text += "d"
print(text, id(text) == before)     # False: a brand-new string was made

t = (1, 2)
before = id(t)
t += (3,)
print(t, id(t) == before)           # False: a brand-new tuple

x = 10
y = x
y += 1
print(x, y)                         # ints are immutable, x is untouched
Output
[1, 2, 3, 4] True
abcd False
(1, 2, 3) False
10 11

The aliasing trap

Because mutable objects change in place, two names that point to the same object see each other's changes. Make a copy when you need an independent object.

a = [1, 2]
b = a              # NOT a copy: both names point to one list
b.append(3)
print(a, b, a is b)

c = a.copy()       # a real (shallow) copy
c.append(99)
print(a, c, a is c)
Output
[1, 2, 3] [1, 2, 3] True
[1, 2, 3] [1, 2, 3, 99] False
Careful with nested objects

A tuple is immutable, but if it contains a list, that inner list can still change: t = ([1], 2); t[0].append(9) works. Immutability applies to the tuple's own slots only.

Checking & Converting Types

A. Checking a type

type(x)

Returns the exact class of x. Use it to see a type or to print it.

isinstance(x, C)

Returns True if x is an instance of C or a subclass of it. Accepts a tuple: isinstance(x, (int, float)). Preferred in real code.

print(type(42), type(3.5), type("hi"), type([1]), type(None))
print(type(42) == int)
print(isinstance(42, int), isinstance(True, int), type(True) == int)
print(isinstance(3.5, (int, float)))
print(isinstance("a", (list, tuple)))
for v in [1, 2.0, "3", [4], (5,), {6}, {7: 8}, None]:

Exam point

type(True) == int is False (the type is bool), but isinstance(True, int) is True because bool inherits from int. That is the main difference between the two functions.

B. Type conversion (type casting)

Implicit conversion

Python converts automatically when it is safe, always towards the "wider" type: bool → int → float → complex. You do nothing; it just happens.

print(type(2 + (3 + 4j)))
try:
    print("5" + 5)
except TypeError as e:

Common Mistakes & Interview Questions

A. Common beginner mistakes

1. Thinking b = a makes a copy

Assignment copies the reference, not the object. Changing one list changes the other.

✗ Wrong

a = [1, 2, 3]
b = a                # wrong idea: "b is a copy"
b.append(4)
print(a)             # a changed too!
Output
[1, 2, 3, 4]

✓ Better

a = [1, 2, 3]
b = a.copy()         # or list(a) or a[:]
b.append(4)
print(a, b)
Output
[1, 2, 3] [1, 2, 3, 4]

2. Forgetting the comma in a one-item tuple

(5) is just the number 5 in brackets. The comma makes the tuple.

✗ Wrong

t = (5)
print(type(t))
Output
<class 'int'>

✓ Better

t = (5,)
print(type(t))
Output
<class 'tuple'>

3. Creating an empty set with {}

Empty curly braces make a dictionary. Use set() for an empty set.

✗ Wrong

s = {}
print(type(s))
Output
<class 'dict'>

✓ Better

s = set()
print(type(s))
Output
<class 'set'>

4. Adding a string and an integer

Python never guesses between text and numbers. Convert one side explicitly.

✗ Wrong

age = 20
try:
    print("Age: " + age)
except TypeError as e:
    print("Error:", e)
Output
Error: can only concatenate str (not "int") to str

✓ Better

age = 20
print("Age: " + str(age))
print(f"Age: {age}")
Output
Age: 20
Age: 20

5. Removing items from a list while looping over it

The list shrinks while the loop walks along it, so some items are skipped.

✗ Wrong

nums = [2, 4, 6, 8]
for n in nums:
    if n % 2 == 0:
        nums.remove(n)
print(nums)          # expected [], got something else
Output
[4, 8]

✓ Better

nums = [2, 4, 6, 8]
nums = [n for n in nums if n % 2 != 0]
print(nums)
Output
[]

6. Comparing floats with ==

Many decimals cannot be stored exactly in binary, so tiny errors appear.

✗ Wrong

print(0.1 + 0.2 == 0.3)
Output
False

✓ Better

import math
print(math.isclose(0.1 + 0.2, 0.3))
print(round(0.1 + 0.2, 2) == 0.3)
Output
True
True

7. Using a list as a dictionary key or set item

Keys and set items must be hashable (immutable). Use a tuple instead.

✗ Wrong

try:
    d = {[1, 2]: "x"}
except TypeError as e:
    print("Error:", e)
Output
Error: unhashable type: 'list'

✓ Better

d = {(1, 2): "x"}
print(d[(1, 2)])
Output
x

8. Forgetting that input() returns a string

Even if the user types digits, you get text. Convert it before doing arithmetic.

✗ Wrong

a = "5"              # what input() gives you
b = "3"
print(a + b)
Output
53

✓ Better

a = int("5")
b = int("3")
print(a + b)
Output

B. Top 10 interview questions

Q1. What are the built-in data types in Python?

The main groups are numeric (int, float, complex), boolean (bool), sequence (str, list, tuple, range), mapping (dict), set (set, frozenset), binary (bytes, bytearray, memoryview) and NoneType.

Q2. What is the difference between a list and a tuple?

A list is mutable (items can be added, removed or changed) and written with []. A tuple is immutable and written with (). Tuples are slightly faster and can be used as dictionary keys when all their items are hashable.

Q3. What does "Python is dynamically typed" mean?

You do not declare a variable's type. The type belongs to the object the name refers to, and it is checked at run time. The same name can later point to an object of a different type.

Q4. Which types are mutable and which are immutable?

Mutable: list, dict, set, bytearray. Immutable: int, float, complex, bool, str, tuple, frozenset, bytes, range, NoneType.

Q5. What is the difference between type() and isinstance()?

type(x) returns the exact class of x. isinstance(x, C) returns True if x is an instance of C or of a subclass, and it accepts a tuple of classes. Because bool is a subclass of int, isinstance(True, int) is True but type(True) == int is False.

Q6. Is a dictionary ordered in Python?

Yes. From Python 3.7 a dict remembers insertion order. Keys must be unique and hashable. A set, however, has no defined order.

Q7. How do you remove duplicates from a list?

list(set(items)) removes them but loses the order. To keep the order use list(dict.fromkeys(items)).

Q8. What is the difference between == and is?

== compares values. is checks whether two names refer to the very same object (same id). Use is mainly for None: if x is None.

Q9. What is the difference between set and frozenset?

A set is mutable and cannot be used as a dictionary key or inside another set. A frozenset is immutable and hashable, so it can.

Q10. What is the difference between a shallow copy and a deep copy?

A shallow copy (list.copy(), a[:]) creates a new outer container but shares the inner objects. copy.deepcopy() copies the inner objects as well, so nested lists become independent.

C. Conclusion

Python's built-in data types are the raw material of every program. Numbers and booleans hold single values. Strings, lists, tuples and ranges hold ordered items. Dictionaries and sets hold items you look up quickly. Knowing which types can change (mutable) and which cannot (immutable) explains most of the "surprising" behaviour beginners meet.

Key takeaways
  • Types belong to objects, and Python checks them at run time.
  • Immutable: int, float, complex, bool, str, tuple, frozenset, bytes, range, None. Mutable: list, dict, set, bytearray.
  • Use isinstance() to check types and int(), str(), list()... to convert them.
  • Choose the type that matches the job: a list for order, a dict for lookup by key, a set for uniqueness.
