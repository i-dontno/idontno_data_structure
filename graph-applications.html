Graphs in the Real World

A graph G = (V, E) is a set of vertices (nodes) connected by edges (links). Whenever a problem is about things and the relationships between them, a graph is usually the right data structure. In the earlier posts of this series we learned BFS, DFS, Dijkstra's, Floyd–Warshall, Prim's and Kruskal's algorithms. In this post we see where they are actually used.

Why graphs?
  • Arrays, lists and trees store data in a fixed shape (sequence or hierarchy). Real relationships are messier: anyone can be friends with anyone, any router can link to any other.
  • A graph stores arbitrary connections directly, so questions like “how are these two connected?” become standard graph algorithms.

One graph, two worlds

👥 Social network

  • Vertex = a person (user account)
  • Edge = friendship / follow / message
  • Question: Who is influential? Whom should I befriend? How far apart are two people?

🌐 Computer network

  • Vertex = a router (or computer)
  • Edge = a physical/logical link, with a cost
  • Question: Which way should a packet go? What if a link fails?

Other important applications

🗺️ Maps & GPS

Road junctions are vertices, roads are weighted edges; navigation apps run shortest-path algorithms.

🔎 Web search

Web pages are vertices and hyperlinks are directed edges; ranking algorithms such as PageRank work on this graph.

🛒 Recommendations

Users and products form a graph; “people who bought this also bought…” follows edges.

🦠 Epidemiology

Contact graphs show how a disease (or a rumour) spreads, and who should be vaccinated or informed first.

📦 Dependencies

Package managers and build tools use directed acyclic graphs and topological sorting to decide installation order.

🧬 Biology & chemistry

Molecules (atoms + bonds) and protein-interaction networks are graphs.

In this post we study the two named applications in depth: Social Network Analysis (Section 3) and Routing Algorithms (Section 3B).

Core Concepts

2.1 Modelling a social network

  • Undirected graph when the relationship is mutual: Facebook friends, LinkedIn connections.
  • Directed graph when it is one-way: Instagram / X followers. A → B means “A follows B”. Then we talk about in-degree (followers) and out-degree (following).
  • Weighted graph when the strength matters: number of messages exchanged, years of friendship.
  • Vertices can carry attributes (age, city, interests) — useful for recommendations.

2.2 Modelling a computer network

  • Vertices are routers; edges are links between them.
  • Each link has a cost (also called metric): hop count (every link = 1), delay, or a value based on bandwidth (faster link → lower cost). Costs are never negative.
  • Links usually work in both directions, so we use an undirected weighted graph (or a directed one if costs differ by direction).

2.3 Social network analysis (SNA) terminology

2.4 Routing terminology

TermMeaning
RoutingDeciding the path packets should take (building the routing tables).
ForwardingSending an arriving packet out on the correct link, using the routing table.
Routing tableFor each destination: total cost and the next hop (the neighbour to send the packet to).
Link-state routingEvery router learns the whole map and runs Dijkstra's algorithm itself (e.g. OSPF, IS-IS).

Count-to-infinityA distance-vector problem: after a failure, routers keep raising each other's costs slowly instead of declaring the destination unreachable.

2.5 Which representation?

A social network is huge but sparse: each person has a few hundred friends out of billions of users. An adjacency matrix needs V² cells, almost all of them 0. An adjacency list stores only the existing edges (V + 2E entries for an undirected graph). For router networks (tens to thousands of routers) both work, but link-state databases are stored as lists of links.

3

Social Network Analysis

Social Network Analysis (SNA) studies relationships between people using graph theory. Platforms use it to suggest friends, rank posts, detect fake accounts and find communities; sociologists use it to study how information and opinions spread. We use the friendship network below: a college group (left) and an office group (right), linked through Rohan and Neha.

Figure — Example friendship network: 10 people, 14 friendships (undirected, unweighted).

3.1 Friends and mutual friends

With an adjacency list of sets, a person's friends are graph[p] and their degree is len(graph[p]). Mutual friends are a set intersection: graph[a] & graph[b]. Example: Sara's friends are {Neha, Vikram, Isha}; Sara and Arjun have mutual friends {Isha, Vikram}.

3.2 Friend recommendation (“People you may know”)

Based on triadic closure: friends-of-friends are likely future friends. A simple and widely taught method:

  1. For every friend f of the person p, look at f's friends.
  2. Skip p itself and people who are already p's friends.
  3. Count how many times each remaining person appears = number of mutual friends.
  4. Recommend in decreasing order of the count.

For Sara: Arjun (2 mutual friends: Isha, Vikram), then Rohan (1: Neha). A refinement, the Jaccard coefficient |N(u) ∩ N(v)| / |N(u) ∪ N(v)|, divides by the size of both friend lists so that very popular people do not dominate.

3.3 Degrees of separation with BFS

In an unweighted graph, the shortest path is the one with the fewest edges, and Breadth-First Search finds it: BFS visits everyone at distance 1, then distance 2, and so on, like ripples in water.

1BFS-DISTANCES(G, s)
2 dist[s] ← 0; Q ← queue containing s
3 while Q not empty:
4 u ← DEQUEUE(Q)
5 for each friend v of u:
6 if v not visited: dist[v] ← dist[u] + 1; parent[v] ← u; ENQUEUE(Q, v)
7 return dist // follow parent[] back to get the actual chain of friends

Small-world in real life

The “six degrees of separation” idea dates back to Frigyes Karinthy (1929) and Stanley Milgram's letter-forwarding experiments in the 1960s. In 2016, Facebook estimated the separation between its 1.59 billion active users at an average of only 3.57. Careful: Facebook counted the people in between, so 3.57 degrees means an average shortest path of 4.57 friendship links. Always state which convention you use; in this post, distance = number of edges.

3.4 Clustering coefficient

C(v) = (number of links among v's friends) / ( k(k − 1) / 2 ) // k = degree of v, k ≥ 2

Isha has 4 friends (Neha, Sara, Vikram, Arjun) → 6 possible pairs. Three pairs are friends (Neha–Sara, Sara–Vikram, Vikram–Arjun), so C(Isha) = 3/6 = 0.50. Diya's two friends know each other: C = 1. Rohan's two friends (Meera, Neha) do not: C = 0 — a typical bridge.

3.6 Communities

A community is a group with many links inside and few links outside (here: college vs office). The simplest grouping is by connected components (BFS/DFS). For connected networks, methods such as Girvan–Newman repeatedly remove the edge with the highest betweenness — in our network that is Rohan–Neha, which immediately separates the two groups.

3B

Routing Algorithms

The Internet is a graph of millions of routers. When you open a web page, your data is split into packets, and every router on the way must decide which neighbour to pass each packet to. A routing algorithm computes these decisions so that packets travel along low-cost paths. Routing is the shortest-path problem, solved by many computers working together.

Figure — Example network: 6 routers, 8 links with costs.

3B.1 Routing tables and forwarding

A router does not store whole paths. It stores, for every destination, only the cost and the next hop. Each router forwards the packet to its next hop, which looks at its own table, and so on — the full path emerges hop by hop. For this to work, the tables of all routers must agree (be consistent).

There are two classic families of routing algorithms:

🗺️ Link-state (global)

Every router gets the complete map and computes shortest paths itself with Dijkstra's algorithm. Used by OSPF and IS-IS.

📣 Distance-vector (decentralised)

Every router knows only its neighbours and repeatedly shares its distance list with them, using the Bellman–Ford equation. Used by RIP.

3B.2 Link-state routing (Dijkstra's algorithm)

  1. Discover neighbours and measure the cost of each attached link.
  2. Build a Link-State Advertisement (LSA): “I am R3; my links: R1 cost 4, R2 cost 2, R4 cost 3, R5 cost 6”.
  3. Flood the LSA to every router. Now every router has the same link-state database = the whole graph.
  4. Each router runs Dijkstra's algorithm with itself as the source and fills its routing table (next hop = first router on each shortest path).
  5. When a link changes, new LSAs are flooded and Dijkstra is re-run.

3B.3 Distance-vector routing (Bellman–Ford)

Each router x keeps a distance vector Dx(y) = its current estimate of the cost to every destination y. Periodically (RIP: every 30 seconds) it sends this vector to its neighbours and updates itself with the Bellman–Ford equation:

Dx(y) = minv ∈ neighbours(x) { cost(x, v) + Dv(y) } // next hop = the v that gives the minimum

Initially each router knows only its direct neighbours. After round 1, it knows routes of 2 hops; after round k, routes of up to k + 1 hops. Here is R1's vector, round by round (each round, all routers update at the same time):

RoundR1→R2R1→R3R1→R4R1→R5R1→R6
01via R24via R3∞∞∞
11via R23via R27via R310via R3∞

31via R23via R26via R27via R210via R3
41via R23via R26via R27via R29via R2

All tables stop changing after 4 rounds: the network has converged, with the same result as Dijkstra's — as it must be.

The count-to-infinity problem

“Good news travels fast, bad news travels slowly.” Suppose the link R5–R6 fails. R5 loses its route to R6, but R4 still advertises “R6 at cost 3” (R4 learned it through R5, but R5 doesn't know that). R5 believes it can reach R6 via R4 for 1 + 3 = 4. R4 then updates to 1 + 4 = 5, R5 to 6, and so on, two by two. The route bounces between R4 and R5 (a routing loop) while the cost slowly climbs. That is why RIP defines 16 = infinity (so the largest usable route is 15 hops). In our simulation, this takes 14 rounds. Try it in the visualiser below.

Fixes
  • Maximum metric (16 in RIP): the count stops at a finite “infinity”.
  • Split horizon: do not advertise a route back to the neighbour you learned it from.
  • Poisoned reverse: advertise it back with cost ∞. Stops 2-router loops. In our example it cuts 14 rounds to 7 — not to 1, because a 3-router loop (R5 → R3 → R4 → R5) still forms. Poisoned reverse cannot stop loops of three or more routers.
  • Triggered updates and hold-down timers spread bad news faster and ignore suspicious good news.

3B.4 Link-state vs distance-vector

BasisLink-stateDistance-vector

Between different organisations' networks (autonomous systems), the Internet uses BGP, a path-vector protocol — a distance-vector relative that sends whole paths to avoid loops. It is beyond this syllabus.

Special Cases & Common Mistakes

5.1 Special cases — social networks

SituationWhat happens / what to do
Disconnected networkPeople in different components have distance ∞. Closeness must use only reachable people (scaled by the fraction reachable).
Directed (follower) graphsDistance is not symmetric: A may reach B in 1 step while B needs 3 to reach A. Use in-degree for popularity (followers).
Hubs / celebritiesReal networks have a few vertices with huge degree. Counting mutual friends with a celebrity is meaningless; Jaccard or weighting by 1/log(degree) helps.
Weighted ties“Strong” vs “weak” friendships: use Dijkstra instead of BFS if distance should depend on tie strength.
Ties in recommendationsSeveral people with the same number of mutual friends — break ties consistently (e.g. by Jaccard, then by name).
PrivacySNA reveals a lot about people (friends, groups, influence). Real systems must respect privacy settings and laws.

5.2 Special cases — routing

SituationWhat happens / what to do
Link failureLink-state: new LSAs, everyone re-runs Dijkstra. Distance-vector: slow re-convergence, possible count-to-infinity.
Unreachable destinationCost becomes ∞ (16 in RIP); the route is removed.
Equal-cost pathsSeveral next hops have the same cost. Routers may split traffic among them (equal-cost multipath, ECMP).
Asymmetric costsIf cost(A→B) ≠ cost(B→A), use a directed graph; the path back may differ from the path there.
Negative costsDo not occur in routing; that is why Dijkstra's is safe for link-state routing.
Inconsistent tablesWhile tables are updating, packets can loop. IP packets carry a TTL (time-to-live) counter so looping packets are eventually dropped.

5.3 Advantages and disadvantages of graph-based modelling

✅ Advantages

  • Natural model for relationships of any shape.
  • Reuses well-known algorithms (BFS, Dijkstra, …) with proven correctness and complexity.
  • Adjacency lists scale to billions of vertices.
  • Same toolbox works for people, routers, roads, web pages.

❌ Disadvantages

  • Some measures (betweenness, diameter) are too slow for huge graphs and must be approximated.
  • Graphs change constantly (new friends, link failures): results go stale.
  • Distributed algorithms (distance-vector) can misbehave temporarily.
  • Graph data can be very privacy-sensitive.

5.4 Common mistakes

Mistake 1 — Using DFS to find degrees of separation

DFS finds a path, not the shortest. From Aarav, DFS might reach Kabir via Diya (2 edges) although they are direct friends (1 edge). Use BFS for unweighted shortest paths.

Mistake 2 — Forgetting the visited check in BFS

Friendships are mutual, so the graph is full of cycles. Without marking vertices as visited, BFS loops forever (A → B → A → …).

Mistake 3 — Recommending yourself or existing friends

When scanning friends-of-friends, skip the person themself and anyone already in their friend set.

Mistake 4 — Mixing up “links” and “people in between”

A path A → B → C has 2 links but 1 intermediary. Facebook's 3.57 counts intermediaries (4.57 links). State your convention.

Mistake 5 — Storing whole paths in routing tables / wrong next hop

A routing table stores only the next hop. When reconstructing it from Dijkstra's prev[] array, walk back from the destination until the vertex whose prev is the source — not the vertex just before the destination.

Mistake 6 — No “infinity” cap in distance-vector code

Without a maximum cost, a simulated count-to-infinity never terminates. Cap the cost (e.g. 16) and treat it as unreachable.

5.5 Important examination points

Remember for exams
  • Social network → vertices = people, edges = relationships; undirected (friends) or directed (followers).
  • Degrees of separation = BFS (unweighted shortest path), O(V + E).
  • Friend suggestion = friends-of-friends ranked by mutual friends (triadic closure).
  • Centralities: degree (popularity), closeness (1 / average distance), betweenness (bridge). Clustering coefficient = links among friends / k(k−1)/2.
  • Link-state = full map + Dijkstra (OSPF). Distance-vector = neighbours + Bellman–Ford (RIP, 16 = ∞).
  • Count-to-infinity happens in distance-vector routing; split horizon / poisoned reverse reduce it.
  • Huge sparse graphs → adjacency lists.

Python Implementation

All four programs are complete and runnable (Python 3.6+, standard library only). The outputs are their real outputs and match the worked examples and visualisers above.

social_network.py
# Social Network Analysis with a Graph (adjacency list of sets)
# Friends, mutual friends, friend suggestions, degrees of separation (BFS)
# and the clustering coefficient.

from collections import deque

friendships = [("Aarav", "Diya"), ("Aarav", "Kabir"), ("Aarav", "Meera"),
               ("Diya", "Kabir"), ("Kabir", "Meera"), ("Meera", "Rohan"),
               ("Rohan", "Neha"), ("Neha", "Sara"), ("Neha", "Isha"),
               ("Sara", "Vikram"), ("Sara", "Isha"), ("Vikram", "Isha"),
               ("Isha", "Arjun"), ("Vikram", "Arjun")]

# Build an undirected graph: friendship works both ways
graph = {}
for a, b in friendships:
    graph.setdefault(a, set()).add(b)
    graph.setdefault(b, set()).add(a)


def mutual_friends(a, b):
    return graph[a] & graph[b]                 # set intersection


def suggest_friends(person):
    """Friends-of-friends who are not already friends, ranked by mutual friends."""
    scores = {}
    for friend in graph[person]:
        for fof in graph[friend]:
            if fof != person and fof not in graph[person]:
                scores[fof] = scores.get(fof, 0) + 1
    return sorted(scores.items(), key=lambda x: (-x[1], x[0]))


def degrees_of_separation(start):
    """BFS: number of friendship links from start to everyone else."""
    dist = {start: 0}
    queue = deque([start])
    while queue:
        u = queue.popleft()
        for v in sorted(graph[u]):
            if v not in dist:
                dist[v] = dist[u] + 1
                queue.append(v)
    return dist


def connection_path(start, goal):
    """Shortest chain of friends from start to goal (BFS with parents)."""
    parent = {start: None}
    queue = deque([start])
    while queue:
        u = queue.popleft()
        if u == goal:
            break
        for v in sorted(graph[u]):
            if v not in parent:
                parent[v] = u
                queue.append(v)
    if goal not in parent:
        return None
    path = []
    while goal is not None:
        path.append(goal)
        goal = parent[goal]
    return path[::-1]


def clustering_coefficient(person):
    """Fraction of pairs of this person's friends who are friends themselves."""
    f = list(graph[person])
    k = len(f)
    if k < 2:
        return 0.0
    links = sum(1 for i in range(k) for j in range(i + 1, k) if f[j] in graph[f[i]])
    return links / (k * (k - 1) / 2)


if __name__ == "__main__":
    print("Friends of Sara  :", sorted(graph["Sara"]), "-> degree", len(graph["Sara"]))
    print("Mutual(Sara, Arjun):", sorted(mutual_friends("Sara", "Arjun")))
    print("Suggestions for Sara:", suggest_friends("Sara"))
    d = degrees_of_separation("Aarav")
    print("Distances from Aarav:", dict(sorted(d.items(), key=lambda x: (x[1], x[0]))))
    print("Aarav -> Arjun path :", " -> ".join(connection_path("Aarav", "Arjun")))
    for p in ["Diya", "Isha", "Rohan"]:
        print(f"Clustering coefficient of {p}: {clustering_coefficient(p):.2f}")

centrality.py
# Who is the most "important" person? Three centrality measures.
#   Degree centrality      : how many friends (popularity)
#   Closeness centrality   : how near to everyone (fast spreader)
#   Betweenness centrality : how often on shortest paths (bridge / broker)
# Betweenness uses Brandes' algorithm: one BFS per vertex -> O(V * E).

from collections import deque

friendships = [("Aarav", "Diya"), ("Aarav", "Kabir"), ("Aarav", "Meera"),
               ("Diya", "Kabir"), ("Kabir", "Meera"), ("Meera", "Rohan"),
               ("Rohan", "Neha"), ("Neha", "Sara"), ("Neha", "Isha"),
               ("Sara", "Vikram"), ("Sara", "Isha"), ("Vikram", "Isha"),
               ("Isha", "Arjun"), ("Vikram", "Arjun")]
graph = {}
for a, b in friendships:
    graph.setdefault(a, set()).add(b)
    graph.setdefault(b, set()).add(a)
people = sorted(graph)
n = len(people)


def bfs_dist(s):
    dist = {s: 0}
    q = deque([s])
    while q:
        u = q.popleft()
        for v in graph[u]:
            if v not in dist:
                dist[v] = dist[u] + 1
                q.append(v)
    return dist


def degree_centrality(p):
    return len(graph[p]) / (n - 1)


def closeness_centrality(p):
    d = bfs_dist(p)
    return (len(d) - 1) / sum(d.values())       # (reachable people) / (total distance)


def betweenness_all():
    bc = {p: 0.0 for p in people}
    for s in people:
        # BFS that also counts shortest paths (sigma) and records predecessors
        stack, pred = [], {p: [] for p in people}
        sigma = {p: 0 for p in people}; sigma[s] = 1
        dist = {s: 0}
        q = deque([s])
        while q:
            u = q.popleft(); stack.append(u)
            for v in graph[u]:
                if v not in dist:
                    dist[v] = dist[u] + 1; q.append(v)
                if dist[v] == dist[u] + 1:
                    sigma[v] += sigma[u]; pred[v].append(u)
        # accumulate dependencies in reverse BFS order
        delta = {p: 0.0 for p in people}
        while stack:
            w = stack.pop()
            for u in pred[w]:
                delta[u] += sigma[u] / sigma[w] * (1 + delta[w])
            if w != s:
                bc[w] += delta[w]
    return {p: bc[p] / 2 for p in people}       # undirected: each pair counted twice


if __name__ == "__main__":
    bc = betweenness_all()
    print(f"{'Person':8}{'Friends':>8}{'Degree':>9}{'Closeness':>11}{'Betweenness':>13}")
    for p in sorted(people, key=lambda p: -bc[p]):
        print(f"{p:8}{len(graph[p]):>8}{degree_centrality(p):>9.2f}"
              f"{closeness_centrality(p):>11.3f}{bc[p]:>13.1f}")

  • Betweenness uses Brandes' algorithm: a BFS from each source counts shortest paths (sigma) and then, in reverse order, adds up how much each vertex lies “between” others (delta). We divide by 2 because each undirected pair is counted from both ends.

link_state.py
# Link-State Routing (as in OSPF): every router knows the whole network map
# and runs Dijkstra's algorithm to build its own routing table.
# Routing table entry: destination -> (total cost, next hop)

import heapq

INF = float('inf')
links = [("R1", "R2", 1), ("R1", "R3", 4), ("R2", "R3", 2), ("R2", "R4", 7),
         ("R3", "R4", 3), ("R3", "R5", 6), ("R4", "R5", 1), ("R5", "R6", 2)]

network = {}
for a, b, cost in links:                      # links work in both directions
    network.setdefault(a, []).append((b, cost))
    network.setdefault(b, []).append((a, cost))


def dijkstra(source):
    dist = {r: INF for r in network}
    prev = {r: None for r in network}
    dist[source] = 0
    heap = [(0, source)]
    while heap:
        d, u = heapq.heappop(heap)
        if d > dist[u]:
            continue                          # stale heap entry
        for v, cost in network[u]:
            if d + cost < dist[v]:
                dist[v] = d + cost
                prev[v] = u
                heapq.heappush(heap, (dist[v], v))
    return dist, prev


def routing_table(source):
    dist, prev = dijkstra(source)
    table = {}
    for dest in sorted(network):
        if dest == source or dist[dest] == INF:
            continue
        hop = dest                            # walk back until the hop after source
        while prev[hop] != source:
            hop = prev[hop]
        table[dest] = (dist[dest], hop)
    return table


def forward_packet(src, dst):
    """Each router looks only at ITS OWN table to choose the next hop."""
    tables = {r: routing_table(r) for r in network}
    path = [src]
    while path[-1] != dst:
        path.append(tables[path[-1]][dst][1])
    return path


if __name__ == "__main__":
    for r in ["R1", "R3"]:
        print(f"Routing table of {r}")
        print("  Dest  Cost  Next hop")
        for dest, (cost, hop) in routing_table(r).items():
            print(f"  {dest:5} {cost:>4}  {hop}")
    print("Packet R1 -> R6 travels:", " -> ".join(forward_packet("R1", "R6")))

distance_vector.py
# Distance-Vector Routing (as in RIP): routers only talk to NEIGHBOURS.
# Each round, every router updates its table with the Bellman-Ford equation
#       D_x(y) = min over neighbours v of ( cost(x, v) + D_v(y) )
# INF = 16 means "unreachable" (the RIP convention).
# Shows convergence and the count-to-infinity problem after a link failure.

INF = 16
routers = ["R1", "R2", "R3", "R4", "R5", "R6"]


def make_links(failed=None):
    links = {("R1", "R2"): 1, ("R1", "R3"): 4, ("R2", "R3"): 2, ("R2", "R4"): 7,
             ("R3", "R4"): 3, ("R3", "R5"): 6, ("R4", "R5"): 1, ("R5", "R6"): 2}
    if failed:
        links.pop(failed)
    cost = {r: {} for r in routers}
    for (a, b), c in links.items():
        cost[a][b] = c
        cost[b][a] = c
    return cost


def initial_tables(cost):
    # each router only knows itself and its direct neighbours
    return {x: {y: ((0, x) if y == x else ((cost[x][y], y) if y in cost[x] else (INF, None)))
                for y in routers} for x in routers}


def one_round(tables, cost, poison=False):
    new = {}
    for x in routers:
        new[x] = {}
        for y in routers:
            if y == x:
                new[x][y] = (0, x)
                continue
            best = (INF, None)
            for v, c in cost[x].items():
                d_v, hop_v = tables[v][y]         # v's advertised distance
                if poison and hop_v == x:
                    d_v = INF                     # poisoned reverse
                if min(INF, c + d_v) < best[0]:
                    best = (min(INF, c + d_v), v)
            new[x][y] = best
    return new


def run(tables, cost, poison=False, label=""):
    rounds = 0
    while True:
        nxt = one_round(tables, cost, poison)
        if nxt == tables:
            return tables, rounds
        tables = nxt
        rounds += 1
        if label:
            print(f"  round {rounds:2}: R5's cost to R6 = {tables['R5']['R6'][0]:>2},"
                  f"  R4's cost to R6 = {tables['R4']['R6'][0]:>2}")


if __name__ == "__main__":
    cost = make_links()
    tables, r = run(initial_tables(cost), cost)
    print(f"Converged after {r} rounds. Table of R1 (dest: cost via next hop):")
    print("  " + ", ".join(f"{y}: {d} via {h}" for y, (d, h) in tables["R1"].items() if y != "R1"))

    print("\nLink R5-R6 fails (R6 becomes unreachable). Without poisoned reverse:")
    broken = make_links(failed=("R5", "R6"))
    _, r1 = run(tables, broken, poison=False, label="x")
    print(f"  -> took {r1} rounds to reach 'infinity' (16): count-to-infinity!")

    print("With poisoned reverse:")
    _, r2 = run(tables, broken, poison=True, label="x")
    print(f"  -> took {r2} rounds")

7.1 Conceptual questions

Q1. How is a social network represented as a graph? When is it directed?
People are vertices and relationships are edges. Mutual relationships (friendship) give an undirected graph; one-way relationships (following) give a directed graph. Interaction strength can be stored as edge weights.
Q2. Why is BFS (not Dijkstra) used for degrees of separation?
Friendship graphs are unweighted: every edge counts as 1. BFS visits vertices in order of distance and finds all shortest distances in O(V + E), faster and simpler than Dijkstra's O(E log V).
Q3. Explain the difference between degree and betweenness centrality with an example.
Degree counts direct friends (popularity); betweenness counts how many shortest paths pass through a person (brokerage). In our network Isha has the highest degree (4), but Rohan (degree 2) has the highest betweenness because all paths between the college and office groups pass through him.
Q4. Compare link-state and distance-vector routing.
Link-state: every router learns the full map by flooding and runs Dijkstra; fast convergence, more memory (OSPF). Distance-vector: routers exchange distance vectors with neighbours and apply Bellman–Ford; simple, but slow convergence and count-to-infinity (RIP).
Q5. What is count-to-infinity and how can it be reduced?
After a failure, routers in distance-vector routing learn stale routes from each other and increase the cost step by step until a maximum (“infinity”) is reached. Reduced by a small maximum metric (16), split horizon, poisoned reverse, triggered updates and hold-down timers.
