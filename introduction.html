Introduction to Data Structures

Definition

A data structure is a particular way of organising, storing and accessing data in a computer's memory so that it can be used efficiently. It defines both the arrangement of the data and the operations allowed on it.

Data is a raw value (e.g. 72). Information is data with meaning (e.g. "Asha scored 72 in DSA"). A data structure decides how many such values are arranged: in a row, in a chain, in a hierarchy, or in a network. The same data can be stored in different structures, and the choice changes how fast we can search, insert or delete.

Why do we need data structures?

  • Efficiency: finding a name among a million in a sorted array takes about 20 comparisons with binary search, but up to a million with a plain scan.
  • Organisation: real problems have natural shapes: a family tree is a hierarchy, a road map is a network, a printer line is a queue.
  • Reusability: a well-defined structure (stack, queue, tree) can be reused across many programs.
  • Managing large data: databases, search engines and operating systems handle data that is far too large to process naïvely.
A famous equation

Niklaus Wirth, the creator of Pascal, titled his classic book Algorithms + Data Structures = Programs. An algorithm is only as fast as the structure it works on allows.

Basic operations on data structures

Traversing

Visiting every element once (e.g. printing all marks).

Searching

Finding the location of an element with a given value.

Inserting

Adding a new element.

Deleting

Removing an element.

Sorting

Arranging elements in order.

Merging

Combining two structures into one.

Abstract Data Type (ADT)

An ADT specifies what a data type does (its values and operations) without saying how it is implemented. A data structure is a concrete implementation of an ADT.

1. Primitive vs Non-primitive

Primitive data structures

Basic types directly supported by the machine or language, holding a single value: int, float, char, bool, pointers. Operated on directly by machine instructions.

Non-primitive data structures

Built from primitive types to hold a collection of values and the relationships between them: arrays, lists, stacks, queues, trees, graphs.

2. Linear vs Non-linear

BasisLinearNon-linear
ArrangementElements form a sequence; each has at most one predecessor and one successorAn element can connect to many others (hierarchy or network)
LevelsSingle levelMultiple levels (trees) or none (graphs)
TraversalAll elements in one runNeeds special methods (tree traversals, BFS, DFS)
ImplementationSimplerMore complex
ExamplesArray, linked list, stack, queueTree, graph, heap
Real-worldQueue at a counter, playlistFamily tree, road network

3. Static vs Dynamic

BasisStaticDynamic
SizeFixed when createdGrows and shrinks at run time
Memory allocationCompile time / onceRun time, as needed
ExampleArray (int a[10] in C)Linked list, Python list, dynamically allocated trees
RiskOverflow or wasted spacePointer overhead, allocation cost

4. Homogeneous vs Heterogeneous

Homogeneous structures store elements of the same type (a C array of int). Heterogeneous structures store elements of different types (a C struct, a Python list such as [1, "two", 3.0], a database record).

Algorithm Analysis & Asymptotic Notations

What is an algorithm?

An algorithm is a finite sequence of well-defined steps that solves a problem. Every algorithm must satisfy five properties:

Input

Zero or more quantities are supplied.

Output

At least one result is produced.

Definiteness

Every step is clear and unambiguous.

Finiteness

It ends after a finite number of steps.

Effectiveness

Every step is basic enough to be carried out exactly.

Why analyse algorithms?

Two correct algorithms can differ enormously in speed. Running them and timing them depends on the computer, language and input, so instead we count how the number of basic steps grows with the input size n. This gives a measure that is independent of the machine.

Time complexity

The time complexity T(n) of an algorithm is the number of basic operations (assignments, comparisons, arithmetic) it performs as a function of the input size n.

Frequency count (step count) method

Count how many times each statement executes and add them up. A loop header such as for i in range(n) is counted n + 1 times: n successful tests plus the final test that ends the loop.

Example 1: Sum of an array T(n) = 2n + 3 → O(n)

StatementFrequency
s = 01
for i in range(n):n + 1
s = s + a[i]n
return s1
Total2n + 3

Example 2: Nested loops T(n) = 2n² + 2n + 2 → O(n²)

StatementFrequency
count = 01
for i in range(n):n + 1
for j in range(n):n(n + 1)
count = count + 1n²
Total2n² + 2n + 2

Example 3: Doubling loop T(n) = 2⌈log₂ n⌉ + 2 → O(log n)

StatementFrequency
i = 11
while i < n:k + 1
i = i * 2k
Total2k + 2, k = ⌈log₂ n⌉

i takes the values 1, 2, 4, 8, …; it reaches n after about log₂ n doublings. Any loop whose variable is multiplied or divided by a constant runs O(log n) times.

Space complexity

The space complexity S(P) of a program is the total memory it needs as a function of the input size:

S(P) = c + SP(n)
  • Fixed part c: space for the code, simple variables and constants. It does not depend on n.
  • Variable part SP(n): space that depends on the input, e.g. arrays of size n, dynamically created nodes, and the recursion stack.
ProgramExtra spaceWhy
Iterative sum of an arrayO(1)A few variables (total, i), whatever n is
Recursive sum of an arrayO(n)n + 1 stack frames are alive at the deepest point
Copying an arrayO(n)A second array of n elements
n × n matrixO(n²)n² cells
Auxiliary space

Exam questions often ask for auxiliary (extra) space: the memory used besides the input itself. Bubble sort uses O(1) auxiliary space; merge sort uses O(n).

Best, worst and average case

For the same n, the number of steps can depend on which input is given. Linear search in an array of n elements:

CaseWhen it happensComparisonsComplexity
Best caseKey is the first element1Ω(1) / Θ(1)
Worst caseKey is last, or not presentnO(n) / Θ(n)
Average caseKey equally likely at any position(1 + 2 + … + n) / n = (n + 1) / 2Θ(n)

The worst case is the most commonly reported, because it is a guarantee: the algorithm never takes longer.

Asymptotic notations

Asymptotic notations describe how a function behaves for large n, ignoring constant factors and lower-order terms. Let f(n) be the running time and g(n) a simple comparison function such as n or n².

Big-O: O(g(n))

Upper bound. f grows no faster than g.

f(n) = O(g(n)) ⟺ ∃ c > 0, n₀ ≥ 1 : 0 ≤ f(n) ≤ c·g(n) for all n ≥ n₀

Read: "f is at most a constant times g, eventually."

Omega: Ω(g(n))

Lower bound. f grows at least as fast as g.

f(n) = Ω(g(n)) ⟺ ∃ c > 0, n₀ ≥ 1 : f(n) ≥ c·g(n) ≥ 0 for all n ≥ n₀

Read: "f is at least a constant times g, eventually."

Theta: Θ(g(n))

Tight bound. f grows exactly as fast as g.

f(n) = Θ(g(n)) ⟺ ∃ c₁, c₂ > 0, n₀ : c₁·g(n) ≤ f(n) ≤ c₂·g(n) for all n ≥ n₀

Equivalently: f = O(g) and f = Ω(g).

Worked proofs

Show 3n + 2 = Θ(n)

  • Upper: 3n + 2 ≤ 3n + n = 4n when n ≥ 2. So c₂ = 4, n₀ = 2 ⇒ 3n + 2 = O(n).
  • Lower: 3n + 2 ≥ 3n for all n ≥ 1. So c₁ = 3 ⇒ 3n + 2 = Ω(n).
  • Both hold for n ≥ 2 ⇒ 3n + 2 = Θ(n).

Show 10n² + 4n + 2 = O(n²)

For n ≥ 5, 4n + 2 ≤ n² (at n = 5: 22 ≤ 25). Then 10n² + 4n + 2 ≤ 10n² + n² = 11n². So c = 11, n₀ = 5. Also 10n² + 4n + 2 ≥ 10n² for all n, so it is Θ(n²).

Show 6·2ⁿ + n² = O(2ⁿ)

For n ≥ 4, n² ≤ 2ⁿ (16 ≤ 16). So 6·2ⁿ + n² ≤ 7·2ⁿ: c = 7, n₀ = 4.

Show n² ≠ O(n)

Suppose n² ≤ c·n for all n ≥ n₀. Dividing by n gives n ≤ c for all n ≥ n₀, which is false for n = max(n₀, c + 1). No constant works, so n² is not O(n).

Also good to know

Little-o: f = o(g) means f grows strictly slower than g (e.g. n = o(n²), but n² ≠ o(n²)). Little-omega: f = ω(g) means f grows strictly faster. Big-O and Big-Ω allow equality; little-o and little-ω don't.

How to Calculate Time Complexity: Best, Average & Worst Case

For many algorithms the number of steps depends not only on the input size n but also on the input itself. Searching for 10 in [10, 20, 30, …] stops immediately; searching for a missing value checks everything. So for each n we describe three functions:

CaseDefinitionFormula
Best caseFewest steps over all inputs of size nTbest(n) = min { T(I) : |I| = n }
Worst caseMost steps over all inputs of size nTworst(n) = max { T(I) : |I| = n }
Average caseExpected steps, weighting each input by its probabilityTavg(n) = Σ p(I) · T(I)
If all k possible inputs are equally likely:  Tavg(n) = (1/k) · Σ T(Ii)

The method, step by step

Recipe
  1. Identify the input size n (number of elements, digits, nodes…).
  2. Choose the basic operation: the statement executed most often, usually a comparison in searching and sorting.
  3. Ask: does the count depend only on n? If yes (e.g. finding the maximum, matrix addition), best = average = worst: count once with the frequency count method and stop.
  4. Best case: find the input that makes the algorithm stop earliest, and count the basic operations for it.
  5. Worst case: find the input that makes it do the most work, and count.
  6. Average case: list the kinds of input (e.g. "key at position i"), give each a probability (usually equal), and compute Σ probability × count.
  7. Simplify: keep the dominant term, drop constants, and state each case with asymptotic notation.

Useful sums: 1 + 2 + … + n = n(n + 1)/2  ·  1 + 2 + 4 + … + 2k−1 = 2k − 1  ·  1 + 1/2 + … + 1/n = Hn ≈ ln n.

Worked example 1: Linear search

for i ← 0 to n − 1:
    if a[i] = key: return i      // basic operation: this comparison
return −1
  • Best case: key is at position 1 → 1 comparison → Θ(1).
  • Worst case: key is last or absent → n comparisons → Θ(n).
  • Average case (successful): the key is at position i (1 ≤ i ≤ n) with probability 1/n and needs i comparisons:
    Tavg = Σi=1..n (1/n) · i = (1/n) · n(n + 1)/2 = (n + 1)/2 → Θ(n)
  • Including unsuccessful searches: if the key is absent with probability q, then Tavg = (1 − q)(n + 1)/2 + q·n. For any q this is still Θ(n).

Worked example 2: Binary search

  • Best case: the key is the middle element → 1 comparison → Θ(1).
  • Worst case: each comparison halves the range: n → n/2 → n/4 → … → 1. That is about log₂ n halvings plus the last comparison: ⌊log₂ n⌋ + 1 → Θ(log n).
  • Average case (successful): take n = 2k − 1. One key needs 1 comparison, 2 keys need 2, 4 keys need 3, …, 2k−1 keys need k:
    Tavg = (1/n) · Σi=1..k i · 2i−1 = ((k − 1)·2k + 1) / n ≈ log₂ n − 1 → Θ(log n)
    For n = 15 (k = 4): (3 · 16 + 1)/15 = 49/15 ≈ 3.27 comparisons, close to the worst case of 4.

Worked example 3: Insertion sort

for i ← 1 to n − 1:
    key ← a[i];  j ← i − 1
    while j ≥ 0 and a[j] > key:     // basic operation: a[j] > key
        a[j + 1] ← a[j];  j ← j − 1
    a[j + 1] ← key
  • Best case: already sorted. Each new element is compared once with its left neighbour and stays put: 1 comparison for each of the n − 1 passes → n − 1 → Θ(n).
  • Worst case: reverse sorted. Element i is compared with all i elements before it: 1 + 2 + … + (n − 1) = n(n − 1)/2 → Θ(n²).
  • Average case: random order. Element i ends up equally likely in any of the i + 1 positions, so on average it moves past about half of the elements before it. Adding these up over all passes gives
    Tavg = n(n − 1)/4 + n − Hn ≈ n²/4 → Θ(n²)
    The average is about half the worst case, but it is still quadratic.

Worked example 4: Early exit

for i ← 0 to n − 2:
    for j ← i + 1 to n − 1:
        if a[i] = a[j]: return TRUE      // duplicate found: stop early
return FALSE

Best: a[0] = a[1] → 1 comparison → Θ(1). Worst: no duplicates → every pair is compared: n(n − 1)/2 → Θ(n²). Any algorithm that can return early usually has different best and worst cases.

Worked example 5: When all three cases are the same

Finding the maximum of an array always compares every element: n − 1 comparisons for every input. Best = average = worst = Θ(n). The same holds for matrix addition, summing an array, and traversal.

Don't mix up cases and notations
  • Best, average and worst are three different functions of n. O, Ω and Θ are ways of bounding a function. You can use any notation with any case: "the worst case of linear search is Θ(n)" and "the best case is Θ(1)" are both precise.
  • "Big-O = worst case, Ω = best case" is a common shortcut, not a definition. It works because the worst case bounds every input from above (so the algorithm is O(worst)) and the best case bounds every input from below (so it is Ω(best)).
  • The best case is not "n = 1". It is the best input for a given n, for every n.

Try it yourself

1. Find the best, worst and average case of finding the minimum of n numbers.

Every element must be checked, so it is always n − 1 comparisons: best = average = worst = Θ(n).

2. A function returns as soon as it finds an even number in an array of n odd/even values. Give its best and worst case.

Best: the first element is even → 1 check → Θ(1). Worst: no even numbers (or only the last) → n checks → Θ(n).

3. Linear search: the key is present with probability 1/2, and if present it is equally likely to be anywhere. What is the average number of comparisons?

(1/2)·(n + 1)/2 + (1/2)·n = (3n + 1)/4 → Θ(n).

4. Why is the average case of insertion sort still Θ(n²) if it does only about half the work of the worst case?

Halving is a constant factor: n²/4 and n²/2 are both Θ(n²). Only the growth rate matters.

Time–space trade-off

Often we can make a program faster by using more memory, or save memory by doing more work:

  • Lookup tables: precompute answers (more space) to answer each query in O(1) (less time).
  • Hash tables use extra space to get O(1) average search instead of O(n).
  • Recursion vs iteration: recursive code is often shorter but uses O(depth) stack space.
  • Compressed data saves space but needs time to decompress.

Advantages of asymptotic analysis

✔ Machine-independent

Compares algorithms without worrying about processor speed, language or compiler.

✔ Predicts scalability

Shows what happens when the input grows 10×, 1000×, a million times.

✔ Simple to compare

O(n log n) vs O(n²) is an instant, meaningful comparison.

✔ Done before coding

Bad designs can be rejected on paper.

Limitations of asymptotic analysis

✘ Ignores constants

1000n and n are both O(n), but one is 1000× slower. For small n, an O(n²) algorithm with a small constant can beat an O(n log n) one.

✘ Only describes large n

Real inputs may be small enough that the "worse" algorithm is faster.

✘ Ignores hardware effects

Cache behaviour, memory access patterns and parallelism matter in practice.

✘ Average case needs assumptions

It depends on a probability distribution of inputs that may not match reality.

Common mistakes

Watch out
  • "Big-O means worst case." Not exactly: O is an upper bound on a function. You can give an O bound for the best, worst or average case. Worst case is simply the most common use.
  • Writing O(2n) or O(n² + n): drop constants and lower terms: O(n), O(n²).
  • Adding nested loops instead of multiplying them: two nested loops of n are O(n²), not O(2n).
  • Assuming every loop is O(n): a loop that doubles or halves its variable is O(log n).
  • Using one n for two inputs: processing lists of size n and m is O(n + m) or O(n·m).
  • Forgetting the recursion stack when computing space complexity.
  • Choosing n₀ or c that only works for one n: the inequality must hold for every n ≥ n₀.

Important examination points

Remember for exams
  • Classification tree: Primitive (int, float, char, bool, pointer) / Non-primitive → Linear (array, linked list, stack, queue) / Non-linear (tree, graph).
  • Five properties of an algorithm: input, output, definiteness, finiteness, effectiveness.
  • S(P) = c + SP(n): fixed part plus variable part.
  • Definitions of O, Ω and Θ with constants c and n₀; Θ = O and Ω together.
  • When proving, state c and n₀ explicitly and check the inequality for n ≥ n₀.
  • Order: 1 < log n < n < n log n < n² < n³ < 2ⁿ < n!
  • Linear search: best 1, worst n, average (n + 1)/2 comparisons. Binary search worst: ⌊log₂ n⌋ + 1.

Python Implementation

Six complete, tested programs. Each tab shows the code and its actual output. Use the Copy button to paste the program into your editor. All outputs are exact counts, so you will get the same results.

# Program 1: Frequency-count (step-count) method
# Each function counts how many times every statement executes,
# including the extra test that ends each loop.
import math

def sum_array(n):
    steps = 0
    a = list(range(n))
    s = 0;                         steps += 1          # s = 0
    i = 0
    while True:
        steps += 1                                     # loop test (runs n + 1 times)
        if i >= n: break
        s = s + a[i];              steps += 1          # body (runs n times)
        i += 1
    steps += 1                                         # return s
    return steps                                       # T(n) = 2n + 3

def nested_pairs(n):
    steps = 1                                          # count = 0
    for i in range(n + 1):                             # outer test: n + 1 times
        steps += 1
        if i == n: break
        for j in range(n + 1):                         # inner test: n + 1 per outer pass
            steps += 1
            if j == n: break
            steps += 1                                 # count += 1 : n*n times
    return steps                                       # T(n) = 2n^2 + 2n + 2

def triangular(n):
    steps = 1                                          # count = 0
    for i in range(n + 1):
        steps += 1                                     # outer test
        if i == n: break
        j = i + 1
        while True:
            steps += 1                                 # inner test
            if j >= n: break
            steps += 1                                 # count += 1
            j += 1
    return steps                                       # T(n) = n^2 + n + 2

def doubling_loop(n):
    steps = 1                                          # i = 1
    i = 1
    while True:
        steps += 1                                     # test i < n
        if not i < n: break
        i *= 2;                    steps += 1          # i = i * 2
    return steps                                       # T(n) = 2*ceil(log2 n) + 2

    "nested_pairs  2n^2+2n+2":     (nested_pairs,  lambda n: 2*n*n + 2*n + 2),
    "triangular    n^2+n+2":       (triangular,    lambda n: n*n + n + 2),

# Program 2: Best, worst and average case of linear search, and binary search

def linear_search(a, key):
    comparisons = 0
    for i in range(len(a)):
        comparisons += 1
        if a[i] == key:
            return i, comparisons
    return -1, comparisons

def binary_search(a, key):
    low, high, comparisons = 0, len(a) - 1, 0
    while low <= high:
        mid = (low + high) // 2
        comparisons += 1
        if a[mid] == key:
            return mid, comparisons
        if a[mid] < key:
            low = mid + 1
        else:
            high = mid - 1
    return -1, comparisons

# Program 3: Space complexity: iterative vs recursive sum
# The iterative version uses a fixed number of variables: O(1) extra space.
# The recursive version keeps one stack frame per pending call: O(n) extra space.

max_depth = 0

def sum_iterative(a):
    total = 0                       # one variable, whatever the size of a
    for x in a:
        total += x
    return total

def sum_recursive(a, n, depth=1):
    global max_depth
    max_depth = max(max_depth, depth)       # how many frames are alive right now
    if n == 0:
        return 0
    return a[n - 1] + sum_recursive(a, n - 1, depth + 1)

for n in [5, 50, 500]:
    a = list(range(1, n + 1))
    max_depth = 0
    r = sum_recursive(a, n)
    print(f"n = {n:3}: iterative = {sum_iterative(a):6}, recursive = {r:6}, "
          f"recursion depth = {max_depth} frames (n + 1)")

# Storing an n x n matrix needs n*n cells: O(n^2) space

# Program 4: Checking Big-O, Omega and Theta constants numerically
# (A numerical check is evidence, not a proof, but it is a good way to test
#  constants c and n0 that you found by hand.)

def holds_from(test, n0, upto=10_000):
    """True if test(n) is true for every n in [n0, upto]."""
    return all(test(n) for n in range(n0, upto + 1))

def smallest_n0(test, upto=10_000):
    for n0 in range(1, upto + 1):
        if holds_from(test, n0, upto):
            return n0
    return None

# Program 6: Best, worst and average case by trying EVERY input (enumeration)
# For each algorithm we count the basic operation (key comparisons) on all
# possible inputs of size n, then take the minimum, maximum and mean.
from itertools import permutations
from fractions import Fraction
import math

def linear_search(a, key):
    c = 0
    for x in a:
        c += 1                       # one comparison per element examined
        if x == key:
            return c
    return c

def binary_search(a, key):
    lo, hi, c = 0, len(a) - 1, 0
    while lo <= hi:
        mid = (lo + hi) // 2
        c += 1                       # one comparison with a[mid] (3-way)
        if a[mid] == key: return c
        if a[mid] < key: lo = mid + 1
        else: hi = mid - 1
    return c

def insertion_sort(a):
    a, c = list(a), 0
    for i in range(1, len(a)):
        key, j = a[i], i - 1
        while j >= 0:
            c += 1                   # comparison a[j] > key
            if a[j] > key:
                a[j + 1] = a[j]; j -= 1
            else:
                break
        a[j + 1] = key
    return c

def report(name, counts, formulas):
    best, worst = min(counts), max(counts)
    avg = Fraction(sum(counts), len(counts))
    print(f"{name}  ({len(counts)} inputs tried)")
    print(f"  best  = {best:<4} formula {formulas[0]}")
    print(f"  worst = {worst:<4} formula {formulas[1]}")
    print(f"  avg   = {float(avg):<8.4f} formula {formulas[2]}")

n = 10
a = list(range(1, n + 1))
succ = [linear_search(a, k) for k in a]
report(f"Linear search, n = {n}, successful only", succ,
       ["1", f"n = {n}", f"(n+1)/2 = {(n + 1) / 2}"])

n = 15
a = list(range(1, n + 1))
succ = [binary_search(a, k) for k in a]
k = n.bit_length()                                         # n = 2^k - 1 -> k = 4
report(f"Binary search, n = {n}, successful only", succ,
       ["1", f"floor(log2 n) + 1 = {math.floor(math.log2(n)) + 1}",
        f"((k-1)2^k + 1)/n = {((k - 1) * 2**k + 1) / n:.4f}  (about log2 n - 1)"])

for n in [4, 6, 8]:
    counts = [insertion_sort(p) for p in permutations(range(n))]
    H = sum(Fraction(1, i) for i in range(1, n + 1))
    exact = Fraction(n * (n - 1), 4) + n - H
    assert Fraction(sum(counts), len(counts)) == exact     # average formula is exact

           [f"n - 1 = {n - 1}", f"n(n-1)/2 = {n * (n - 1) // 2}",
            f"n(n-1)/4 + n - H(n) = {float(exact):.4f}"])

A. Conceptual questions

1. Define a data structure. How is it different from an abstract data type?

A data structure is a way of organising and storing data for efficient access and modification. An ADT specifies only the values and operations (what); a data structure is a concrete implementation of an ADT (how).

2. Classify data structures with a diagram and examples.

Primitive (int, float, char, bool, pointer) and non-primitive. Non-primitive divides into linear (array, linked list, stack, queue) and non-linear (tree, graph). Other bases: static/dynamic, homogeneous/heterogeneous.

3. What is the difference between time complexity and space complexity?

Time complexity counts the basic operations performed as a function of n; space complexity measures the memory needed (fixed part plus variable part, including the recursion stack) as a function of n.

4. Define O, Ω and Θ. Which one gives a tight bound?

O: f ≤ c·g eventually (upper bound). Ω: f ≥ c·g eventually (lower bound). Θ: c₁·g ≤ f ≤ c₂·g eventually; Θ is the tight bound.

5. Why is worst-case analysis usually preferred?

It gives a guarantee on the maximum time for any input of size n, it is often easier to compute than the average case, and for many algorithms the worst case occurs frequently.

D. Proof-based question

Show that f(n) = 5n² − 6n is Θ(n²). Give c₁, c₂ and n₀.

Show solution
  • Upper bound: 5n² − 6n ≤ 5n² for all n ≥ 1, so c₂ = 5.
  • Lower bound: we want 5n² − 6n ≥ 4n², i.e. n² ≥ 6n, i.e. n ≥ 6. So c₁ = 4, n₀ = 6.
  • Hence 4n² ≤ 5n² − 6n ≤ 5n² for all n ≥ 6: f(n) = Θ(n²). (Program 4 confirms n₀ = 6.)
