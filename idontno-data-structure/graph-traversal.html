Graph traversal: explore every vertex

How do you visit every vertex of a graph without getting lost or going in circles? Learn Breadth First Search and Depth First Search by watching them run, step by step, and then solve problems yourself.

1. What is graph traversal?

Traversal means visiting every vertex of a graph, one by one, by following its edges.

In an array you can simply go from index 0 to the end. A graph has no first element and no fixed order. Vertices are joined in all kinds of ways, and there may be cycles. So we need a clear method that starts at one vertex, visits every vertex it can reach, and never visits a vertex twice.

Why do we traverse a graph? To search (is there a path from A to B?), to find the shortest route, to check if the graph is connected, to detect cycles, and to explore everything reachable, as a web crawler does.

Four ideas behind every traversal

1. Start vertexWe choose the vertex where the traversal begins. Only vertices reachable from it are visited.
2. Visited markingWe remember which vertices are already visited. Without this, a cycle would send us around forever.
3. Neighbour orderWhen a vertex has several neighbours, we need a rule. On this page we always take the smaller number first.
4. A to-do listWe keep a list of vertices still to explore. A queue gives BFS. A stack gives DFS.
Visit vs explore"Visit" means we process the vertex (print it, count it). "Explore" means we look at its neighbours.
Two strategiesBFS spreads out level by level. DFS goes as deep as possible, then backs up.

2. Breadth First Search (BFS)

BFS visits the start vertex, then all its neighbours, then all of their neighbours, and so on. It spreads out level by level, like ripples in a pond.

How BFS works

  1. Mark the start vertex as visited and put it in a queue.
  2. While the queue is not empty: take the vertex at the front of the queue and visit it.
  3. Look at each neighbour of that vertex (smaller number first). If it is not visited yet, mark it visited and add it to the back of the queue.
  4. When the queue becomes empty, BFS is finished.
Why a queue? A queue is first in, first out. The vertices found first (the closest ones) are explored first. That is what keeps BFS moving level by level.

More about BFS

  • Levels and distance: the small d= label under each vertex is its distance from the start (number of edges). BFS finds the shortest path in an unweighted graph, because it reaches every vertex by the fewest edges possible.
  • BFS tree: the thick indigo edges are the edges that first discovered each vertex. Following them back from any vertex gives a shortest path to the start.
  • Time: O(V + E) with an adjacency list (each vertex is queued once and each edge is checked once or twice). With an adjacency matrix it is O(V2), because finding the neighbours of a vertex scans a whole row.
  • Space: O(V) for the queue and the visited marks. In a wide graph the queue can hold a whole level at once.
  • Uses: shortest path in an unweighted graph, finding connected components, checking whether a graph is bipartite, "people within 2 friendships", web crawling, GPS and network broadcasting.

3. Depth First Search (DFS)

DFS goes as deep as it can along one path. When it hits a dead end, it backtracks and tries the next path. It is like exploring a maze.

How DFS works

  1. Visit the current vertex and mark it visited.
  2. Look at its neighbours (smaller number first). For the first neighbour that is not visited, go deeper: repeat the same steps from that neighbour.
  3. When a vertex has no unvisited neighbours left, backtrack to the vertex you came from and continue with its next neighbour.
  4. When you backtrack out of the start vertex, DFS is finished.
Why a stack? A stack is last in, first out. The newest vertex is explored first, so we keep going deeper. Recursion uses the computer's call stack to do the same job, so a recursive DFS needs no stack written by you.

Watch DFS run

Press Next. The stack shows the path from the start to the current vertex. Popping from the stack is the backtrack.

More about DFS

  • Back edge: if DFS meets a neighbour that is already visited and still on the stack, that edge points back to an ancestor. This means the graph has a cycle. This is how DFS detects cycles. Try the "Directed with a loop" graph.
  • Time: O(V + E) with an adjacency list, and O(V2) with an adjacency matrix. Space: O(V) for the stack (the depth of the path can be as long as V).
  • Uses: cycle detection, topological sorting of a DAG, finding connected components, solving mazes and puzzles, finding a path (not necessarily the shortest) between two vertices.
  • Recursive and iterative: the recursive version is shortest to write. The iterative version uses an explicit stack. To get the same order, push the neighbours in reverse order so that the smallest neighbour is popped first.

5. Special cases and common mistakes

Disconnected graphsOne traversal only reaches the vertices connected to the start. To visit every vertex, loop over all vertices and start a new traversal from each one that is still unvisited. The number of times you start a new traversal is the number of connected components. Try "Two separate parts" with "visit all parts" ticked.
Directed graphsYou may only travel in the direction of the arrow. Some vertices may be impossible to reach from the start, even when the graph looks connected. Try "Directed with a loop" and "Directed acyclic".
CyclesCycles are the reason we mark vertices as visited. DFS also uses a cycle to find a back edge. BFS simply skips a neighbour that is already visited.
The order is not uniqueThe order of visiting depends on the start vertex and on the order of neighbours. A different rule gives a different, still correct, traversal. This page always uses the smaller number first.

Mistakes students often make

  • Marking a vertex visited only when it is removed from the BFS queue. Mark it when it is added, otherwise the same vertex can enter the queue many times.
  • Using a stack for BFS or a queue for DFS. The structure decides the traversal.
  • Forgetting that the order changes when the neighbour order changes.
  • Forgetting to start a new traversal for the other parts of a disconnected graph.
  • Calling BFS the "shortest path" method for weighted graphs. BFS counts edges, not weights. Weighted shortest paths need Dijkstra's algorithm.

6. Python code

The graph is stored as an adjacency list: a dictionary from each vertex to its list of neighbours.

from collections import deque

graph = {0: [1, 2], 1: [0, 3, 4], 2: [0, 5, 6],
         3: [1], 4: [1], 5: [2], 6: [2]}

def bfs(graph, start):
    visited = {start}               # mark when we ADD to the queue
    queue = deque([start])
    order = []
    while queue:
        u = queue.popleft()         # take from the front
        order.append(u)             # visit u
        for v in sorted(graph[u]):  # smaller neighbour first
            if v not in visited:
                visited.add(v)
                queue.append(v)     # add to the back
    return order

print(bfs(graph, 0))   # [0, 1, 2, 3, 4, 5, 6]
def dfs(graph, u, visited=None, order=None):
    if visited is None:
        visited, order = set(), []
    visited.add(u)                  # mark and visit u
    order.append(u)
    for v in sorted(graph[u]):
        if v not in visited:
            dfs(graph, v, visited, order)   # go deeper
    return order                    # returning = backtracking

graph = {0: [1, 2], 1: [0, 3, 4], 2: [0, 5, 6],
         3: [1], 4: [1], 5: [2], 6: [2]}
print(dfs(graph, 0))   # [0, 1, 3, 4, 2, 5, 6]
def dfs_iterative(graph, start):
    visited, order, stack = set(), [], [start]
    while stack:
        u = stack.pop()             # take from the top
        if u in visited:
            continue
        visited.add(u)
        order.append(u)
        for v in sorted(graph[u], reverse=True):   # reverse: smallest is popped first
            if v not in visited:
                stack.append(v)
    return order

print(dfs_iterative(graph, 0))   # [0, 1, 3, 4, 2, 5, 6]
def bfs_distance(graph, start):
    dist = {start: 0}               # distance in edges
    queue = deque([start])
    while queue:
        u = queue.popleft()
        for v in sorted(graph[u]):
            if v not in dist:
                dist[v] = dist[u] + 1
                queue.append(v)
    return dist

def count_components(graph):
    seen, count = set(), 0
    for s in sorted(graph):         # start from every unvisited vertex
        if s not in seen:
            count += 1
            seen.update(bfs(graph, s))
    return count

print(bfs_distance(graph, 0))   # {0: 0, 1: 1, 2: 1, 3: 2, 4: 2, 5: 2, 6: 2}
